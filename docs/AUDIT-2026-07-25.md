A three-part audit of the whole repo (~88k LOC), covering bugs & correctness, performance, and architecture & maintainability.

Each part is self-contained: findings are numbered within the part, ranked most-severe first, and every one carries a file:line reference, quoted code, a concrete failure scenario, and a specific fix. Each part also ends with a "What's solid" section and its own suggested priority order.

**Verification.** All findings are read-verified against the source with the relevant lines quoted. The decoder part additionally got a clean `go vet` / `gofmt` / scoped `golangci-lint` run after local toolchain workarounds; the GPU and serving parts are reading-only (cgo/build-tag code that cannot compile on the audit host, and unfetchable module dependencies respectively). A sample of the highest-severity claims across all three parts — decoder #1, #2, #3, #7, #9, #10; GPU #1, #6; serving §1, §4, §9, §11 — was independently re-checked against the tree afterwards and all held.

## The cross-cutting picture

Read together, the three parts point at four recurring shapes rather than 68 unrelated defects. These are worth fixing as *classes*.

### 1. A predicate that gates a fast path drifts from the code it is supposed to describe

The repo's central design idea — declare per-arch and per-backend capabilities, then admit only representable combinations — is genuinely good, and `decoder/features.go` is the best thing in the codebase. But six findings are the same failure of that mechanism:

- `specRollbackSafe` keys its ring exemption on `m.resident == nil`, which is not the condition that decides whether the speculative loop uses a staged cache (decoder #1).
- `Model.AttnScale()` recomputes `1/√headDim` instead of returning the registry-resolved `arch.AttnScale`, so all three resident backends mis-scale Gemma-3-27B (decoder #7).
- `ArgmaxEquivalent()` omits `LogitProcessor` while its own doc comment says it must not (decoder #21).
- `FeatEmbedScale`'s admission predicate is `> 1` where the forward tests `!= 0 && != 1` (decoder #28).
- The own-forward family list is duplicated across seven sites with three different memberships, latent only by coincidence (decoder #22).
- `prefillFeatures` omits `FeatPerLayerRoPE` but claims `FeatSlidingWindow`, and Metal prefill binds model-level RoPE/window where decode binds per-layer — safe only because every mixed-window arch happens to also have per-layer RoPE (GPU #23).

**The class fix.** Every capability predicate should be derived once, in one place, from the same value the forward actually consumes — and cross-checked by a table-driven test over every registered arch. Where the taxonomy cannot express a constraint (a *numeric* cap: `nE ≤ 256`, `nGroup ≤ 32`, `hd ≤ 128`, `K % 32 == 0`), give it a slot rather than leaving the check to whichever backend remembered (GPU #1, #8, #22).

### 2. Silent clamping and silent dropping where a loud decline belongs

The same shape appears in every layer, and in each case one sibling gets it right:

| Silently wrong | Correct sibling |
|---|---|
| WebGPU `min(p.nE, MAXE)` truncates a 384-expert router (GPU #1) | CUDA and Metal both `return declined(...)` |
| Metal int4 truncates a non-multiple-of-32 `K` (GPU #8) | CUDA errors; WebGPU pads |
| Tool-call grammar compile errors dropped → unconstrained generation (serving §5) | `response_format` returns a 400 |
| OpenAI `max_tokens` unvalidated → 278 GB allocation (serving §1) | Anthropic handler validates `> 0` |
| Batched/Q8 encoder forward drops attention biases (aikit, sibling repo) | single-sequence f32 path applies them |
| `tk.Decode` error discarded → 460 tokens silently unemitted with HTTP 200 (serving §16) | — |
| Metal/WebGPU never read a GPU error at all (GPU #2) | CUDA latches a sticky `launchErr` |

**The class fix.** Where two implementations of one contract exist, make the strict one the shared one. GPU #2 is the highest-leverage single item in the whole audit: it costs a handful of lines and converts an entire family of silent corruptions (GPU #3, #10, #13, and every future one) into observable failures.

### 3. Exact-fit growth and per-call scratch on paths that run once per token

Nine findings are the same allocation mistake at different scales, and the fix pattern already exists in the codebase (`decodeScratch`, `linalg.Workspace`, `bm25`'s `sync.Pool`):

- `attnBatchBufs` grows by exactly `nKeys*hd` each token, so `cap < n` is true *every token forever* — 4.2 MB malloc'd and zeroed per token at 4k context, 33.6 MB on the int8-KV path (decoder #9).
- `Generate` allocates the full ~1 GB CPU KV cache before deciding it will use the GPU (decoder #10).
- MoE `swiGLUExpert` allocates two `inter`-wide slices per expert per layer per token — ~8 MB/token on DeepSeek-V3 (decoder #12).
- `forwardN` allocates ~16 buffers per speculative round, ~7.5 MB (decoder #13).
- Full-vocab sort + 3.6 MB per sampled token to pick top-40 (decoder #14, serving §20).
- `constrain.TokenBytes` rebuilds a 3.6 MB immutable vocabulary table per request (serving §14).
- Grammar stack snapshot/restore per *candidate token* — ~58 MB of memmove per decode step (serving §15).
- `PrefillLast` creates and destroys ~24 `MTLBuffer`s (~150 MB) per request, 16 of them 4-byte constants (GPU #15).
- Metal/WebGPU norm, quantize and SwiGLU kernels each run in **one** threadgroup on the critical path (GPU #12, #5).

**The class fix.** Grow with headroom (`max(2*cap, n)`), hoist per-model-immutable tables to load time, and hang per-shape scratch off the `KVCache` next to `scr`. None of this needs design work.

### 4. Untrusted bytes reach an allocation or an index without a bound

Concentrated in the serving layer and its readers, and the reason `--max-queue` currently bounds nothing that matters:

- `max_tokens` → KV pre-allocation (serving §1); a 73 KiB PNG → 1.67 GiB, a crafted one → 19 GB fatal OOM (serving §10); unbounded `/v1/embeddings` array → 3 GB (serving §3); `minItems: 1e300` → platform-dependent unclosable array (serving §23); a 21-byte `.giw` → 4 GiB allocation, a 40-byte GGUF header → negative-slice panic (serving §27).
- All of the above run **before** queue admission, because every handler claims its slot last (serving §2). The vision tower — documented at ~3 min/image — runs pre-admission with no `context.Context`.
- Sequential, guessable `previous_response_id` with no ownership check replays one client's conversation into another's completion (serving §7); recurrent Mamba/DeltaNet state is never reset on session eviction, leaking conversation A's state into conversation B (decoder #2).

**The class fix.** Move `enter()` immediately after `decodeJSON` + `pick`; clamp every client-supplied number against a model-derived ceiling in `prepare`; validate header lengths against `f.Stat()` before `make`; thread `r.Context()` everywhere.

## If you only do five things

1. **GPU #2** — check `MTLCommandBufferStatus`/`.error` on Metal and install a WebGPU uncaptured-error callback. Small, and it makes the rest of the GPU findings *visible* instead of silent.
2. **Serving §1 + §2** — clamp `max_tokens` and move admission ahead of prompt assembly. Closes the process-kill and restores backpressure in one pass.
3. **Decoder #1 + #2** — the two Critical items: fix `specRollbackSafe`'s predicate and reset recurrent state on `Reset`/rewind. #2 is a cross-user state leak reachable with default flags.
4. **Decoder #9 + #10** — headroom growth in `decodeScratch`, and don't allocate a 1 GB cache the resident path never reads. The two best perf-per-line changes in the repo.
5. **Serving §4 + §5** — `CanEnd` vs `MustEnd`, and stop swallowing grammar compile errors. Together these are what make "a Go struct the model cannot violate" actually true.
