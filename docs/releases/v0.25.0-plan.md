# goinfer v0.25.0 plan

<!-- citations-at: d927d942b88a -->

Written 2026-11-03, the day v0.24.0's release work began. Window: from the v0.24.0 tag (Nov 5–6) to about Nov 27.
Owner's direction (Francis, 2026-11-03): 1.0 is a few releases away, so v0.25.0 is a "finish what's in flight" release,
not the 1.0 run-up. New models: the cheap ones here, new architectures most likely in v0.26.0.

The appendix is a doc-by-doc triage of the 77 live task docs and the three audits, drafted by Gemini on 2026-11-03 and
read by the coordinator. Its line citations are a starting point: verify each against the tree before acting on it.

## 1. Theme

Finish the four big tracks to a clear stopping point, add the models that are cheap to add, fix the small audit
leftovers that affect correctness or security, and cut the task-doc pile from 77 to the dozen that are live.

## 2. The four tracks

Each track's realistic slice for one release, with what "finished" means, is in the appendix, §2. In short:

| Track | v0.25.0 slice | Finished when |
|---|---|---|
| Subsystems (`task-subsystems-2026-10.md`) | VK5 week 3 grade and the SB4 switch (~Nov 10); VK6 canary; MM7/MM8 skip tables shrunk toward empty; MM5 buffer lists on CUDA; SB11a/b; SB12; MM6 grade (Nov 15); AX7 and PW6 re-counts (~Nov 26) | All ledger rows closed (42 of 59 today) |

| Memory (`task-memory-campaign-2026-10.md`) | D8b-cuda, MEM6-CUDA, MEM11-bf16-CUDA, MEM13 host copies on CUDA (~4 GB on Nemotron-H 9B), MEM17 with aikit and ken; MEM10 if time | Every non-parked ledger row closed |

## 3. Models

Source: `docs/next-models.md` (field checks 2026-10-15 and 10-26). A fresh field check from 10-26 onward, by that
doc's selection rule, runs at the start of the window and updates its "Next up" and "Watching".

Cheap, in v0.25.0:
- **Nemotron 3.5 Bolt E4B**: NVIDIA's post-training of Gemma 4 E4B; expected to be a `gemma4` checkpoint swap. Gate 0
  checks architecture, license, the chat template's reasoning toggle and tool format.
- **Mistral Small 4 routing guard**: a `mistral3` wrapper whose text config is `mistral4` is handed to the dense
  Ministral 3 adapter today; decline it by name.
- **Bonsai low-bit guard**: PrismML's files labelled `Q2_0`/`TQ1_0` can load silently into garbage; make it a named
  decline (or read upstream `Q2_0` correctly).

- **From the 2026-11-03 field check** (`docs/next-models.md`): LFM3-1.7B (new version of the `lfm2` family; CPU until a
  GPU runs short-conv), Nanbeige4.3-33B (plain `llama`, nobara only, a checkpoint swap), and the MiniCPM-OCR-1.0 text
  decoder (`qwen3_5_text` behind a new outer key). The Bonsai guard also has to key on Bonsai-2's Hadamard-rotated weights.

Bigger, likely v0.26.0 (owner's call at pickup):
- **Muse Glimmer 30B** (Meta): the one new family next-models.md ranks worth building. Mostly existing parts; resident
  only on nobara; plan the reference forward (oracle) first.
- **SenseNova-Loop-9B**: looped layers with per-pass cache state and two-stream hyper-connections; new primitives.
- **Low-bit read formats** (IQ types, NVFP4): a format bet that unlocks real files (Nemotron 3.5 Bolt's 24 GB build,
  Unsloth dynamic quants). `task-fp4-formats.md` is its scoping.

## 4. Fixes and small user-visible items

Correctness and security first (appendix §3B):
- **F-N01**: `/v1/embeddings` on a GPU-resident model can overwrite KV slot 0 during a concurrent chat
  (`decoder/embed.go`). Correctness; small.
- **N-26, N-40**: the banner overstates KV after a declined resident; CUDA LoRA leaks buffers on a mid-upload OOM.
  Small.
- **N-33 (CORS on a keyless `serve`), N-43, N-29, N-86**: the triage called these open, but the files it cited are no
  longer in the tree (the citation lint caught it). Recheck each against today's code before scheduling.
- Signed release binaries (left from the 2026-10-12 security audit): decide the mechanism.

User-visible, small (appendix §3C):
- CUDA `--kv i8` (halves KV again on 8 GB cards; unblocked by KV4).
- The mapped-MoE working-set refusal with `--accept-slow` (owner-decided 2026-10-21).
- `goinfer-pull prune-sidecars` to reclaim stale `.giw` versions.
- Multimodal leftovers: the `--vision-int8` default (owner decision), Qwen3-VL MoE prefill on paged KV, int4 embedding
  upload on Metal.
- `cost` telemetry completed under MC3, Metal, WebGPU, media and speculative decode.

## 6b. Code cleanup (first weeks, in the same window as the decoder split)

Owner's go-ahead 2026-11-03. All three touch the same files as the decoder split, so they run in one window: one round
of parity-hash refresh (`scripts/refresh_parity_hashes.sh`, which runs the forward goldens as proof) instead of three.

1. **`go fix` modernizers.** Dry run on the root module at the commit this plan is pinned to: 95 files, about 250 lines
   (`new(expr)` 51, range over an integer 40, `strings.SplitSeq` 34, `maps` 17, `strings.Cut` 12, `slices` 6, `max` 4).
   The backend modules are not measured yet. One mechanical PR per module. Rerun at each Go toolchain upgrade, not in
   CI (a toolchain bump alone would turn it red).
2. **Dead code.** staticcheck's U1000 already removes unexported dead code on every platform build. Add
   `golang.org/x/tools/cmd/deadcode` for exported code nothing reaches, run once per platform and tag set (cuda,
   metal, gpu, the test hooks) across the whole workspace, because root internal packages are called only from the
   backend modules and architectures are reached through the registry. Delete only what every run agrees is dead.
3. **Duplicate helpers.** `dupl`, plus a Gemini audit of exported signatures across the 46 internal packages, clustering
   near-duplicate helpers (file I/O, retry loops, version stamping, slice and JSON utilities) and pass-through wrappers.
   Consolidate into focused internal packages, one theme per PR.
4. **Single-implementation interfaces: list, don't delete by rule.** Many exist on purpose as test seams built by the
   subsystems track (`engine.Engine` with its scripted fake, the scheduler, the backend kernel layers). The audit
   lists them; each needs a reason to go.

Every PR here is behavior-neutral and has to show it: parity, censuses and the wire census unchanged.

## 7. Decisions for the owner

1. Low-bit formats: build in v0.26.0, or keep watching?
2. Signed release binaries: which mechanism, and in which release?
3. CUDA `--kv i8` in v0.25.0: yes or later?
4. The `--vision-int8` default.

## 8. A rough road to 1.0

- v0.25.0: the four tracks finished; cheap models; audit leftovers; docs cleaned.
- v0.26.0: new families (Muse Glimmer), low-bit formats if chosen, the rest of the library-surface fixes, decoder split
  continued.
- v0.27.0 or so: API freeze practice: `apidiff` baseline in CI, tier promises settled, submodule tag posture decided;
  then 1.0 when a release goes out with no Hard-tier API change.
