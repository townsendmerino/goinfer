# goinfer v0.20.0 — lighter on memory, steadier tool calls, faster decode

> **This file is the DRAFT for the GitHub Release body** (`gh release create --notes-file`).
> Per `RELEASING.md`, the **published Release body is canonical** the moment it goes out — after
> that, edit the Release, not this file. It lives here rather than in gitignored `docs/internal/`
> so it is reviewable in a clone and cannot silently diverge on one machine.

Most of this release is about running bigger models on the machine you already have without it
starting to swap, and about tool calls coming back in a shape an agent can use. Along the way a
fair number of kernels got faster, and nearly all of them produce exactly the output they did
before. Where one does not, it says so below.

## A few things may need a moment of your attention

- **Seeded sampling produces different tokens.** Plain `temperature` sampling (no `top_k`,
  `top_p` or `min_p`, which is the OpenAI default) now draws by Gumbel-max from a counter-based
  generator keyed by the seed. The distribution is unchanged, but for a given seed the tokens are
  not the ones an earlier release produced. Sampling with `top_k` / `top_p` / `min_p` is unchanged
  token for token.
- **Two `serve` flags are gone.** `--metal-fast-prefill` had been a no-op since September 9 and
  `--cpu-fast-attention` could only do what `--cpu-exact-prefill` does. A script passing either
  now stops at startup with `flag provided but not defined`; deleting the flag is the fix.
  Relatedly, an exported `GOINFER_CPU_FAST_ATTENTION` no longer overrides the command-line flags.
- **On Linux, a `.gguf` now loads through a `.giw` sidecar, as it already did on macOS.** The
  first start per model and backend transcodes once and writes roughly the model's size beside the
  `.gguf`. After that, loads map the file instead of re-quantizing (CUDA 7B: 10 s instead of
  26.6 s), and decode speed is unchanged within noise. If there is not enough free disk, `serve`
  refuses to start and says so; `-direct-load` or `GOINFER_GGUF_DIRECT=1` keeps the old behaviour.
- **Sidecars move to weights format v14.** Older sidecars still load; they just share less memory
  with the OS on Metal, and the load banner suggests rebuilding them.
- **CUDA decode at long context uses a new attention kernel by default** once the span reaches
  2048 keys. It is not bit-identical to the exact path, so output deep into a long conversation can
  differ from earlier releases in the last bits, and occasionally in a token at a near-tie. It
  passed its pre-registered fidelity gate; `GOINFER_CUDA_FLASH_DECODE=0` turns it off. Short chat
  turns never reach it.
- **Some code has been removed:** the never-released gemma demos (`goinfer-chat` and
  `goinfer-serve` cover what they did) and the unused MTP self-draft measurement adapter in
  `decoder` (`MTPHead`, `LoadMTPHead` and friends), which had no caller.

## Less memory, less swap

The aim here was simple: a model that fits should not push your machine into swap.

- **Metal serves `.giw` weights directly from the file.** Instead of copying them into GPU
  buffers, it binds them from the file mapping, so they are page cache the OS can reclaim rather
  than memory that has to be swapped out. Memory held after 32 tokens went from 4,134 MB to 105 MB
  on a 7B and from 1,013 MB to 90 MB on a 1.5B. Logits are byte-identical and decode is within 3%.
  `GOINFER_METAL_ALIAS=0` restores the copy path.
- **The gemma4 transcode no longer needs a machine larger than the model.** It now streams one
  layer at a time like every other family: the 26B-A4B's peak drops from 18.1 GB to 1.61 GB, with
  byte-identical output. It takes about 45% longer (1:50 instead of 1:16), which seemed a fair
  trade for being able to do it at all.
- **"Will it fit" agrees with what the backend does.** `fit` and Metal's memory guard now use one
  accounting function, and `fit` prices CUDA's KV cache the way CUDA actually allocates it. MLA
  models such as DeepSeek and Kimi had their KV counted twice on CUDA, so their default context was
  smaller than it needed to be.
- **`goinfer-chat` accepts every model-loading flag `goinfer-serve` does**: `--ctx`,
  `--stream-weights`, `--weight-cache`, `--moe-cache-experts`, `--moe-cache-slots`, `--moe-pager`,
  `--accept-slow`, `--embed-int4` and `--cpu-exact-prefill`. Both register them from one place, so
  they should stay in step. A chat binary with a model built in now also honours `--kv`, `--fit`
  and `--exact-prefill`, which it had been accepting and quietly ignoring.

## Tool calls come back well formed

With two or more tools supplied, a grammar over those tools now constrains the call once the model
starts one, so a call can no longer be malformed or name a tool you did not supply. On a Qwen2.5-7B
agent transcript, 14 unusable and 10 invalid-argument calls out of 111 became 0 and 0. Turns where
the model answers in prose are untouched: 630 of 630 outputs were byte-identical with the feature
on and off, at the same speed. `GOINFER_TOOL_UNION=0` turns it off.

- llama3, which writes its calls as bare JSON, is constrained under `auto` as soon as the reply
  begins as a call.
- Small Qwen2.5-Coder models tend to emit the call object without its `<tool_call>` wrapper, which
  used to come back as prose. A reply that opens with a JSON object naming a supplied tool is now
  treated as that call (0 → 236 and 219 parsed calls out of 300 on the 0.5B and 1.5B). This fixes
  the form of the call, not the judgement: a small model still often picks the wrong tool.
- The same handling applies across OpenAI chat, Responses and Anthropic Messages.

Grammar can make a call well formed; it cannot make it a good idea. That part is still up to the
model.

## Faster, mostly without changing a bit

All figures are paired, same-session measurements; the records are linked from `CHANGELOG.md`.

**CUDA**

- Long-context decode: 1.5B at 3,900 keys 124.7 → 194.1 tok/s, 7B at 8,000 keys 39.6 → 61.1.
- MoE models too big for VRAM (the C′ expert cache) overlap expert transfers with compute:
  26B 30.4 → 38.7 tok/s, bit-identical. MoE prefill admits each expert once per chunk rather than
  once per token, 2.26–2.66× faster, also bit-identical. The expert staging buffer is now pinned
  in place, which made a 26B load about 10% faster.
- Fused normalization and activation kernels: a further 2–5% on decode, bit-identical. The 7B now
  decodes at 0.99–1.03× of Ollama v0.32.5 on the same card.
- `top_k` / `top_p` / `min_p` sampling runs at 0.96–0.97× of greedy speed, up from about 0.66×,
  with the same tokens at a fixed seed. Plain `temperature` sampling draws on the device.
- Speculative decoding reduces its argmax on the GPU: 1.23× on a spec round, same output.
- The vision tower's attention: 26.0 → 4.1 s per image. This one does change output slightly
  (cosine 0.96 against the previous kernel) and ships by owner decision;
  `GOINFER_CUDA_VISION_ATTN=exact` restores the previous kernel.

**CPU (amd64)**

- Decode got two rounds of bit-identical work. First, amd64 stopped using a grouped-attention
  fallback that was slower than the path it replaced, and stopped over-parallelising the
  activation (1.5B 74.5 → 54.5 ms/token). Then the gate and up projections were fused, a further
  1.02–1.24× served. That puts it at about 0.82× of Ollama on the same machine, up from
  0.66–0.82×. Still behind, and closer.

**WebGPU**

- Batched prefill uses a register-blocked matrix kernel, bit-identical: 5.89× at 1.5B with a
  512-token prompt (1.44 s → 0.25 s to first token).

**Metal**

- Decode attention switches to a flash-style kernel past depth 1,536 tokens: 1.11–1.19× at
  depth. Not bit-identical; `GOINFER_METAL_ATTN_FA=0` opts out.
- Plain `temperature` sampling draws on the device (about 0.80× → 0.96× of greedy).

## Fixes

- A gemma4-26B `.gguf` loaded directly generated only `<pad>`. It now matches the sidecar path
  byte for byte.
- When a GPU backend declines to run a model resident, the load banner and `serve check` now give
  its actual reason, for example which features the model needs that the backend does not
  implement, or the memory guard's own figures.

## Smaller things you might notice

- **A new family: Spark-X2.5** (`spark2_5`, 1.7B and 4B community coding tunes), CPU only for now.
  On the real 1.7B checkpoint it matches HuggingFace's logits (cosine 1.000000) and greedy
  continuation.
- `GOINFER_DECODE_TIMING` also prints where a decode token's time goes (attention, MLP, LM head).
- Both binaries refuse a negative `--ctx`, `--moe-cache-slots` or `--weight-cache` at startup.
- The shared kernel library moved to aikit v1.47.1.

## Getting it

Binaries for six platforms are attached to this release, for both `goinfer-serve` (each with the
backend that platform can actually use) and `goinfer-chat`, with checksums — plus a model-embedded
`goinfer-chat-0.5b` per platform if you want a single file that needs nothing else.

```bash
go install github.com/townsendmerino/goinfer/cmd/serve@v0.20.0
```

goinfer is still pre-1.0: the forward-pass and quantization numerics are parity-gated against
HuggingFace and are the stable contract, and [`docs/api-tiers.md`](../api-tiers.md) says which
surfaces v1.0 will bind. Until then, any surface may still change.
