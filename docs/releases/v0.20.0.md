# goinfer v0.20.0 — Gemma 1 and 2, several requests at once, decisions, and a faster Mac

goinfer runs open-weight language models inside a Go program, with no cgo, and also ships as a server and as
single-file binaries.

This release adds Gemma 1, CodeGemma and Gemma 2, lets a server work on several requests for the same model at once,
answers structured decisions, and makes decoding and prompt processing noticeably faster on a Mac's GPU. Most of the
speed work produces exactly the same output as before. Where something does not, it says so below. The full list of
changes is in [CHANGELOG.md](https://github.com/townsendmerino/goinfer/blob/v0.20.0/CHANGELOG.md).

## Before you upgrade

- **The same seed now gives different tokens.** Plain `temperature` sampling (no `top_k`, `top_p` or `min_p`, which
  is the OpenAI default) uses a new, faster way of drawing each token. The probabilities are unchanged, but a given
  seed no longer reproduces an earlier release's output. Sampling with `top_k`, `top_p` or `min_p` is unchanged
  token for token.
- **`--embed-int4` is on by default.** With `--quant int4`, the model's vocabulary tables (the token embedding and the
  output layer) are stored at 4 bits as well. That halves the largest single block of weights in a small model and
  made CPU decoding 1.05–1.12× faster. It is slightly lossy: about 2.3 points of top-1 accuracy, mostly on rare
  tokens (measured before it became the default, and not re-checked since). `--embed-int4=false` restores the
  previous 8-bit tables. On `--backend metal` it stays off, because the Mac's GPU path cannot use 4-bit tables yet.
- **Reasoning models keep their thinking out of the answer.** A Qwen3, Qwen3.5 or Gemma 4 reply no longer mixes
  `<think>…</think>` into `content`. The thinking arrives as `reasoning_content` (OpenAI chat), as `thinking` blocks
  (`/v1/messages`), or is left out of `output_text` (`/v1/responses`). A client that parsed the tags out of
  `content` itself can pass `-reasoning-format none`.
- **`GOINFER_*` environment variables are read once per model, when it loads.** Changing one afterwards no longer
  affects a loaded model. A Go program that changed them mid-process should set `decoder.Options.Knobs` instead.
- **`--kv i8` now applies on the CPU too**, where it selects a smaller, slightly lossy 8-bit cache; before, the CPU
  ignored it. `--kv-quant` still works, as a deprecated CPU-only override.
- **A `.gguf` is now converted once and loaded from a cache, on macOS and Linux.** The first start for each model and
  backend writes a copy in goinfer's own `.giw` format beside the `.gguf`, roughly the model's size; later starts map
  that file instead of re-quantizing (a 7B on CUDA starts in 10 s instead of 26.6 s). A cache built by an earlier
  release is rebuilt once. If there is not enough free disk, `serve` refuses to start and says so;
  `-direct-load` or `GOINFER_GGUF_DIRECT=1` keeps the old behaviour.
- **Long conversations use faster attention by default**, on CUDA past 2,048 tokens of context and on Metal past
  1,536. It can change the last digits of the output, and very occasionally a word where two choices were almost
  tied. Both were checked against the exact version on held-out prompts before shipping. `GOINFER_CUDA_FLASH_DECODE=0`
  and `GOINFER_METAL_ATTN_FA=0` turn them off.
- **Removed:**
  - two `serve` flags that no longer did anything, `--metal-fast-prefill` and `--cpu-fast-attention` (a script that
    still passes either now stops at startup);
  - unused `decoder` API: the experimental EAGLE-3 speculation code, the MTP measurement adapter, `F16BitsToF32`,
    `CPUExpertWeights`, `ComputeExpertMLP` and `Model.NewCPUBlockSpec`;
  - eight `GOINFER_*` variables that no longer have any effect;
  - the gemma demo programs, which were never released.

## New models

- **Gemma 1, CodeGemma and Gemma 2**, from the original weights or GGUF files. On gemma-2b-it, codegemma-2b and
  gemma-2-2b-it, the output matches HuggingFace's reference implementation: to within float rounding from the original
  weights, and closely from llama.cpp's 8-bit GGUF files. Gemma 1 and CodeGemma run on the GPU (checked on CUDA and Metal).
  Gemma 2 runs on the CPU only for now, because no GPU backend has the kernel for its attention-score cap yet; a GPU
  load says so and falls back.
- **Spark-X2.5** (1.7B and 4B community coding models), on the CPU for now; checked against the reference on the 1.7B.
- **Images for Qwen3.5.** A Qwen3.5 checkpoint in its original weights that includes its vision tower accepts images
  through `serve`'s OpenAI `image_url`, on the CPU for now. Checked on the 0.8B so far.
- That makes 39 model families. Each has a page at [goinfer.dev/models](https://goinfer.dev/models/) saying how it was
  checked.

## Several requests at once

`serve` now works on up to four requests for the same model at the same time by default (`--max-concurrent`). Each
has its own cache, so every reply is identical to the one it would get alone. On the CPU, dense models of 2 GiB or more
process those requests' next tokens together in one pass (`--cpu-batch`), and on Metal and CUDA they decode in shared
steps on the GPU. Each conversation also keeps its own cache on the GPU (`--kv-sessions`), so two conversations
alternating no longer re-read each other's history, and a long new prompt is read in chunks between the other
requests' tokens (`--prefill-chunk`) so it does not stall them.

With four clients on one model, throughput rose to: CPU 1.5B 1.97×, CPU 7B 2.19×, Metal 1.5B 1.59×, CUDA 1.5B 1.38×
and CUDA 7B 1.83×. A single request runs as fast as before. Speculative decoding, adapters, vision and
weight-streaming models still take one request at a time.

## Decisions

`POST /v1/systemone` accepts the request format of TypeSafe's decisions API, so clients such as jevx can use goinfer
([setup](https://github.com/townsendmerino/goinfer/blob/v0.20.0/docs/integrations/typesafe-jevx.md)).

- By default it reads each question once and scores the allowed answers, without generating any text. That has been
  measured, and it is well short of a model trained for the job: Qwen3.5-9B chose the right answer 42% of the time on
  an out-of-distribution test set, against the 92% published for the trained JEV-9B.
- **With a trained decision head** (a small classifier trained on top of the model), `--model name=DIR,head=DIR`
  answers the way the JEV reference does, on the GPU when the model fits there. `goinfer-chat decide --head DIR` does
  the same from the command line. For Qwen3.5, a LoRA adapter is merged when the model loads, and `prequant -lora`
  can build it into a `.giw` file ahead of time.

## Structured output

- **Tool calls come back well formed.** With two or more tools, a grammar over the tools you sent constrains each call
  once the model starts writing one, so it cannot be malformed or name a tool you did not send. On a recorded
  Qwen2.5-7B agent session, 14 unusable and 10 invalid-argument calls out of 111 became 0 and 0. Turns where the
  model answers in prose came out byte-identical with the feature on and off. Llama 3's bare-JSON calls are covered
  too, and small Qwen2.5-Coder models that leave off the `<tool_call>` wrapper now have their calls recognised.
  Grammar can make a call well formed; choosing the right tool is still up to the model.
- **Per-field confidence.** Add `"goinfer_confidence": true` beside a `json_schema` response format (or call
  `constrain.Masker.CaptureConfidence` in Go) and each enum, boolean and integer field comes back with the model's
  probability over the values the schema allowed. A low value is wrong more often, which makes it useful for routing
  ("ask a person below 0.7"). It is not calibrated, though, and it is not the probability that the value is right.

## Faster, mostly with identical output

Each figure compares two builds, or goinfer and Ollama v0.32.5, side by side in one session. The records are linked
from the CHANGELOG.

**On a Mac's GPU (M1 Pro)**

- The kernels that do most of decoding's work were rewritten with identical output: a 1.5B token now takes 10.46 ms
  of GPU time instead of 12.93, and a 7B token 33.12 ms instead of 45.78. Side by side with Ollama, decoding now reads
  1.03–1.06× on the 1.5B and 1.06–1.19× on the 7B, from short contexts to 3,900 tokens, and 1.30× on the 0.5B at a short context.
- Reading the prompt is much faster: the main matrix kernel is 3.23× faster with identical output, and a new attention
  kernel roughly halves the time to read a long prompt (3,900 tokens on the 1.5B: 8.2 s down to 4.3 s). Time to first token
  on the 1.5B is now level with Ollama's at a 3,900-token prompt, and within measurement noise of it at 512 tokens.
- Long conversations decode 1.22× faster at 2,048 tokens and 1.41× at 3,900 on the 1.5B (output can differ in the
  last digits; see "Before you upgrade").
- A `.giw` model's weights are used straight from the file, so the operating system can reclaim that memory instead
  of swapping it: memory held after 32 tokens fell from 4,134 MB to 105 MB on a 7B.
- Speculative decoding (`--spec ngram`) is 2.08× faster than plain decoding on the 1.5B when a reply mostly repeats
  text already in the conversation, such as editing code.

**On CUDA (RTX 2070 SUPER)**

- Long conversations decode much faster: the 1.5B at 3,900 tokens of context went from 124.7 to 194.1 tokens per
  second, and the 7B at 8,000 from 39.6 to 61.1. In a side-by-side comparison on 2026-09-29, goinfer decoded faster
  than Ollama in all 12 cases measured (0.5B, 1.5B and 7B, from short contexts to 8,000 tokens), by 1.05–1.47×.
- Models with recurrent layers (Qwen3.5, Qwen3-Next, Olmo Hybrid) now read the prompt in one batch instead of a token
  at a time: 5.7× faster on Qwen3.5-9B, with identical output. On models whose attention heads are 128 wide (such as
  Qwen2.5-1.5B and -7B), reading a long prompt is 1.50× faster at 3,900 tokens, also with identical output.
- Mixture-of-experts models too big for the card copy experts to the GPU while it computes (Gemma 4 26B: 30.4 to 38.7
  tokens per second) and fetch each needed expert once per chunk of the prompt (2.26–2.66× faster), both with
  identical output.
- Sampling with `top_k`, `top_p` or `min_p` now runs at 0.96–0.97× of greedy speed, up from about 0.66×.
- The vision encoder takes 4.1 s per image instead of 26.0. Its output differs slightly from before;
  `GOINFER_CUDA_VISION_ATTN=exact` restores the previous kernel.

**On the CPU**

- Decoding on x86 got faster in several steps, all with identical output. Side by side with Ollama on a Ryzen 7 3700X
  it now reads 0.905× on the 0.5B, level on the 1.5B (1.01×) and 1.04× on the 7B.
- On Apple Silicon, long conversations decode 1.32× faster at 8,192 tokens of context on the 1.5B.

**With WebGPU**

- Reading the prompt uses a new matrix kernel with identical output: 5.89× faster on the 1.5B with a 512-token prompt
  (time to first token 1.44 s down to 0.25 s).

## Fixes

- **Metal: two less common setups could corrupt the attention cache without any error.** One was `--kv i8`; the
  other was a context past 4,096 tokens on a model whose attention heads are wider than 128, or with
  `GOINFER_METAL_FUSED_ATTENTION=0`. Both now use the slower, correct way of reading the prompt, and say so.
- **Phi-3 gave unusable output at every quantized setting**, and had no chat template. A default Phi-3 load now keeps
  the file's 4-bit weights as they are (`--quant q4k`) on the CPU and CUDA, and uses a finer-scaled 8-bit path
  elsewhere. The chat template and the tokenizer are fixed too.
- **CUDA: prompts longer than 512 tokens were mostly read by the slow fallback kernels**, 3.5× slower at 3,900
  tokens. This bug shipped in v0.19.0.
- **Speculative decoding could leave its cache one position off** when a reply stopped at `max_tokens`, so a later
  turn could differ from what plain decoding would produce. Fixed for `--spec ngram`, the CUDA drafter, and
  speculation under a schema or tool grammar.
- A Gemma 4 26B `.gguf` loaded directly produced only `<pad>`; a Gemma 4 `.gguf` never ran on the Mac's GPU; and
  gpt-oss-20b with `--moe-cache-experts` ran out of host memory while loading on CUDA. All three are fixed.
- When a model cannot run on the GPU, the startup banner and `serve check` now give the actual reason.

## Smaller things you might notice

- `serve` watches swap after it starts. Once swap has grown by 512 MiB it answers new requests with a 503 instead
  of letting the machine slow to a crawl, and finishes the ones already running (`GOINFER_SWAP_GUARD` sets the limit).
- `goinfer-chat` accepts every model-loading flag `goinfer-serve` does, and gained `--spec ngram`.
- `--moe-pager pool`, the macOS default, keeps a paged mixture-of-experts model to its memory budget.
- Every `serve` flag is listed in [docs/flags.md](https://github.com/townsendmerino/goinfer/blob/v0.20.0/docs/flags.md),
  generated from the binary itself.
- The shared kernel library moved to aikit v1.51.0.

## Using it from Go

goinfer is a Go module you import, with no cgo. From inside your own module:

```bash
go get github.com/townsendmerino/goinfer/decoder@latest github.com/townsendmerino/goinfer/tokenizer@latest
```

[Use it from Go](https://goinfer.dev/docs/use-from-go/) walks through the smallest working program, output shaped
like a Go struct, and per-field confidence. Every code sample on it is taken from an example that is built and
tested.

## New to how any of this works?

[An inference primer for Go engineers](https://goinfer.dev/book/) has eleven chapters on how a language model actually
runs, for someone who knows Go and not machine learning, each ending in a number measured in this repo. New in this
release: how to predict decoding speed from memory bandwidth before measuring it, and what Go's garbage collector
costs while a model runs (in steady state, almost nothing; the one case measured where it hurt is described).

## Getting it

Binaries for six platforms are attached to this release with their checksums, and listed on
[goinfer.dev/download](https://goinfer.dev/download/): `goinfer-serve` (each built with the GPU backend that platform
can use), `goinfer-chat`, and `goinfer-chat-0.5b` and `goinfer-chat-1.5b`, which have a model built in if you want a
single file that needs nothing else.

```bash
go install github.com/townsendmerino/goinfer/cmd/serve@v0.20.0
```

goinfer is still before 1.0. The model math and quantization are checked against HuggingFace's own implementation
and are what stays stable; [docs/api-tiers.md](https://github.com/townsendmerino/goinfer/blob/v0.20.0/docs/api-tiers.md)
says which parts of the API v1.0 will commit to. Until then, any of it may still change.
