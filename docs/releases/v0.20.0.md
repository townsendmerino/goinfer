# goinfer v0.20.0 — Gemma 1 and 2, several requests at once, decisions, and a faster Mac

> **This file is the DRAFT for the GitHub Release body** (`gh release create --notes-file`).
> Per `RELEASING.md`, the **published Release body is canonical** the moment it goes out — after
> that, edit the Release, not this file. It lives here rather than in gitignored `docs/internal/`
> so it is reviewable in a clone and cannot silently diverge on one machine.

This release adds three model families, lets a server run several generations of one model at once,
answers structured decisions, and makes Metal decode and prefill noticeably faster on a Mac. Most
of the speed work produces exactly the output it did before. Where something does not, it says so
below, and the full list is in `CHANGELOG.md`.

## Before you upgrade

- **Seeded sampling produces different tokens.** Plain `temperature` sampling (no `top_k`,
  `top_p` or `min_p`, which is the OpenAI default) now draws by Gumbel-max from a counter-based
  generator keyed by the seed. The distribution is unchanged, but for a given seed the tokens are
  not the ones an earlier release produced. Sampling with `top_k` / `top_p` / `min_p` is unchanged
  token for token.
- **`--embed-int4` is on by default.** With `--quant int4` the token-embedding and LM-head table is
  int4 too, which halves the largest tensor on a small model and made CPU decode 1.05–1.12× faster.
  It is lossy (about 2.3 points of top-1, mostly on rare tokens), and `--embed-int4=false` restores
  the previous table. On `--backend metal` it stays off, because the Metal GPU path does not take an
  int4 table yet.
- **Reasoning models put their thinking in its own field.** A Qwen3, Qwen3.5 or Gemma 4 reply no
  longer mixes `<think>…</think>` into `content`; it arrives as `reasoning_content` (OpenAI chat),
  `thinking` blocks (`/v1/messages`) or is left out of `output_text` (`/v1/responses`). A client
  that parsed the tags out of `content` can pass `-reasoning-format none`.
- **`GOINFER_*` variables are read once per model, at load.** Changing one after a model has loaded
  no longer affects it. A program that toggled them mid-process should set `decoder.Options.Knobs`
  instead.
- **`--kv i8` now applies on the CPU too**, selecting the lossy int8 CPU cache; before, it was
  ignored there. `--kv-quant` still works as a deprecated CPU-only override.
- **A `.gguf` loads through a `.giw` sidecar by default on macOS and Linux.** The first start per
  model and backend transcodes once and writes roughly the model's size beside the `.gguf`; after
  that, loads map the file instead of re-quantizing (CUDA 7B: 10 s instead of 26.6 s). An int4
  sidecar from an earlier release is rebuilt once (weights format v15). If there is not enough free
  disk, `serve` refuses to start and says so; `-direct-load` or `GOINFER_GGUF_DIRECT=1` keeps the
  old behaviour.
- **CUDA decode at long context uses a new attention kernel by default** once the span reaches 2048
  keys, and Metal past 1536. Neither is bit-identical to the exact path, so output deep into a long
  conversation can differ from earlier releases in the last bits, and occasionally in a token at a
  near-tie. Both passed pre-registered fidelity gates; `GOINFER_CUDA_FLASH_DECODE=0` and
  `GOINFER_METAL_ATTN_FA=0` turn them off.
- **Removed:** two dead `serve` flags (`--metal-fast-prefill`, `--cpu-fast-attention`; a script
  passing either now stops at startup), unused `decoder` API (EAGLE-3 speculation, the MTP
  measurement adapter, `F16BitsToF32`, `CPUExpertWeights`, `ComputeExpertMLP`,
  `Model.NewCPUBlockSpec`), eight `GOINFER_*` variables that now do nothing, and the never-released
  gemma demos.

## New models

- **Gemma 1, CodeGemma and Gemma 2**, from safetensors or GGUF. On the released gemma-2b-it,
  codegemma-2b and gemma-2-2b-it they match HuggingFace's logits (cosine 1.000000 in f32, and
  0.999981–0.999999 from llama.cpp's Q8_0 GGUFs). Gemma 1 and CodeGemma run on the GPU, measured on
  CUDA and Metal.
  Gemma 2 runs on the CPU only for now: its attention-score softcap has no GPU kernel yet, and a
  GPU load says so and falls back.
- **Spark-X2.5** (`spark2_5`, 1.7B and 4B community coding tunes), CPU only for now.
- That makes 39 families. Each has a page at [goinfer.dev/models](https://goinfer.dev/models/) that
  says how it was checked.

## Several requests at once

`serve` now runs up to four generations of one model at the same time by default
(`--max-concurrent`), each on its own cache, so every reply is identical to serving that request
alone. On the CPU their decode steps can share one batched pass (`--cpu-batch`, on for models of
2 GiB or more), and on Metal and CUDA dense models decode in shared batched steps. Each
conversation also keeps its own resident cache on the GPU (`--kv-sessions`), so interleaved
conversations stop re-reading each other's history, and a long new prompt is prefilled in chunks
between other requests' steps (`--prefill-chunk`).

With four clients against one model: CPU 1.5B 1.97× the serialized throughput, CPU 7B 2.19×
(batched against unbatched workers), Metal 1.5B 1.59×, CUDA 1.38× (1.5B) and 1.83× (7B). A model
on its own runs as before. Speculative decoding, adapters, vision and weight-streaming models
still run one at a time.

## Decisions

`POST /v1/systemone` answers TypeSafe's decisions wire shape, so clients such as jevx work against
goinfer ([recipe](https://github.com/townsendmerino/goinfer/blob/v0.20.0/docs/integrations/typesafe-jevx.md)).

- By default it scores the option labels with the served model: one prefill per question, nothing
  generated. This is measured, and it is well short of a trained model: Qwen3.5-9B scored top-1
  0.42 against the trained JEV-9B's 0.92 on an out-of-distribution sample.
- **With a trained decision head**, `--model name=DIR,head=DIR` answers the way the JEV reference
  does, on the GPU when the model is resident. `goinfer-chat decide --head DIR` does the same from
  the command line. A LoRA adapter is merged at load for Qwen3.5, and `prequant -lora` can bake one
  into a `.giw`.

## Structured output

- **Tool calls come back well formed.** With two or more tools supplied, a grammar over those tools
  constrains a call once the model starts one, so it can no longer be malformed or name a tool you
  did not send. On a Qwen2.5-7B agent transcript, 14 unusable and 10 invalid-argument calls out of
  111 became 0 and 0, and turns where the model answers in prose were byte-identical with the
  feature on and off. llama3's bare-JSON calls are covered too, and small Qwen2.5-Coder models that
  leave off the `<tool_call>` wrapper now have their calls recognised. Grammar can make a call well
  formed; picking the right tool is still up to the model.
- **Per-field confidence.** `"goinfer_confidence": true` beside a `json_schema` response format (or
  `constrain.Masker.CaptureConfidence` in Go) reports, for each enum, boolean and integer field, the
  model's probability over what the schema allowed. It ranks answers, so it is useful for routing
  ("ask a person below 0.7"), but it is not calibrated and is not the probability that the value is
  right.

## Faster, mostly without changing a bit

All figures are paired, same-session measurements; the records are linked from `CHANGELOG.md`.

**Metal (M1 Pro)**

- Decode matrix-vector kernels rewritten, bit-identical: a 1.5B token 12.93 → 10.46 ms, a 7B
  45.78 → 33.12 ms. Against Ollama v0.32.5 in the same session, decode now reads 1.03–1.06× on the
  1.5B and 1.06–1.19× on the 7B, from depth 128 to 3,900.
- Prefill matrix kernel 3.23× faster, bit-identical. Time to first token is now 1.05× behind Ollama
  at a 512-token prompt (was 2.65×) and 1.96× behind at 3,900 (was 4.18×), so long prompts are
  still the slower part.
- Long-context decode attention: 1.22× at 2,048 and 1.41× at 3,900 on the 1.5B (not
  bit-identical; it passed its fidelity gate).
- `.giw` weights are served straight from the file, so they are page cache rather than memory that
  swaps: memory held after 32 tokens 4,134 → 105 MB on a 7B.
- `--spec ngram` verifies on the batched kernels: 2.08× plain decode on copy-heavy traffic.

**CUDA (RTX 2070 SUPER)**

- Long-context decode: 1.5B at 3,900 keys 124.7 → 194.1 tok/s, 7B at 8,000 keys 39.6 → 61.1. In
  the 2026-09-29 peer sweep goinfer decoded ahead of Ollama in all 12 greedy cells, 1.05–1.47×.
- Gated-DeltaNet models (Qwen3.5, Qwen3-Next, Olmo Hybrid) prefill in a batch: 5.7× on Qwen3.5-9B,
  bit-identical. Prefill attention on head-dim-128 layers: 1.50× at 3,900, bit-identical.
- MoE models too big for VRAM overlap expert transfers with compute (26B 30.4 → 38.7 tok/s) and
  admit each expert once per prefill chunk (2.26–2.66×), both bit-identical.
- Sampling with `top_k` / `top_p` / `min_p` runs at 0.96–0.97× of greedy speed, up from about 0.66×.
- The vision tower's attention: 26.0 → 4.1 s per image. This one changes output slightly (cosine
  0.96 against the previous kernel); `GOINFER_CUDA_VISION_ATTN=exact` restores it.

**CPU**

- x86 decode got several bit-identical rounds. Against Ollama on the same Ryzen 7 3700X it now reads
  0.905× on the 0.5B, level on the 1.5B (1.01×) and 1.04× on the 7B.
- arm64 decode: grouped attention kernels, 1.32× at depth 8,192 on the 1.5B.

**WebGPU**

- Batched prefill uses a register-blocked matrix kernel, bit-identical: 5.89× at 1.5B with a
  512-token prompt (1.44 s → 0.25 s to first token).

## Fixes

- **Phi-3 gave unusable output at every quantized precision**, and had no chat template. A default
  Phi-3 load now uses `--quant q4k` on the CPU and CUDA (int8 with per-32 activation scales
  elsewhere), and the template and tokenizer are fixed.
- **CUDA: long prompts prefilled most of their chunks on the slow exact kernels**, 3.5× slower at
  3,900 tokens. This regression was in v0.19.0.
- **Speculative decoding could leave the cache one position off** at a `max_tokens` stop, so a
  later turn could differ from plain greedy. Fixed for `--spec ngram`, the CUDA block drafter and
  the grammar-fused loop.
- A gemma4-26B `.gguf` loaded directly generated only `<pad>`; a Gemma 4 `.gguf` never went
  resident on Metal; gpt-oss-20b with `--moe-cache-experts` ran out of host memory while loading
  on CUDA. All three are fixed.
- When a GPU backend declines to run a model resident, the load banner and `serve check` now give
  its actual reason.

## Smaller things you might notice

- `serve` watches swap after startup and returns 503 to new requests once it has grown by 512 MiB,
  instead of letting the machine page (`GOINFER_SWAP_GUARD`).
- `goinfer-chat` accepts every model-loading flag `goinfer-serve` does, and gained `--spec ngram`.
- `--moe-pager pool` (the macOS default) holds a paged MoE model's expert budget firmly.
- Every `serve` flag is listed in [docs/flags.md](https://github.com/townsendmerino/goinfer/blob/v0.20.0/docs/flags.md),
  generated from the binary.
- The shared kernel library moved to aikit v1.51.0.

## Using it from Go

goinfer is a Go module you import, with no cgo. From inside your own module:

```bash
go get github.com/townsendmerino/goinfer/decoder@latest github.com/townsendmerino/goinfer/tokenizer@latest
```

[Use it from Go](https://goinfer.dev/docs/use-from-go/) walks through the smallest program, output
shaped like a Go struct, and per-field confidence, with every code sample taken from a tested
example.

## New to how any of this works?

There is an eleven-chapter primer, written for someone who knows Go and does not know machine
learning: **[An inference primer for Go engineers](https://goinfer.dev/book/)**. Each chapter ends
in a measured number from this repo.

## Getting it

Binaries for six platforms are attached to this release, with checksums, and listed on
[goinfer.dev/download](https://goinfer.dev/download/): `goinfer-serve` (each with the GPU backend
that platform can use), `goinfer-chat`, and a model-embedded `goinfer-chat-0.5b` per platform if
you want a single file that needs nothing else.

```bash
go install github.com/townsendmerino/goinfer/cmd/serve@v0.20.0
```

goinfer is still pre-1.0: the forward-pass and quantization numerics are parity-gated against
HuggingFace and are the stable contract, and [`docs/api-tiers.md`](../api-tiers.md) says which
surfaces v1.0 will bind. Until then, any surface may still change.
