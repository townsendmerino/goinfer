# goinfer v0.11.0

**MINOR** — backward-compatible additions and behavior changes; no public API removed. The
core-numerics surface is unchanged since `6edd1ca`; the delta from there to this tag is docs-only.

> **⚠ Sampled output for a given seed changed in this release** — both the temperature-only path and
> the filtered `top_p`/`top_k`/`min_p` paths. **The distribution is unchanged** (same sampler
> semantics, same probabilities); only the seed→token mapping shifts, once, for both paths together.
> If you pin a seed for reproducible sampling, expect a different token stream. Greedy (`temperature=0`)
> is unaffected.

## The three stories

### 1. Sampling overhaul — the nonzero-temperature cliff is largely gone
Temperature sampling normalized the full vocabulary sequentially every token; it is now a deterministic
parallel normalization (fixed chunk count, reduction ordered by chunk index — identical output across
machines and `GOMAXPROCS`, gated by `TestChunkedSoftmax_MachineIndependent`), and the separate
normalize-divide pass is gone. Measured decode-only (RTX 2070 SUPER, q4_K_M int4, 128-token prompt):

- **temperature-only +126–137%** — qwen2.5-coder-0.5b 97.6 → 220.2 tok/s, gemma3-1b 56.6 → 134.2.
- **temperature+top_p ~2×** — 93.4 → 184.7, 56.3 → 117.0.
- **`top_k=1` routes to the on-device greedy fast path** (+18–22%): a `top_k=1` request with no
  logprobs / logit-bias / penalties is deterministic, so it skips the full-logits readback exactly as
  `temperature=0` does — emitted tokens unchanged (`decoder.TestTopK1_MatchesGreedy`).

Net: the published sampled deficit vs the peer fell from **2.1–2.9× to 1.08–1.40×** (anchored,
`docs/benchmarks.md`). This is the release's biggest user-facing win — most chat traffic runs
temperature > 0.

### 2. Split-KV decode attention re-gated — a default-path regression fixed
The split-KV attention gate turned on at `nKeys ≥ 256` for every model — a constant characterized on
one geometry by an in-process microbench. End-to-end measurement across four geometries × six depths
shows it fired **3–12× too early** and was a **live regression of up to 18–25%** (and wrong on its own
geometry). It is now a **measured per-geometry table** with a "never" class (phi3-mini MHA never
benefits) and a conservative default, judging each layer by its **effective attended span** (so
sliding-window layers are gated by their window). Kernel-selection only — both arms stay bit-identical
(`TestSplitKV_bitIdentical`), so any request produces exactly the same tokens. Measured: qwen2.5-coder-0.5b
@512 ctx **240.0 → 286.6 tok/s** (+19%), gemma3-1b @512 **152.7 → 167.7**. `GOINFER_SPLITKV_MIN_KEYS=<n>`
overrides the threshold without a rebuild. Method: `docs/benchmarks.md` §B6.

### 3. Capability — configurable deep context, and a larger MoE router
- **`-ctx N` raises the CUDA resident KV capacity** (was a hard-coded 4096); per-model via
  `--model name=path,ctx=N`. The **default is unchanged** — unset still means 4096, so nobody who did
  not ask allocates deep-KV VRAM. The KV a configured cap implies is **VRAM-checked at load and fails
  fast naming its arithmetic**: `resident context 32768 positions needs 1.88 GB of KV (56.0 KB/position
  across 28 layers) but only 0.37 GB is free …`. Allocation-size change only — no kernel, no numerics.
  It unblocks the 8k/16k/32k depth cells.
- **The resident MoE router capacity cap is raised 256 → 512** (eligibility, not correctness). This
  makes **Kimi K2 GPU-resident-eligible on WebGPU** (it ships 384 experts; the router scored into a
  256-slot scratch and correctly declined to CPU). Delivered on WebGPU for the K2 class; **on CUDA the
  cap is raised too but K2 still declines on `FeatMLA`** (declared by WebGPU only), so the CUDA raise
  clears one of two blockers ahead of any MLA-on-CUDA work — stated honestly, not overclaimed. Metal
  stays at 256 (Mac-validation work) and is now correctly declared in the capability matrix.

## Also in this release
- **README repositioning** — a new "What it's for — and what it isn't" section (single-user local
  inference, no toolchain; explicitly *not* a serving engine — no continuous batching / paged
  attention), and a corrected parity claim: every GPU fast path is gated **bit-identical against its
  own reference path**, with all backends **parity-gated** against the pure-Go CPU implementation,
  which is itself parity-gated against HuggingFace (byte-identity is path-vs-path; WebGPU MLA is
  tolerance-gated — the old "every GPU path byte-identical vs CPU" was an overclaim).
- **The capability matrix gains an honest `experimental` tier.** Parity `status: validated` now
  *enforces* a T3 (full-model real-oracle class) run (`TestParityManifest_methodTier`); a genuine but
  sub-T3 row is labeled `experimental: <method>` and excluded from the supported count, so a weak row
  no longer sits at "validated" with a T1 artifact in a T3 slot.
- **`/admin/models/unload` frees device memory instead of leaking it** (a drain, not a `Close()` race),
  and no longer returns `409` for a busy model — it unpublishes immediately and returns `200 {freed}`
  within `-unload-drain-wait` (default 5s) else `202`; `/health` gains a `draining` array.

Full detail and every measured number: `CHANGELOG.md` and `docs/benchmarks.md`.

## Install

```bash
go get github.com/townsendmerino/goinfer@v0.11.0     # brings the default (WebGPU) GPU backend
go run  github.com/townsendmerino/goinfer/cmd/serve --model ~/models/qwen2.5-coder-0.5b-instruct-q4_k_m.gguf
```

Selecting the CUDA or Metal backend is a build-tag / entrypoint choice — see the **Build** section of
the README for the exact per-backend commands.
