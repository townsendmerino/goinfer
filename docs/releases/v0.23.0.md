# goinfer v0.23.0 — coding agents against a local model, and speech to text

> **DRAFT, 2026-10-14. Not released, not tagged.** Checked against `CHANGELOG.md`'s `[Unreleased]` section at the
> release commit `695ce16c` (main after PR #14, KV3 CUDA, and PR #15). Nothing in it is conditional any more. X1
> (`usage.goinfer_timings`), HL and KV2 are on branches and ride the next release.
> The release plan and what is still owed: [v0.23.0-checklist.md](v0.23.0-checklist.md). This header is not part of
> the published notes.

goinfer runs open-weight language models inside a Go program, with no cgo, and also ships as a server and as
single-file binaries.

Most of this release is about one use: pointing a coding agent (Claude Code, Codex, opencode) at a model served by
goinfer, and having it work. It also adds speech to text, faster prompts under `--backend webgpu`, and a fix for
sampled output under concurrency on CUDA that you should read about if you serve Gemma 4, Command-R or Granite there.
The full list of changes is in [CHANGELOG.md](https://github.com/townsendmerino/goinfer/blob/v0.23.0/CHANGELOG.md).

## A fix to know about: concurrent sampled output on CUDA

**Who was affected:** `--backend cuda` serving a dense Gemma 4, Command-R or Granite (any model with a final-logit
softcap or a logit scale) to two or more conversations at once, with a sampling temperature above zero. **Since:**
batched multi-conversation decode on CUDA, added on 2026-09-27, so v0.20.0, v0.21.0 and v0.22.0 all have it.

In that case each sampled token was drawn from logits with the softcap or the logit scale applied twice. On a dense
Gemma 4 that pushed the logits further toward the cap; on Command-R, whose logit scale is 0.0625, it raised the
effective sampling temperature by a factor of 16. Greedy decoding, and a conversation decoding alone, were not
affected. Each transform is now applied once, and a batched row's logits equal the single-conversation result bit for
bit.

## Before you upgrade

None of these breaks an API except the first, but each can change what you see:

- **`.giw` weight files are format v16, and only v16 is read.** A `.giw` built by an earlier release, including one
  embedded in your own binary, must be rebuilt with `cmd/prequant`. Sidecars built by `goinfer-serve` rebuild
  themselves; their file names now carry the format version, so a release binary and a dev build stop rebuilding each
  other's.
- **On CUDA the KV cache is f16 by default** for the dense llama, mistral, qwen2, qwen3 and phi3 families, so the same
  card holds about twice the context. `--kv f32` keeps the exact cache. This was an owner decision over a fidelity
  check that read "parked" rather than "pass" (agreement 92.0% against 92.97% on a 7B at 8,000 keys); the record is
  `docs/tasks/task-cuda-f16-kv-2026-10.md`.
- **`--windowed-kv` is on by default on CUDA**, so a model with sliding-window layers fits a longer context.
  `--windowed-kv=false` opts out. A follow-up turn reuses its prefix when it diverges up to 448 tokens from the end of
  what the cache holds (below).
- **On Metal, the default context grows** from 4,096 toward 16,384 positions when memory allows, so it holds a coding
  agent's first request. That costs KV memory up front in every slot (0.9 GB on Qwen2.5-Coder-1.5B, 1.8 GB on a 7B);
  `--fit=off` or an explicit `-ctx` keeps the old behaviour.
- **A prompt that overflows the context is refused with new wording**, chosen so that each coding agent does the right
  thing (compact the conversation, or stop when the system prompt alone does not fit). A client that matched the old
  text must match the new one; `context_length_exceeded` is still there.
- **Some image replies can differ from v0.22.0's at temperature 0:** Gemma 4 images are now resized as the reference
  processor resizes them (bicubic, not bilinear), and a Qwen3.5-family image turn on the CPU reduces a matmul in a
  different order.

## Coding agents

- **`goinfer-serve connect claude-code | opencode | codex`** writes the agent's configuration against a running
  server, with the context window the server really holds, and says whether the agent's first request fits.
  `-write` patches the agent's own file in place and `-undo` restores it. For Claude Code it also:
  - names the served model in every model slot Claude Code reads, and sets `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`, so a
    subagent that asks for `sonnet` runs on the served model instead of getting a 404;
  - sizes the output cap to what the window leaves beside the 20,199-token first request (a 2,048-token margin, at
    most 8,192), and warns when that comes out under 4,096, the size at which Claude Code compacts after every read;
  - sets `CLAUDE_CODE_ATTRIBUTION_HEADER=0`, without which no two Claude Code conversations share more than 22 tokens
    of prompt.

  Not yet confirmed by running each agent on a file `connect` wrote.
- **Claude Code 2.1.268 works against `/v1/messages` again.** It now sends a `system` message mid-conversation, which
  the route refused.
- **Codex keeps its prompt warm.** `/v1/responses` returns a thinking model's reasoning as a reasoning item and reads it
  back, so a follow-up turn no longer rolls back to the end of the previous prompt. Measured live with Codex and
  Mellum2.1 on an RTX 2070 SUPER: follow-up turns reached their first token in 0.6 s and 0.9 s, against 65 s for the
  cold first turn.
- **Codex replies are no longer cut at 512 tokens**: `/v1/responses` without `max_output_tokens` now allows a quarter of
  the context window, between 1,024 and 8,192 tokens. An answer never carries a stray `</think>` tag.
- **An empty answer says why**, and a tool call a thinking model wrote inside its reasoning is no longer lost (an
  Experimental vendor extension, `goinfer_empty_answer` and `goinfer_tool_calls_from_reasoning`; see `docs/server.md`).
- **A single tool no longer traps a client in a loop**: with exactly one tool and `tool_choice` auto, every reply used
  to be forced into that tool's call.
- **Several system messages are kept**, where all but the last were dropped (Codex lost its instructions).
- **`serve -lenient-tool-calls`** (off by default) reads one fenced JSON call at the end of a reply as a tool call.
  A demonstration that ends on one valid call looks the same as a meant call, so use it with a client that confirms
  before it acts.

## Longer prompts

- **On Metal, a long prompt prefills in blocks**, so a 21,000-token request no longer needs 3 GB of scratch at once and
  is not refused on a 16 GB Mac whose context holds it. Replies and prefill time are unchanged.
- **On CUDA, a prompt past 12,160 tokens
  prefills in batched passes** instead of falling to the per-token path (a 17,755-token Claude Code first request took
  268.7 s to its first token before). Below that length logits and KV are bit-identical to before. Admission on CUDA
  also prices a long prompt by one chunk of its prefill, not by the whole prompt.
- **Under `--backend cuda` with windowed KV, a follow-up
  turn that drops the last reply reuses its prefix** when it diverges up to 448 tokens from the end (up to 1,024 when
  the card has VRAM to spare), where it used to re-prefill the whole prompt on most turns. Output is unchanged.
- The bookkeeping of which conversation each GPU KV slot holds moved into one package. Nothing a request reuses or
  computes changes; it is the first step of the KV work in `docs/tasks/task-kv-architecture-2026-10.md`.

## Security

Fixes from a security audit of the server, none with a known use against a default `serve`:

- **DNS rebinding:** a web page could re-point its own name at `127.0.0.1` and read a loopback server's replies. A
  loopback server now refuses a request whose `Host` is not its own.
- **Turn forgery through tools:** with `tools` declared, a chat marker typed into a message, a tool result or the
  system prompt could end a turn early. It is now tokenized as text.
- **A crash from one request:** a panic inside a job, a batch line or a batch's finalizer ended the whole process. It
  now fails only that item.
- The web UI has a full content policy, its HTML preview no longer runs scripts, and Copy drops hidden characters.

## Apple silicon

- GLM-OCR, Command-R, Command-R7B and Aya now run on the GPU, prefill included, and GLM-OCR's vision tower runs there
  too: an invoice in 23 s instead of 70 s on an M1 Pro.

## Speech, images and embeddings

- **Speech to text**: `POST /v1/audio/transcriptions` from a pure-Go Whisper, and `input_audio` for Qwen3-ASR and Voxtral
  Mini. The audio encoder runs on the GPU under `--backend cuda`.
- **Image turns on Qwen3.5 are much faster**: on a 0.8B, time to first token for a 1024×640 image went from 37.5 s to
  3.6 s on CUDA and from 38 s to 7.7 s on the CPU (exploratory, one run per cell).
- **Qwen3-VL-30B-A3B images**, checked against Hugging Face on the CPU. Its CUDA paged-experts path is not yet
  validated.
- **EmbeddingGemma 2 takes images and audio** at `/v1/embeddings`, and runs on the GPU on a Mac. **Qwen3.5+ images from a
  GGUF `mmproj`** (`--vision mmproj.gguf`).

## WebGPU

- **A long prompt reaches its first token sooner**: a 4-bit model prefills in one batched pass with the same logits,
  about 3 times faster on an M1 Pro and 7 times on an RTX 2070 SUPER for a 1,024-token prompt (read in process).
- Gemma 4 E2B and E4B decode on the GPU, and several vision towers can run there (opt-in, `--vision-device gpu`).

## Using it from Go

- **`server.NewHandler` and `server.Transport`** (Experimental) serve the HTTP API from inside your program, with no
  port or daemon; any client that takes an `*http.Client` talks to a local model in process.
- `Model.Close` is safe during a generation, `Tokenizer.NewStream` prints tokens without losing spaces, and
  `Options.Quant` `"bf16"` / `"f16"` holds a 16-bit checkpoint at half f32's memory, bit-identical to f32 on the CPU.
- aikit v1.70.1 in all five modules.

## Getting it

Binaries for six platforms are attached to this release with their checksums, and listed on
[goinfer.dev/download](https://goinfer.dev/download/).

```bash
go install github.com/townsendmerino/goinfer/cmd/serve@v0.23.0
```

goinfer is still before 1.0. The model math and quantization are checked against Hugging Face's own implementation
and are what stays stable; [docs/api-tiers.md](https://github.com/townsendmerino/goinfer/blob/v0.23.0/docs/api-tiers.md)
says which parts of the API v1.0 will commit to. Until then, any of it may still change.
