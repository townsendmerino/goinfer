# goinfer v0.23.0 — coding agents against a local model, and speech to text

> **DRAFT, 2026-10-15. Not released, not tagged.** Release commit `695ce16c`. Every figure below is from `CHANGELOG.md`'s
> `[Unreleased]` section or a graded record. The release plan and the owner override for the two release-night reds:
> [v0.23.0-checklist.md](v0.23.0-checklist.md). This header is not part of the published notes.

goinfer runs open-weight language models inside a Go program, with no cgo, and also ships as a server and as
single-file binaries.

This release is mostly about one job: **pointing a coding agent — Claude Code, Codex or opencode — at a model running on
your own machine, and having it work.** Until now that mostly didn't. The agent's first request alone is about 20,000
tokens. On an 8 GB NVIDIA card goinfer took four and a half minutes to answer it. Codex lost its warm prompt on every turn.
Claude Code's subagents asked for models the server didn't have. v0.23.0 fixes those, and adds a command that sets each
agent up for you. It also brings speech to text and faster image turns. **One fix concerns sampled output on CUDA, and if
you serve Gemma 4, Command-R or Granite to several users at once, you should read it.**

## Point a coding agent at it

Start a server, then let goinfer write the agent's configuration:

```bash
goinfer-serve --model ~/models/qwen3-4b &
goinfer-serve connect claude-code      # or: connect codex, connect opencode
```

`connect` asks the running server what context window it really holds, and writes the matching settings. It tells you
whether the agent's first request will fit. With `-write` it patches the agent's own config file, and `-undo` puts it back.
For Claude Code it does three more things:
- **Subagents get the served model.** It fills every model setting Claude Code reads with the served model, so a subagent
  that asks for `sonnet` doesn't get a 404.
- **The output cap fits your window.** If the window is too small for Claude Code to work without compacting after every
  file it reads, it says so and names the `-ctx` that fixes it.
- **Conversations share their prompt.** It turns off a per-conversation header that otherwise stops any two of Claude Code's
  conversations sharing more than their first 22 tokens.

`connect` has been checked by its tests. It has not yet been run end to end with each agent on a file it wrote, so tell us
if one misreads it.

What changed underneath:
- **Long first requests are fast on CUDA.** A prompt past about 12,000 tokens used to fall back to processing one token at a
  time. It is now prefilled in batches. Claude Code's 17,869-token first request reaches its first token in **25 seconds
  instead of 272** on an RTX 2070 SUPER. Shorter prompts give exactly the same results as before.
- **Codex keeps its prompt warm.** `/v1/responses` now returns a thinking model's reasoning to Codex and accepts it back,
  and a model with sliding-window layers on CUDA keeps enough of its recent history to reuse. In two-hour runs of Codex
  against Mellum2.1 on one 8 GB card, the share of requests that re-read the whole prompt fell from 66% to 23%. A follow-up
  turn now starts in under a second, where the cold first turn takes about a minute.
- **Fewer ways for a turn to go wrong:**
  - Claude Code 2.1.268 works against `/v1/messages` again; it now sends a system message mid-conversation, which the
    route refused.
  - Codex replies are no longer cut at 512 tokens, and no answer carries a stray `</think>`.
  - A tool call that a thinking model wrote inside its reasoning is no longer lost.
  - An empty answer says why it is empty.
  - Several system messages are all kept, so Codex no longer loses its instructions.
  - A request with a single tool no longer forces every reply into that tool.
  - `serve -lenient-tool-calls` (off by default) reads one fenced JSON call at the end of a reply as a tool call. Use it
    only with a client that asks before it acts: a reply that merely shows an example call looks the same.

A small model can still struggle with an agent's tasks, and that is down to the model, not the server. In our runs on an
8 GB card, opencode with Mellum2.1 completed most tasks, Codex with the same model was hit-and-miss, and Claude Code
finished few tasks with either Mellum2.1 or Qwen3-4B.

## A fix to know about: concurrent sampled output on CUDA

**Who was affected:** anyone serving a dense Gemma 4, Command-R or Granite under `--backend cuda` to two or more
conversations at once with a temperature above zero. More generally, any model with a final-logit softcap or a logit
scale. **Since** v0.20.0: v0.20.0, v0.21.0 and v0.22.0 all have it.

In that case each sampled token came from logits with the softcap or the logit scale applied twice. On Gemma 4 that
squeezed the logits toward the cap. On Command-R, whose logit scale is 0.0625, it made sampling 16 times hotter than asked.
Greedy decoding, and a single conversation on its own, were not affected. Each transform is now applied once, and a
conversation's output is the same whether it decodes alone or beside others.

## Before you upgrade

Most of these change defaults rather than break anything, but each can change what you see:

- **Rebuild old `.giw` files.** Weight files are format v16, and only v16 is read. A `.giw` from an earlier release,
  including one embedded in your own binary, must be rebuilt with `cmd/prequant`. Sidecars that `goinfer-serve` builds
  rebuild themselves.
- **CUDA's KV cache is half precision by default** for llama, mistral, qwen2, qwen3 and phi3. The same card holds about
  twice the context. Outputs can differ slightly from the full-precision cache; `--kv f32` keeps it exact.
- **CUDA keeps only the window for sliding-window layers** (`--windowed-kv`, now on by default), so such models fit a
  longer context. `--windowed-kv=false` turns it off.
- **On a Mac, the default context grows** from 4,096 toward 16,384 positions when memory allows, so a coding agent's
  first request fits. That reserves more memory up front: 0.9 GB on a 1.5B model, 1.8 GB on a 7B. `-ctx` or `--fit=off`
  keeps the old size.
- **The context-overflow error has new wording**, chosen so each coding agent reacts correctly: it compacts its
  conversation, or stops when even the system prompt doesn't fit. The `context_length_exceeded` code is unchanged, but
  a client that matched the old message text needs updating.
- **Some image replies can differ from v0.22.0's even at temperature 0.** Gemma 4 images are resized the way the
  reference processor does it. A Qwen3.5-family image turn on the CPU adds up a sum in a different order.

## Speech, images and embeddings

- **Speech to text.** `POST /v1/audio/transcriptions` runs a pure-Go Whisper. `input_audio` works with Qwen3-ASR and Voxtral
  Mini. On CUDA the audio encoder runs on the GPU.
- **Image turns on Qwen3.5 are much faster.** On a 0.8B model, a 1024×640 image went from 37.5 s to 3.6 s to the first
  token on CUDA, and from 38 s to 7.7 s on the CPU. These were single exploratory runs.
- **Qwen3-VL-30B-A3B takes images**, checked against the Hugging Face reference on the CPU. Its CUDA path for paged experts
  is not validated yet.
- **Qwen3.5 images from a GGUF projector** (`--vision mmproj.gguf`).
- **EmbeddingGemma 2 takes images and audio** at `/v1/embeddings`, and runs on the GPU on a Mac.

## Security

These fixes come from a security audit of the server. None has a known use against a default `serve`:
- **DNS rebinding.** A web page could point its own hostname at `127.0.0.1` and read a local server's replies. A loopback
  server now refuses a request whose `Host` isn't its own.
- **Turn forgery through tools.** With tools declared, text typed into a message, tool result or system prompt could end a
  turn early. It is now treated as plain text.
- **One bad request crashing the server.** A panic inside one job or batch line now fails only that item.
- **The web UI.** It has a strict content policy, its HTML preview no longer runs scripts, and Copy drops hidden
  characters.

## Also in this release

- **Apple silicon:** GLM-OCR, Command-R, Command-R7B and Aya now run on the GPU, and GLM-OCR's vision tower too. An invoice
  takes 23 s instead of 70 s on an M1 Pro. A long prompt now prefills in blocks, so a 21,000-token request is no longer refused on a 16 GB Mac whose context holds it.
- **WebGPU:** a long prompt on a 4-bit model reaches its first token about 3× sooner on an M1 Pro and 7× sooner on an RTX
  2070 SUPER, with identical results. Gemma 4 E2B and E4B decode on the GPU.
- **From Go:**
  - `server.NewHandler` and `server.Transport` (Experimental) serve the whole HTTP API inside your program, with no port
    and no daemon.
  - `Model.Close` is safe during a generation.
  - `Tokenizer.NewStream` prints tokens without losing spaces.
  - `Options.Quant: "bf16"` holds a 16-bit checkpoint in half the memory.
- **Under the hood:** goinfer now uses aikit v1.70.1 in all five modules.

The full list is in [CHANGELOG.md](https://github.com/townsendmerino/goinfer/blob/v0.23.0/CHANGELOG.md).

## Getting it

Binaries for six platforms are attached to this release, with their checksums. They are also listed on
[goinfer.dev/download](https://goinfer.dev/download/).

```bash
go install github.com/townsendmerino/goinfer/cmd/serve@v0.23.0
```

goinfer is still before 1.0. The model math and quantization are checked against Hugging Face's own implementation, and
those are what stay stable. [docs/api-tiers.md](https://github.com/townsendmerino/goinfer/blob/v0.23.0/docs/api-tiers.md)
says which parts of the API v1.0 will commit to. Until then, any of it may still change.
