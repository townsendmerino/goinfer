# goinfer v0.9.0

A pure-Go (no-cgo) LLM runtime. This release lands **two cgo-free GPU decode backends** —
**CUDA** (Linux/NVIDIA) and **Metal** (macOS/Apple Silicon) — as opt-in, fallback-safe
paths, and adds **speculative decoding**, **batched prefill**, and **long-context decode**
on top. Everything on the GPU is held to a **bit-identity contract**: each GPU path is
byte-reproducible against the CPU reference, and there are gates that fail if that ever
drifts. Forward-pass numerics stay parity-gated against HuggingFace.

> **Both GPU backends are `CGO_ENABLED=0`** (pure Go via purego/dlopen), behind build tags
> (`-tags cuda` / `-tags metal`) + `--backend`, with graceful CPU fallback. The default
> pure-Go build is unchanged — you opt in, and if the device or a feature isn't there, it
> declines to CPU instead of running something wrong.

## Highlights

### 🟩 A cgo-free CUDA backend
Resident decode + prefill with **no cgo** — gocudrv (dlopen `libcuda`) + NVRTC (PTX JIT).
Measured on an RTX 2070 SUPER (real q4_K_M): **1.5B 218.6 tok/s, 0.5B 507.5 tok/s**. The
arc: coalesced W4A8 GEMV + ILP unroll, a launch diet (18→13 dispatches/layer), f16 group
scales, on-device greedy argmax, and rmsnorm-into-GEMV super-kernels (+21.3% on 0.5B). The
forward is guarded by a mutation-proven parity gate that hard-fails on any real divergence.

### 🍎 A cgo-free Metal backend
Resident decode + prefill via purego-objc (dlopen Metal.framework, MSL 3.1 compiled at
runtime) — no Xcode, no toolchain, first `CGO_ENABLED=0` GPU path on the platform. Decode
went **~20 → 73.6 tok/s** (the practical batch-1 ceiling on an M1 without DP4A). Against
Ollama-Metal v0.32.5, server-to-server: **0.96×** on 0.5B, **0.74×** on 1.5B. Metal's
value here is the cgo-free / no-Xcode property and correctness parity — not a raw-speed
multiple, and we don't quote one.

### ⚡ Speculative decoding (opt-in, lossless)
- **CPU n-gram** (`--spec ngram`) — a free prompt-lookup drafter; wins on copy-heavy traffic
  (code edits / RAG / agent loops): ~1.55–1.59× on 0.5B, greedy bit-exact vs sequential.
- **Grammar-fused** — for constrained / tool requests, the grammar's forced bytes are drafted
  for free (lossless).
- **Resident CUDA (D1)** — batched verify, **1.23×@128 / 1.86×@512 / 1.18×@2048**,
  byte-identical to plain greedy.

Recurrent families (Mamba-2 SSM, Gated DeltaNet) are guarded out of speculation and fall
back to plain decode.

### 🏎️ Batched prefill + long-context decode (CUDA), bit-identical
- **Batched prefill** ingests the whole prompt in one pass — TTFT up to **6.17× faster**
  (2048-token prompt 13.1 s → 2.1 s), default-on, byte-identical to decode.
- **Split-KV attention** — 2048-token decode **133 → 160 tok/s**, and **1.61× over baseline**
  with attention coalescing. It splits the independent key/value axes without reordering the
  softmax sum, so it stays bit-exact (flash attention's online rescale is not, so we don't
  use it on the default path).

### 🧩 More model families, and no silent-wrong output
Resident on **both** backends now: Qwen2/Llama, **Qwen3**, **Gemma-3**, and **MoE** (Mixtral
/ Qwen2-MoE / Qwen3-MoE / GLM-4.5/4.6). Metal adds **Mistral** and **Phi-3**. **Cohere /
Command-R (v1 + v2)** land CPU-correct (cosine 1.0 vs HF). Admission is one shared feature
taxonomy: a backend that can't fully run a family **declines to CPU** rather than dropping a
feature silently — a whole class of quiet wrong-output bugs is now structurally impossible.

### 📦 A 26B MoE, fully GPU-resident on an 8 GB card
Gemma-4 **26B-A4B** decodes **fully GPU-resident at 16.98 tok/s** on an 8 GB RTX 2070 SUPER
by streaming routed experts host→VRAM into an LRU cache (81.6% hit at 30% residency; it
auto-caps to free VRAM and never OOMs). The wall is **capacity, not kernels** — a model that
fits would decode *faster* than a dense 7B.

### 🔒 A bit-identity contract you can see fail
- The **Metal snapshot golden** stores a machine+OS-pinned hash of Metal's own logits past
  the reduction widths — the absolute reference that catches changes the "does paged == non-paged?"
  and "GPU ≈ CPU?" gates are blind to (fused rewrites, accumulation-order moves, width sweeps).
- The CUDA batched/decode paths carry an **FMA lint** that fails the build on any bare float
  MAC — after a real ~1-ULP contraction bug caused 84% token-stream divergence on real weights
  (invisible on uniform fixtures) and was fixed with explicit round-to-nearest FMA.

## Notes
- **Peer numbers re-anchored to current Ollama v0.32.5.** All goinfer-vs-Ollama comparisons in
  `docs/benchmarks.md` were re-measured against the current peer (the old figures were 12–18
  months stale). Read the absolute tok/s and the cgo-free property, not a peer multiple — the
  ratio is size-, depth-, and platform-dependent. The prior "peers can't load the 26B" claim
  (§B4) was **false and is retracted**: Ollama v0.32.5 runs it via CPU offload, faster than us;
  our distinct property is running it *fully GPU-resident*.
- **Pre-1.0.** A family is "supported" only with both a CI-runnable T1 golden and a current T3
  parity record; families short of that ship **experimental**. The full per-family backfill is
  the 1.0 gate.
- **Test census (this release):** on the Mac, pure-Go **415 pass / 0 fail / 167 skip** and
  Metal **59 pass / 0 fail / 30 skip** — every skip is asset/GPU/heavy-model-gated, none are
  silent failures (`scripts/skip_census.py`). CUDA runs on the Linux box.
- **Upgrade heads-up:** the GPU backends are opt-in; nothing changes unless you build with a
  tag and pass `--backend`.
