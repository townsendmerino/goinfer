## The tag, two steps (RELEASING.md, "The two-step tag")

On `main`, clean, after `git pull`, as townsendmerino (`gh auth switch --user townsendmerino`).

**Step 1: the root, pushed first.**
```
# CHANGELOG: [Unreleased] -> [v0.23.0] - <date>, with the Highlights draft rewritten as the tagger's
go mod tidy
git commit -am "release: v0.23.0 (coding agents against a local model, speech to text)"
git tag v0.23.0
git push origin main v0.23.0
```
If the CHANGELOG move landed earlier and `go mod tidy` changes nothing, there is nothing to commit: tag HEAD and push.

**Step 2: the submodules against the published root.** `gpu`, `cuda` and `metal` in one commit:
```
cd gpu   && GOWORK=off go get github.com/townsendmerino/goinfer@v0.23.0 && GOWORK=off go mod tidy && GOWORK=off go build -tags gpu ./...   && cd ..
cd cuda  && GOWORK=off go get github.com/townsendmerino/goinfer@v0.23.0 && GOWORK=off go mod tidy && GOWORK=off go build -tags cuda ./...  && cd ..
cd metal && GOWORK=off go get github.com/townsendmerino/goinfer@v0.23.0 && GOWORK=off go mod tidy && GOWORK=off go build -tags metal ./... && cd ..
git commit -am "release: gpu/cuda/metal require goinfer v0.23.0"
git tag cuda/v0.23.0 ; git tag gpu/v0.23.0 ; git tag metal/v0.23.0
git push origin main cuda/v0.23.0 gpu/v0.23.0 metal/v0.23.0
```
`metal` on Linux prints "matched no packages" (its files are darwin-only): expected there, and its real build gate is a
Mac or CI. Then `demo/agent`, in its own commit, after `gpu/v0.23.0` is published (it requires `goinfer/gpu`):
```
cd demo/agent && GOWORK=off go get github.com/townsendmerino/goinfer@v0.23.0 && GOWORK=off go get github.com/townsendmerino/goinfer/gpu@v0.23.0 && GOWORK=off go mod tidy && GOWORK=off go build ./... && cd ../..
git commit -am "release: demo/agent requires goinfer + goinfer/gpu v0.23.0"
git tag demo/agent/v0.23.0
git push origin main demo/agent/v0.23.0
```
