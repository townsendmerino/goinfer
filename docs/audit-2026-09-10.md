**Headline.** The numerics of the week's ports are mostly sound: the six G6 feature ports on
WebGPU match their CUDA/Metal kernels term for term (attention sink in all seven kernels, GeGLU
clamp, sandwich placement, `(1+w)`, softcap), the Gemma 4 batched bidirectional attention is
provably inert on text, the m-RoPE resident seed reproduces the CPU positions, the CUDA image-block
window matches `kvcache.go`, and every `.cu`/`.ptx` pair in the tree is consistent today. The
serious defects are concentrated in four places:

1. **Compute-time LoRA on the resident path (G3) is wrong in two independent ways on CUDA and
   Metal.** The batched prefill has no LoRA dispatch and nothing declines it, so every adapter
   prompt of ≥8 tokens (CUDA) or ≥512 (Metal, since the default flip one day later) is encoded with
   the *base* weights and decoded with the adapter (C-01); and resident prefix reuse records token
   ids only, so a base turn and an adapter turn that share a system prompt reuse each other's K/V in
   both directions (C-02). The three G3 parity gates drive per-token `Forward` and never the path
   serve takes (G-06). Metal additionally commits a command buffer pre-encoded under the previous
   adapter state on the first token after every `SetAdapter` (C-07).
2. **Bailing Hybrid's KDA state is in none of the lifecycle predicates** — `Recurrent:false` in
   the table, absent from `hasRecurrentState` and `resetRecurrent` — so session eviction leaks
   conversation A's recurrence into B, identical resends report `exact`, and n-gram speculation is
   admitted with a rollback that touches only `mlaLatent` (C-03). The test written after C-02 to
   prevent exactly this compares two hand-written lists and passes when both omit the family (G-05).
3. **Three silently-wrong resident kernels in the new admissions:** Command-R on CUDA runs
   RMSNorm at the final norm and lets the default-ON batched prefill re-normalise with a buffer
   that was never allocated (C-04); gpt-oss int4 on WebGPU dispatches the int8 down-projection
   kernel over the W4A8 expert stack (C-06); and int8-KV + m-RoPE decode on WebGPU writes each new
   K scale at the *rope* position (C-09). Plus one loader: dense Granite GGUF is read un-permuted
   (C-05).
4. **The release evidence chain has three holes it had closed a week ago.** The parity manifest's
   `aikit_version` is two releases stale again, three days after the gate for that was "re-armed"
   (G-01); `olmo_hybrid` is `validated` with a `deps_hash` over zero files (G-02); and the seven
   v0.17.0 families are gated by tests CI skips, the sweep files as FIRST-RUN, and a ledger not
   promoted since 09-02 — `TestOlmo3_forwardParity` was red on the box across five commits with the
   family `validated` throughout (G-03, G-04).

Two more are worth calling out because they are user-facing and cheap: `--fit=off`, the spelling
the server itself prints, is rejected by Go's flag parser (M-14); and the README's "bigger than
RAM" command (`-weight-cache 6GiB`) does not parse, and the README smoke gate checks flag names,
not values (M-47, G-13f).

On performance: `fit` reads free RAM *after* loading the model it is planning for (M-19) and
`-measure` loads a second copy while the first is resident (M-20); every `Model.Generate` on a
resident model allocates a full host KV cache it never touches (P-01); and the field has moved on
speculation for recurrent hybrids — llama.cpp shipped per-slot recurrent-state rollback on
2026-09-01 with numbers showing the naive whole-state approach loses and the narrow conv-window
snapshot wins, which is the mechanism goinfer measured at <1% of a round and left unbuilt (L-01).

## §0 — Cross-cutting themes

1. **The fourth kind was missed at four sites again.** `decoder/kvcache.go:451` says "The fourth kind will
   be added here, once, or it will be missed at four sites again." e6b31cc added the field and the
   `NewCache` arm and nothing else (C-03). The chokepoint exists; nothing forces a new state kind
   through it. A reflection-based test over `KVCache`'s `[]*xxxState` fields (G-05's fix) is the
   mechanical version of that sentence.
2. **A premise in a comment is not a predicate.** Metal's batched prefill says "paging is never
   used by prefill" (`metal/moe.go:701`) and admits paged models (C-08); G3 was designed while Metal
   prefill was opt-in and the flip a day later did not re-check it (C-01); `residentPath` in serve
   still reads `lm.adapter == ""` after G3 removed the routing rule it encoded (M-01); `Generation.
   Budget`'s doc says VL paths don't clamp after three VL paths grew a clamp (M-02).
3. **A gate that supplies its own calling convention.** The LoRA parity gates call `Forward`
   (G-06); the gpt-oss WebGPU gate uses a fixture whose biases dominate every weight term (G-07);
   the Metal LoRA gate binds before the executor has pre-encoded anything (G-06c); the §3.2 gate
   drops missing cells from its decision set and prints the full header (G-08). CLAUDE.md's rule
   ("test through its caller") was cited by three reviewers independently.
4. **Fix reached one sibling.** LoRA dimension checks on the merge path, not compute-time (M-05);
   router f32 on gpt-oss/qwen35 GGUF loaders, not the five generic ones (M-27); `BudgetClamped` in
   `generateInto`, not the seven VL clamp sites (M-02); M-12's temp+rename on the GGUF branch, not
   the dir branch (M-33); V-07's gate-listing test for Metal, not WebGPU (G-10); G10's requant label
   for `int8int8`, not `int8`/`int4mix`, and in serve, not chat (M-25); `--exact-prefill` for CPU
   and Metal, not CUDA (M-48); the C-10 decline printed by serve, not the REPL (M-41).
5. **Default-ON flips shipped ahead of their consumers.** Metal fast prefill and fused attention
   went default-ON on 09-09/09-10 while `HiddenLast` (M-10), spec verify at M≥16 (M-11), resident
   prefix reuse on GPU (M-55) and the LoRA path (C-01) still assume prefill == decode; the CUDA ctx
   default moved 4096→8192 with no CHANGELOG line and a `-ctx` help that says it did not (M-52);
   `[Unreleased]` carries one entry for 95 commits (M-53).
6. **Guards keyed on the wrong quantity.** The fit guard prices KV at full width on every layer
   (3–7× over on hybrids and rings, M-28) and f32-resident mixers at the int4 rate (M-29); `Plan`
   fits with zero headroom and the build then demands 384 MiB more (M-12); `fit` measures free RAM
   after consuming it (M-19); the memory-fit guard on Metal double-counts mmap-aliased int4 (M-24).
7. **Evidence that cannot go stale.** A hand-typed `aikit_version` (G-01), an empty dependency set
   (G-02), an unbounded FIRST-RUN bucket (G-03), a `-update` with no refusal (G-04), a hash over a
   test body whose assertion lives in a helper (N-50).
