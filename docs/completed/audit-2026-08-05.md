## §1 — Release blockers

Fix before the tag. Everything else can wait.

### 1a. The tagged submodules will not build for anyone

**B-01 | CRITICAL | `metal/go.mod:5`** — requires the root module at the synthetic
placeholder `v0.0.0-00010101000000-000000000000`, tolerated only by the sibling `replace`
on line 18. **Go ignores `replace` in non-main modules.**
*Failure:* `go get github.com/townsendmerino/goinfer/metal@vX` fails with
`invalid version: unknown revision 00010101000000-000000000000`. Tagging publishes that
state permanently.
*Fix:* require a real published root version before tagging `metal`.

**B-02 | CRITICAL | `metal/go.mod`** — `metal` imports `aikit/linalg` (backend.go:14,
model.go:16) and `aikit/mmap` (gemma4_moe.go:11), but never requires module
`github.com/townsendmerino/aikit`. It requires only `aikit/gpu`, which is a *different*
module.
*Failure:* `cd metal && go build ./...` on a clean clone fails —
`no required module provides package .../aikit/linalg`. The gitignored `go.work` is the only
reason this has never been seen; CI comments already document the workaround.
*Fix:* `go mod tidy` in `metal/` with `replace` temporarily removed, and add a standalone
(`GOWORK=off`) build to CI.

**B-03 | CRITICAL | `gpu/go.sum`** — carries `x/sys v0.45.0 h1:` and `x/text v0.37.0 h1:`
but only the `/go.mod` hashes for the versions `gpu/go.mod` actually selects (`v0.47.0`,
`v0.40.0`). The module-zip hashes for the selected versions are absent. *(Verified by hand.)*
*Failure:* `cd gpu && go build -tags gpu ./...` on a clean clone fails with
`missing go.sum entry for module golang.org/x/sys@v0.47.0`. CI is green only because the
workspace borrows the root's `go.sum`.
*Fix:* `GOWORK=off go mod tidy` inside `gpu/`; add a standalone build step to the gpu job.

**B-04 | CRITICAL | `demo/agent/go.sum`** — holds only `aikit v1.3.0/v1.9.0`,
`x/sys v0.41.0/v0.45.0`, `x/text v0.37.0` — none of the versions MVS selects once the
`replace ../..` pulls in the root's `aikit v1.16.0`. It is in neither `go.work` nor any CI job.
*Failure:* a committed module in the release tree does not build, and nothing would notice.
*Fix:* `go mod tidy`, add a CI build step — or drop it from the repo.

### 1b. The release would ship code that isn't in the tree

**B-05 | CRITICAL | `go.mod:7` + `go.work`** — `go.work` and `go.work.sum` are gitignored
(`.gitignore:67-68`), so a clean clone has no workspace. The root `go.mod` pins
`goinfer/cuda` and `goinfer/metal` at Aug-2 pseudo-versions
(`v0.0.0-20260802175847-6c995fe3b22e`) that predate the current trees.
*Failure:* on a fresh clone, `go build -tags cuda ./cmd/serve` **succeeds** and silently
links the published Aug-2 snapshot from the proxy — not the reviewed source. The release
binary would ship backends that are not the code in the tag. The developer `go.work` omits
`./cuda` entirely, so even locally `./cmd/serve` never resolves `cuda/` from the tree.
*Fix:* tag `cuda` and `metal`, bump the root requires to those tags, add `./cuda` and
`./demo/agent` to `go.work`, and document that a workspace is mandatory for backend work.

**B-06 | CRITICAL | release ordering** — the four modules form a requirement cycle
(root → gpu/cuda/metal → root); `cuda` and `metal` have never been tagged, `gpu` is pinned at
`v0.8.0`. No single-shot tagging produces a consistent set.
*Fix:* three-step: (1) tag root `v0.9.0`; (2) set `goinfer v0.9.0` in the three submodules,
tidy, tag `gpu/v0.9.0`, `cuda/v0.9.0`, `metal/v0.9.0`; (3) bump the root's submodule requires,
tidy, tag root `v0.9.1`. Write it into `RELEASING.md`.

**B-07 | CRITICAL | dependency skew** — `gpu` requires `aikit v1.11.0` while root and `cuda`
require `v1.16.0`; `metal` requires `aikit/gpu v0.25.2` while root records `v0.25.0 //
indirect` and `cuda` requires `v0.25.0`. *(Verified by hand.)*
*Failure:* MVS hides this inside the workspace, but a standalone consumer of `goinfer/gpu`
gets `aikit v1.11.0` — five minors behind anything CI ever compiled. Any post-1.11 aikit API
used by `gpu` is a consumer-only build break.
*Fix:* align all four modules on `aikit v1.16.0` / `aikit/gpu v0.25.2`, tidy the root last.

### 1c. Exported-API mistakes that are breaking to fix later

**B-08 | CRITICAL | 27 exported test hooks** *(verified by hand)* —
`Model.ResidentForwardForTest`, `ForwardForTest`, `EmbedResidentForTest`, `FinalNormForTest`,
`Gemma4MoERouterForTest`, `Gemma4MoEExpertForTest`, `KVCache.LayerKVForTest`,
`SetGemma4HiddenCaptureForTest`, `SetRouterCaptureForTest`, `RouterMarginForTest`,
`SetMambaCapHook`, `SetSSMForceF32`, `SetSSMQ8CPU`, `gpu.Context.IndexedGEMVForTest`,
`RouteExpertsForTest`, `cuda.CacheStatsForTest`, and others.
*Failure:* all become permanent semver API; removing them later is a breaking change. The
`Set*` ones are unsynchronized process-global state a consumer can flip mid-decode, changing
numerics for every concurrent `Generate`.
*Fix:* move to `export_test.go` (same package, invisible outside) or `internal/testhooks`.

**B-09 | CRITICAL | `decoder/features.go:251`** *(verified by hand)* —
`ResidentBackendFeatures` is an exported, unsynchronized, uncopied package-level map that the
admission gate reads at `BuildResident` time.
*Failure:* any consumer or third-party `init()` can add an entry claiming a feature its
kernels don't implement — precisely the silent-wrong-output failure the registry exists to
prevent. A concurrent `Load` during a write is a fatal map throw.
*Fix:* unexport; expose an accessor returning a copy.

**B-10 | CRITICAL | `metal/model.go:302`** — exported `metal.BuildResident` **panics** on
pipeline-compile failure, non-int4 expert weights and buffer OOM
(`model.go:285,343,398`, `moe.go:271,284`, `gemma4_moe.go:261,271,333`). The `recover()` that
converts these to a clean decline lives only in the *unexported* backend wrapper
(`backend.go:51`).
*Failure:* a caller using the documented exported entry point gets a process-killing panic
where the signature promises an `error`.
*Fix:* move the `defer recover()` into `metal.BuildResident` itself.

**B-11 | CRITICAL | `metal/model.go:83,105,618,633,807,831` + `prefill.go:298`** —
`metal.Resident` exports geometry fields (`H, nL, nH, I, V int`) that its GPU buffers were
sized from, and every method discards errors: `Forward(id, pos) []float32`, `ForwardEmb`,
`PrefillLast`, `ForwardArgmax(id,pos) uint32`, `Close()`.
*Failure:* a caller can mutate `H`/`I`/`V` on a live resident → out-of-bounds dispatches; a
GPU failure returns garbage floats with no signal. `cuda`'s equivalents all return `error`,
as does `decoder.ResidentForward` — the same concept has two contradictory contracts across
sibling modules.
*Fix:* unexport `Resident` (expose only through `decoder.RegisterBackend`, as `gpu` and
`cuda` do), or unexport the fields and add `error` returns.

**B-12 | CRITICAL | teardown naming across three modules** — `gpu` uses `Release()` with no
return (`ResidentMatrix`, `ResidentW8A8`, `ResidentW4A8`, `ResidentStackedW8A8`,
`DeviceBuffer`, `GEMVRunner`, `DecodeRunner`) while `Context.Close()` and
`VisionEncoder.Close()` in the same package use `Close`; `cuda` and `metal` use `Close` with
and without `error` respectively. None implement `io.Closer`.
*Failure:* four spellings of "free this GPU resource" across three modules; callers cannot
write generic cleanup. Renaming after the tag breaks all three.
*Fix:* standardize on `Close() error` before the tag.

**B-13 | CRITICAL | exported methods returning unexported types** — `EagleHead.NewState()
*eagleState` (decoder/eagle.go:184), `EagleHead.Prefill(...) *eagleState` (:400),
`metal.Resident.PagedProfile() pagedProfile` (metal/gemma4_moe.go:35).
*Failure:* undocumentable in godoc and unusable in any consumer signature — a caller cannot
store the value in a struct field or pass it to a helper. Fixing changes exported signatures.
*Fix:* export the types as opaque structs, or unexport the methods.

**B-14 | CRITICAL | `cmd/serve/main.go:242`** — the server has **no authentication of any
kind** and `-addr` defaults to `":8080"` (all interfaces). No handler inspects
`Authorization`, `Bearer` or `x-api-key`. With `--allow-admin`, `POST /admin/models/load`
takes an arbitrary filesystem `path` and (with `--stream-weights`) writes a sidecar `.giw`
next to it.
*Failure:* anyone who can reach the host gets unmetered inference and, with admin enabled,
arbitrary path-driven load + write. This default becomes a compatibility commitment at the tag.
*Fix:* default to `127.0.0.1:8080` (llama.cpp's default) and add an optional shared-secret
check that `--allow-admin` requires.

## §2 — Critical: silently wrong output or state corruption

**C-01 | `decoder/kvcache.go:420` + `gpu/residency.go:878` — recurrent state is never reset.**
Two facets of one gap, found independently by two reviewers. `KVCache.TruncateTo` rewinds
`keys/vals`, rings and `mlaLatent` but never touches `c.delta` (Gated DeltaNet) or `c.mamba`
(Mamba-2); and the resident `residentDecoder.Reset()` — the only thing that re-zeroes the
GPU-side `{win, ssm}` state — **is called by nothing in the repo** (`grep` finds only
`constrain`, `Session.Reset`, and demos).
*Failure:* `serve` with `-kv-sessions 4` on granite-4.0-h / nemotron-h / qwen3_5_moe:
conversation A fills the slots, B arrives, `sessionLRU.fresh()` → `Reset()` →
`TruncateTo(0)` drops the KV but leaves A's SSM state; `mamba2Step` mutates it in place, so
B's first token decodes from A's state. Silently wrong output **and a cross-conversation
state leak**. On the resident path, two successive `Generate` calls on one `*Model` have the
same problem with no session involved. Note `Session.Snapshot` *does* refuse recurrent caches
— only the reset/rewind path is unguarded.
*Fix:* add `KVCache.resetRecurrent()` called from `TruncateTo(0)`; make `TruncateTo` return
`exact=false` when recurrent state is present so `rewindForReuse` cold-prefills; re-zero
`mambaWin`/`mambaSSM` inside `Forward` when `pos == 0` rather than relying on an external call.

**→ fixed (`33c5479`, before the v0.9.0 tag) — verified against the tree 2026-08-05.** All three facets landed: `KVCache.resetRecurrent()` called from `TruncateTo(0)`, `exact=false` on any rewind with recurrent state, and the resident path re-zeroing `{win,ssm}` at `pos == 0` in both `Forward` and `ForwardN`. Test: `TestTruncateTo_resetsRecurrent`. No further change.

**C-02 | `decoder/speculative.go:59-82` — `GenerateSpeculative` is the one speculative entry

## §8 — Cross-cutting themes

1. **Recurrent state has no lifecycle.** Mamba-2 and DeltaNet state is reset nowhere, rolled
   back nowhere, and snapshotted nowhere (the snapshot path at least *refuses*). C-01, C-02,
   C-17 are three symptoms of one missing abstraction. The KV cache got a full lifecycle;
   recurrent state got none.

2. **The fourth speculative entry point.** `GenerateSpeculative` is missing every guard its
   three siblings have — `specRollbackSafe`, the `resBusy` claim, the arch allow-list. It looks
   like the original, and the guards were added to the newer paths without back-porting.

3. **Errors are dropped at exactly the GPU boundary.** `cuda` discards every upload error and
   never assigns `setupErr`; `metal` never reads a command-buffer status; `gpu`'s two
   `DecodeToken*` entry points panic where their sibling returns an error. Each was independently
   noted in code comments as *handled*. This is the single most dangerous pattern in the
   codebase, because it converts a resource failure into a numerics result.

4. **Dimension guards are per-kernel folklore.** `gemv_w4a8_sa_bk` has the row guard, its six
   siblings don't. `MatmulW8A8GemmRow` bounds M, `DecodeTokenFusedBatched` doesn't. `MLAAttn`
   bounds head_dim, the three attention kernels don't. CUDA declines `K%32 != 0`, WebGPU pads,
   Metal silently corrupts. The same invariant is enforced in some places and assumed in others.

5. **The workspace hides the module graph.** `go.work` is gitignored, so every standalone-build
   defect (B-01 … B-04, B-07) is invisible to both developers and CI. This is a gate-that-cannot-
   fail at the build-system layer, and it is the reason four release blockers survived to a tag.

6. **Test hooks became public API.** 27 `*ForTest` identifiers plus four global `Set*` mutators
   are exported from a library about to commit to semver.
