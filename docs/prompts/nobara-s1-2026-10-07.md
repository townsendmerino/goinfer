## 2. S1.0's `v_norm` fix on CUDA and WebGPU

HF applies the scale-less `v_norm` on every Gemma 4 layer that owns its K/V. The CPU does; Metal does since S1.0
(`c12e2778`). CUDA and WebGPU apply it only on K=V layers, so every sliding layer of the 26B/31B running resident there
misses it. (The dense layer scalar, S1.0's other fix, is already right on both.)

- **CUDA:** `cuda/resident.go` gates the decode's v_norm on `Ly.kEqV` (around the "scale-less v_norm(raw k in vB)"
  comment), and `r.vNormUnit` is allocated only when some layer is K=V (`cuda/backend.go`, near `L.kEqV =
  m.VFromKResident(l)`). The batched prefill (`cuda/prefill.go`) has its own `Ly.kEqV` branches and a refusal when the
  unit weight is missing. All three need the Gemma 4 case: every K/V-owning layer.
- **WebGPU:** `gpu/decoderunner.go` runs `vNorm(k, v, …)` only for K=V. A non-K=V layer needs it on the v_proj output
  (src = dst = v). Check whether the `vNorm` shader can bind one buffer as both input and output; if not, a copy or an
  in-place variant is needed.
- **The S1.0 rule applies unchanged:** read the Gemma 4 resident-vs-CPU parity tests (`cuda/gemma4_*`,
  `gpu/gemma4_twogeom_test.go`, the scaled-dense and MoE ones) before and after, each with its own metrics; PASS when no
  metric moves the wrong way and re-dropping the fix through a test seam reproduces the before-fix numbers. Then tighten
  each bar in a separate recorded amendment, between its before and after readings, as S1.0 did on Metal.
- Run the tagged vets (`go vet -tags 'cuda goinfer_testhooks' ./cuda/`, `-tags 'gpu goinfer_testhooks' ./gpu/`) and
  CI's staticcheck before committing.
