# goinfer code audit — 2026-09-02

**Tree:** `cfec302` (2026-09-01, v0.15.0-184), plus the one docs-only commit after it. Every
`path:line` below is keyed to that commit; `scripts/queue_citation_lint.py --update` needs one run
before this file is pushed, since the pre-push hook indexes every live `path:line`.

**Scope:** the whole repo at equal depth — all five modules (root, `gpu/`, `cuda/`, `metal/`,
`demo/agent/`), 897 Go files / ~170k lines (~70k non-test), the 15 `.cu` sources, the MSL and WGSL
shaders embedded as Go strings, `scripts/`, the workflows, and the docs that make claims about the
code. Same critical bar as the 2026-08-05 audit: silently wrong output, state corruption, a gate that
passes when it should fail, a reachable panic/leak/race, and anything that will be breaking to fix
after a tag.

**Method:** eleven independent reviewers, one per subsystem (decoder forward core; hybrid families +
cache lifecycle; loaders + paging; sampling + speculation; the HTTP surface; constrain + tokenizer +
multimodal + demos; CUDA; Metal; WebGPU; engineering/CI/release), plus a sourced landscape sweep, each
given `CLAUDE.md`, the prior audit's dispositions and the four queues so that deliberate design
(bit-identity, pinned reduction widths, frozen PTX, per-machine fixtures, "measure, don't assume") was
not misread as defect. Every finding was confirmed by reading the lines it cites; the Critical and
gate items were then re-verified by hand from the source. Findings reached independently by two or
three reviewers are marked, and count once.

**Limitations:** static only — the review sandbox has go1.24.7 against a `go 1.27.0` requirement, no
module proxy and no GPU, so nothing was built, run, fuzzed or raced. The audit copy also excluded
`*.safetensors`, `*_golden.json` and `docs/assets/`, which produced two false claims (that
`testdata/lfm2-tiny` and the tokenizer goldens were uncommitted); both were checked against the Mac
and corrected before this was written. aikit internals were not readable; anything that depends on
them is marked aikit-side.

**Relationship to the 2026-08-05 audit:** nothing closed there was found reopened wholesale. What
recurs is the *shape* of three of its themes — recurrent state with no lifecycle (now for a fourth
family), errors dropped at the GPU boundary (a handful of new sites), and gates that cannot fail (six
new instances, four of them in the Metal release ritual). The tree grew ~60k lines and ~400 commits
in the four weeks between; the concentration of defects is in that new code, and in the places where
a fix landed on one backend or one route and not its siblings.

**Headline.** The numerics of the fresh default-ON work are sound: P18 expert-major MoE prefill is
bit-identical by construction, the P19 fused kernel and the A3 head fan-out are correct and their
gates can fail, and the recurrent lifecycle fixes from August still hold for Mamba-2 and DeltaNet.
The serious defects are concentrated in four places:

1. **LFM2 (2026-08-31) fell through seven hand-maintained family lists** — `canBatchN`, the
   `TruncateTo`/`reconcile` recurrent guards, `specRollbackSafe`, `Snapshot`, the `.giw` writer, the
   capture allow-lists and the layer pager. The first of those crashes the server on any prompt of
   two or more tokens (C-01); the rest are the August C-01/C-05/R3 defects reproduced for a new state
   kind (C-02, C-03). The family's parity gate is green because it drives the forward one token at a
   time.
2. **Two new batched-prefill defects on warm sessions**: the attention tile is recomputed per layer
   from that layer's key count while the worker pool was sized from the global one, which panics on a
   sliding-window model after the ring wraps (C-04); and a cancelled sweep on a wrapped ring leaves
   rows the next turn reads as history, because `reconcile` discards `TruncateTo`'s `exact` (C-05).
3. **The Metal release ritual vouches for tests it never runs**: `gate gpu`'s lifecycle and prefill
   groups print PASS with zero tests executed (G-01), no Metal cell passes `-tags goinfer_testhooks`
   so none of the 64 resident-parity gates are ever compiled by the ritual or by CI (G-02), and the
   "cgo-free" check builds the root binary (G-03). The paged gpt-oss path those gates would cover
   applies expert 0's biases to every expert (C-09).
4. **The serving surface has three unbounded request dimensions and one data race** — the
   decoder-as-embedder has no token bound (C-07), `top_logprobs` is unclamped (C-08), a client that
   stops reading pins the decode worker forever (M-17), and the heartbeat goroutine writes the same
   `ResponseWriter` the tool-call prose deltas write (C-06).

Two more are worth calling out because they are silent: the byte-level pre-tokenizer implements one
regex shape and applies it to every family, so gpt-oss, GPT-2 and the Llama-4/Kimi/DeepSeek GGUFs
tokenize differently from HuggingFace on digits, contractions and combining marks (C-10) — every
real-model gate uses a prompt with none of those; and `ResidentWeightBytes` omits whole tensor
classes, so the new Metal memory-fit guard refuses the paged 35B-A3B that fits and admits the
stacked 26B that does not (M-01, M-02).

On performance: the P19 default-ON flip allocates a fresh fused scratch (including an `hd×nKeys`
block) per pool slot, per layer, per *decoded token*, on a path that can never use it (M-03) — up to
~1.4 GB of zero-filled allocation per token at 16k context on a 1.5B; and the field has moved the bar
for the 8 GB CUDA MoE case: FreeToken's 39.3 tok/s and llama.cpp's 27–41 tok/s on 8 GB laptop cards
both come from executing missing experts on the CPU from host RAM rather than streaming them over PCIe
(L-01), which is the repo's own Lead 5 in `docs/task-freetoken-techniques.md` with the field's numbers
now behind it.

## §0 — Cross-cutting themes

1. **One predicate, seven consumers.** `canBatchN`, `specRollbackSafe`, `TruncateTo`'s recurrent
   guard, `Session.reconcile`, `Snapshot`, `ForwardCapture`/`ForwardSubCapture`/`HiddenLast` and
   `newLayerPager` each hand-list the families that have their own forward or non-positional state.
   LFM2 is the fourth family to need all of them and the first to miss six. The August lesson
   recorded in `CLAUDE.md` for descriptor fields ("check at the single chokepoint every family passes
   through") applies to lifecycle predicates too: derive `ownForward()` and `recurrentState()` once.
2. **A fix on one backend, one route or one converter is not a fix.** C-15's canonical f16
   rounding reached `cuda/` but not `gpu/` (N-04); d9829ce's bias-by-slot fix reached CUDA and the
   same bug ships on Metal (C-09); G-01's tagged parity group was built for CUDA and not Metal (G-02);
   M25's segment-rendering reached the text route and not vision or tools (M-22); C-21's input bound
   reached the aikit encoder and not the decoder embedder (C-07); R-11's error shaping reached the
   OpenAI decoder and not the Anthropic one (N-16); G19's heartbeat reached two of three
   buffer-then-stream sites (M-19).
3. **Gates that skip, count, or pass by construction.** Ten instances (§2). Four sit in the release
   ritual itself.
4. **Guards keyed on the wrong quantity.** `ResidentWeightBytes` is a lower bound that omits the
   dominant terms for three families (M-01); the Metal guard runs before the slot budget it should be
   computing from (M-02); the snapshot header bound (queue item M17) divides by blob-declared dims and multiplies by the
   model's (M-04); `noteIfEmpty` counts a skip as a run (G-01); `whyNoResult` diagnoses from a cell
   list production never passes (N-41).
5. **Default-ON flips shipped ahead of their registry, docs and gates.** `--cpu-fast-attention`,
   P19, P18 and A3 are all default ON; none of their escape hatches is in `docs/env-vars.md`, which
   `docs/api-tiers.md` names as Hard-tier contract (N-42); `docs/server.md` still promises exact
   session reuse and EAGLE prefills with the exact kernel while `Generate` prefills with the fast
   one (M-07).
6. **Per-token allocation in fresh code.** The fused scratch per decoded token (M-03), ~50 MB per
   512-row chunk per layer in P18 (P-03), full-vocab sort per token under `logprobs` (P-13), and
   the two full-vocab float64 vectors per verify position in sampled n-gram speculation (P-14).
7. **Bounds that stop at bytes.** The 1 MiB embed cap, the body cap and the text cap all bound
   bytes; positions, logprob entries and write time are unbounded (C-07, C-08, M-17).

## §1 — Critical

### C-01 · LFM2 is admitted to the generic batched prefill, which has no conv mixer — every prompt of ≥2 tokens panics *(three reviewers, independently)*

- **Where:** `decoder/forwardn.go:103` (`canBatchN`), `decoder/forwardn.go:1120-1133`
  (`prefillLogits`), `decoder/forwardn.go:379-381` and `decoder/forwardn.go:400-403` (the generic
  layer loop), `decoder/weights.go:694-702` (conv layers load no q/k/v/o and no QK-norm),
  `decoder/registry.go:1198` (`QKNorm: true`), `decoder/rmsnorm.go:32`, `decoder/model.go:806-809`
  (no `recover` in the `Generate` goroutine).
- **Code** (as it stood at the audit; the line references point at the FIXED code, since the
  citation lint keys on live lines):
  ```go
  // decoder/forwardn.go:103 — every own-forward family EXCEPT lfm2 is excluded
  return K > 1 && m.w.Embed.Rows() != 0 && !a.NonGatedMLP && !a.LearnedPosEmbed && a.gemma4 == nil && a.qwen35 == nil && a.granite == nil && a.nemotron == nil && a.mla == nil && a.llama4 == nil && a.gptoss == nil
  // decoder/rmsnorm.go:32 — lw.QNorm is nil on a conv layer
  row[i] = (v * inv) * weight[i]
  ```
- **Mechanism:** `runLayers` (sequential) dispatches LFM2 to `runLayersLFM2`, but `prefillLogits`
  asks `canBatchN` first, and `forwardn.go` contains no reference to `lfm2`, `shortConv` or
  `isConvLayer`. Every 2+-token prompt therefore runs the dense attention stack over the 22 conv
  layers, whose `QProj/KProj/VProj/OProj/QNorm/KNorm` were never loaded. `rmsNorm(qi, nil, …)`
  indexes a nil slice at the first conv layer (layer 0 in LFM2.5) — an unrecovered panic inside the
  `Generate` goroutine, i.e. the process exits; `net/http`'s handler recover does not reach a
  sibling goroutine. If aikit's `MatmulBT` on a zero-value `WeightMat` were to run instead of
  panic, the conv history would never be pushed and the output would be garbage. The same batched
  path backs `forwardN` (every speculative verify) and `NewCPUBlockSpec`.
- **Why the gate is green:** `TestLFM2_textParity` (`decoder/lfm2_test.go:178-182`) drives
  `m.forward` one token at a time and never touches `prefillLogits`; the HF differencing during
  bring-up went through the same sequential forward. `PrefillPath()` (`decoder/residency.go:730`)
  reports "batched shape" for LFM2 at serve startup — the same omission, published as a fact.
- **Trigger:** `serve --model <any LFM2/LFM2.5 checkpoint>`, first chat request. Or
  `Model.Generate(ctx, []int{a, b}, …)`.
- **Fix:** `a.lfm2 == nil` in `canBatchN` (the family's scoping doc, `docs/scoping-lfm2.md:46`,
  already said "no batched prefill"); add a `Generate` test on the committed `testdata/lfm2-tiny`
  fixture with the golden's multi-token prompt. The durable fix is §0 theme 1.
- **Confidence:** high. **Known?:** new (7098769, 2026-08-31).
- **DISPOSITION — FIXED 2026-09-02.** Reproduced first, on the committed `testdata/lfm2-tiny` with
  a 4-token prompt: `index out of range [0] with length 0` at `decoder/rmsnorm.go:32`, through
  `prefillLogits` → `forwardLayersN` → `runLayersFromEmbedN`, with `PrefillPath()` reporting
  "batched shape" for the same model.

  Fixed as §0 theme 1 rather than as `a.lfm2 == nil`: `ownForwards` is now ONE table carrying each
  family's dispatch function, and `runLayers` and `canBatchN` both read it, so "runLayers dispatches
  here" and "the batched path must not touch this" are the same fact. A family added to the table
  gets the exclusion for free.

  The regression test asserts the two paths AGREE, not that the crash stopped: `prefillLogits`
  documents itself as bit-identical to the sequential prefill, and a fix that stopped the panic by
  taking some third path would satisfy the weaker claim. A source scan
  (`TestOwnForward_tableNamesEveryFamilyForward`) fails if a `runLayersXxx` is written that the table
  does not name — the check that notices a SECOND list being born, which is what this defect was.

### C-02 · LFM2's conv window is recurrent state that none of the lifecycle plumbing knows about *(three reviewers)*

- **Where:** `decoder/kvcache.go:458-463` (the guard), `decoder/kvcache.go:408-416`
  (`resetRecurrent` *does* clear `c.conv`, but is only reached through that guard),
  `decoder/session.go:98` (`reconcile`), `decoder/forwardn.go:122` (`specRollbackSafe`),
  `decoder/kvsnapshot.go:71` (`Snapshot`'s refusal list), `decoder/forward_lfm2.go:111-147` (no
  pos-0 reset of its own), `decoder/model.go:703` and `decoder/model.go:733`
  (`ForwardCapture`/`ForwardSubCapture` allow-lists), `decoder/embed.go:40`,
  `decoder/layerpaging.go:64`.
- **Code** (as it stood at the audit; the line references point at the FIXED code):
  ```go
  // decoder/kvcache.go:458-463 — only mamba/delta reset on 0 or report inexact
  if c.mamba != nil || c.delta != nil {
      if pos == 0 { c.resetRecurrent() } else if pos < c.pos { exact = false }
  }
  // decoder/session.go:98
  if rolledBack && (s.cache.mamba != nil || s.cache.delta != nil) {
  // decoder/forwardn.go:122
  if a.granite != nil || a.nemotron != nil || a.qwen35 != nil { return false }
  // decoder/kvsnapshot.go:71
  if c.delta != nil || len(c.mamba) > 0 || len(c.mlaLatent) > 0 { return nil }
  ```
- **Mechanism:** `shortConvState.convWin` is mutated in place per token exactly like the Mamba-2
  and DeltaNet windows, and is absent from every predicate that treats those as non-positional.
  (a) `TruncateTo(0)` — `Session.Reset`, `sessionLRU.fresh()` — never clears it, so conversation
  B's first K−1 tokens at every conv layer convolve over conversation A's last `Bx` vectors: the
  cross-conversation leak audit C-01 closed for Mamba/DeltaNet. (b) A partial rewind reports
  `exact = true`, so `rewindForReuse` warm-reuses a prefix whose windows still hold the dropped
  positions; the attention layers then append K/V computed from that residual, so the corruption
  is permanent for the session. (c) `specRollbackSafe` admits LFM2 (no sliding window), so all six
  speculative entry points would "roll back" a rejected draft by a `TruncateTo` that touches only
  K/V. (d) `Snapshot` serializes an LFM2 cache; `LoadSession` rebuilds it via `NewCache(pos)` with
  empty windows and the session comes back "warm" — the C-05 shape, through `-session-dir` and
  `-kv-idle-demote`. (e) `ForwardCapture` returns nil rows for LFM2 (`runLayersLFM2` never calls
  `captureResidual`), the outcome `decoder/model.go:698-700` promises to fail loudly on; EAGLE's `fuseAt`
  would panic on them.
- **Trigger:** today everything multi-token dies at C-01 first; (a) and (b) are reachable now on the
  server's session path with a one-token divergent suffix (the sequential path). The rest goes
  live the moment C-01 is fixed.
- **Fix:** `c.conv != nil` in the three guards and in `Snapshot`'s refusal (or persist the window —
  it is `(K−1)×convDim` floats per conv layer, cheaper than one KV row); `a.lfm2 != nil` in
  `specRollbackSafe`, the two capture lists, `HiddenLast` and the pager exclusion; a conv-only case
  in `TestTruncateTo_resetsRecurrent` (`decoder/kvcache_recurrent_test.go:13-14` sets `mamba` and
  `delta` together, so a guard that checks either stays green and a third kind is invisible) and
  `"lfm2"` in `TestSpecRollbackSafetyGuard` (`decoder/spec_ngram_test.go:83-91`).
- **Confidence:** high. **Known?:** new — C-01/C-05/R-14 class, closed for two state kinds only.
- **DISPOSITION — FIXED 2026-09-02.** `KVCache.hasRecurrentState()` (mamba | delta | conv) is read
  by `TruncateTo`, `Snapshot` and `Session.reconcile`; the `ownForwards` table's `Recurrent` bit is
  read by `specRollbackSafe`; its `Captures` bit by `ForwardCapture`; and `ForwardSubCapture`,
  `HiddenLast` and `newLayerPager` refuse every own-forward family outright. Seven hand-written
  lists, none now.

  Worth recording: `resetRecurrent()` ALREADY cleared `c.conv` and was simply unreachable, because
  the guard that calls it named only mamba and delta. The fix was one word in a predicate; finding
  it was not.

  `HiddenLast`'s list had drifted by TWO, not one — **gpt-oss was missing from it as well**, so that
  seam was reachable for gpt-oss too. It refuses both now, which is the contract its own doc comment
  states.

  The new test uses a cache carrying ONLY `conv`, because `TestTruncateTo_resetsRecurrent` sets
  `mamba` and `delta` together — a guard checking either stays green, which is exactly why a third
  kind was invisible to it. `TestOwnForward_recurrentBitMatchesTheCacheKinds` pins the arch-side and
  cache-side views against each other, since a family recurrent in one sense and not the other is
  this same defect with the halves swapped.

### C-03 · LFM2 is serialized without its conv weights: a CRC-valid `.giw` that loads clean and nil-derefs at the first forward (regression of R3)

- **Where:** `decoder/serialize.go:899-939` (writer), `decoder/serialize.go:1266-1317` (reader),
  `decoder/serialize.go:105-120` (`canSerialize` returns nil for every family since v6),
  `decoder/weights.go:96` (`shortConv *shortConvWeights`), `decoder/forward_lfm2.go:126` and
  `decoder/forward_lfm2.go:32`, `internal/prequant/prequant.go:101-146` (`selfCheck` is `Load`
  only), `decoder/serialize_census_test.go:135-146`.
- **Code:** `grep shortConv decoder/serialize.go` → 0 matches; the v6 tail writes GProj, AttnSinks,
  expert biases, `mla`, `mamba` and nothing for `shortConv`.
- **Mechanism:** `cmd/prequant -o x.giw <lfm2-dir>` loads the model, serializes every field except
  `shortConv`, appends a valid CRC, and `selfCheck` passes because it only loads. Serving the
  bundle, the first token reaches conv layer 0 with `lw.shortConv == nil` → nil-pointer panic in the
  decode goroutine. This is the C2/R3 class (`docs/queue-release.md:44` records it closed by v6:
  "every registered family is representable, `canSerialize` is EMPTY"). The recurrence guard,
  `TestSerializeCensus_noSilentFieldDrop`, reflects over `LayerWeights` and would catch this — but
  its fixture list is hand-maintained and stops at 21 paths; `../testdata/lfm2-tiny` is committed
  (ed112b0) and not on it. The census test's own preamble says the previous guard failed because
  it "asks only 'is this family on the list?'" — the replacement still asks a list.
- **Trigger:** any LFM2 safetensors checkpoint → `cmd/prequant` → `serve --model <that .giw>`.
- **Fix:** a v8 tail with `shortConv` (presence byte + three f32 tensors, the mamba block's shape),

  `arch.lfm2 != nil` until then; and a registry-driven census (every `model_type` in `registry`
  maps to a fixture or an explicit skip) or a reflection-built synthetic `LayerWeights` with every
  field populated, round-tripped without a fixture. Also exclude lfm2 in `newLayerPager`
  (`decoder/layerpaging.go:64`) — `runLayersLFM2` never calls `enterLayer` (the 2026-08-05 audit's N-13 class).
- **Confidence:** high. **Known?:** regression of R3 (closed 2026-08-19).
- **DISPOSITION — FIXED 2026-09-02.** Reproduced by putting the committed fixture into the census:
  `SILENT DROP: layer 0 field shortConv was populated (1) and is empty after a .giw round-trip`, on
  layers 0/2/3, with the round-tripped model returning no tokens at all.

  A v8 tail (presence byte + `inProj`/`convW`/`outProj`, the v6 Mamba-2 block's shape) written
  unconditionally, plus a `validateShapes` refusal for an lfm2 conv layer with no mixer. Both halves
  are needed: the tail makes a correct bundle round-trip, and the refusal makes every EXISTING
  (pre-v8) bundle fail at load instead of at the first forward. `canSerialize` stays empty — the
  family is representable now, which is the better answer than refusing it.

  **The guard was itself a hand-maintained list, which is the finding.** The census's own preamble
  says the guard it replaced failed because it "asks only 'is this family on the list?'" — and it
  asked a list too, 21 paths, and `../testdata/lfm2-tiny` had been committed since ed112b0 without
  being on it. `TestSerializeCensus_everyFixtureIsListedOrExcluded` now requires every committed
  model fixture to be censused or excluded with a written reason; it found **eleven** the census had
  never mentioned, all eleven are censused now (30 fixtures, 0.19 s), and the five exclusions are
  measured cost, not judgement (gpt2 529 MB, gemma4-dense-scaled 449 MB, mellum-mellum2-slice 4.0 GB

  config-only fixture that `Load` refuses). Glob discovery was tried first and **rejected on
  measurement**: 152 s against 0.19 s, because it dragged those three in.

### C-04 · Batched prefill sizes its attention scratch from the global key count but tiles from the per-layer one — a warm sliding-window session panics

- **Where:** `decoder/scratch.go:294-319` (`newHeadWorkerPool`), `decoder/scratch.go:192-202`
  (`attnRowTile`), `decoder/forwardn.go:211`, `decoder/forwardn.go:306`, `decoder/forwardn.go:423`,
  `decoder/forwardn.go:694`, `decoder/forwardn.go:745-751`; `decoder/kvcache.go:515-552`
  (`batchReadLocal`).
- **Code** (as it stood at the audit; the line references point at the FIXED code):
  ```go
  // decoder/forwardn.go:211 and :298 — the pool is sized ONCE from the global key count
  maxKeys := startPos + K
  attnPool := newHeadWorkerPool(prefillAttnWorkers(K, maxKeys, hd, arch.maxHeads()), K, maxKeys, hd)
  // decoder/scratch.go:304-313 — slot buffers sized for t = attnRowTile(K, maxKeys) rows
  t := attnRowTile(K, nKeys)
  qh: make([]float32, t*hd), ... scores: make([]float32, t*nKeys), ch: make([]float32, t*hd)
  // decoder/forwardn.go:694 and :745-751 — but each call tiles from ITS OWN key count
  nKeys := len(keys) / kvDim
  tile := attnRowTile(K, nKeys)
  for t0 := 0; t0 < K; t0 += tile {
      kt := min(tile, K-t0)
      for i := range kt { b := (t0+i)*qDim + qhead*hd; copy(qh[i*hd:i*hd+hd], q[b:b+hd]) }
  // decoder/kvcache.go:521-522 and :533 — a local layer's assembled window is SHORTER than maxKeys once startPos ≥ W
  base = max(startPos-r.w+1, 0); hist := startPos - base; ... return base, hist + K
  ```
- **Mechanism:** `attnRowTile(K, n) = min(K, 2,097,152/n)`. For a ring layer with `startPos ≥ W`,
  `nKeys = W−1+K < maxKeys`, so the per-layer tile is *larger* than the slot was sized for. Whenever
  `K·maxKeys > 2,097,152` (so `t < K`) the gather at `decoder/forwardn.go:750` slices `qh` past its
  length — `panic: slice bounds out of range`, in a worker goroutine on the fan-out arm and in the
  `Generate` goroutine on the serial one; neither is recovered. Independent of
  `--cpu-fast-attention` (the acc64 arm uses the same `qh`). A cold prefill always has
  `nKeys == maxKeys`, which is why every golden and benchmark misses it.
- **Trigger:** `serve --kv-sessions 4` with Gemma-3-1b (W=512, hd=256): turn 1 leaves the session at
  600 tokens, turn 2 appends 2048. `maxKeys=2648 → t=791`; local layers `nKeys=2559 → tile=819`;
  `qh[791*256:792*256]` on a 791·256 slice. Gemma-3-4b (W=1024): a 1200-token session + an
  1800-token suffix. Mistral-7B (W=4096) needs an 8k+ session and a 1k+ suffix. Any windowed family
  through `Session.Generate` or n-gram speculation (both prefill via `prefillLogits` →
  `forwardLayersN` with `startPos = cache.Pos()`).
- **Fix:** make the tile a property of the pool — compute it once in `newHeadWorkerPool` /
  `headWorkerPool`, store it on `headWorkerScratch`, and have `attendOneHead` read it (or clamp
  `tile = min(attnRowTile(K, nKeys), len(ws.qh)/hd)`). Gate: `forwardLayersN` on a ring cache with
  `startPos ≥ W` and `K·(startPos+K) > 2Mi`, tiny `hd` keeps it cheap and asset-free.
- **Confidence:** high. **Known?:** new (G20 tiling landed 2026-08-26).

### C-05 · A cancelled batched prefill on a wrapped ring leaves stale K/V that the next warm turn reads as history — `reconcile` discards `TruncateTo`'s `exact`

`decoder/kvsnapshot.go:287-309` checks nothing on the global branch (the ring branch,

`len(keys[l])`, `len(vals[l])`, `len(keyScale[l])` and `len(tokens)` are blob-controlled and never

## §5 — Performance observations

Each names a mechanism and what to measure before believing it; none is a claimed speedup. Where a
figure appears it is arithmetic from the code, not a measurement, and is labelled so. The
"do-nothing arm" rule applies to every one.

**CPU decode and prefill**

- **P-01 · Decode allocation churn from M-03.** Measure tok/s and `MemStats.{TotalAlloc,NumGC}` per
  token at context 1k/4k/16k, `GOINFER_FUSED_ATTENTION` unset vs `=0`, same binary, interleaved.
  Expect the gap to grow linearly with context. A decode allocation gate (`testing.AllocsPerRun` on
  one `forward` step) would have caught it.
- **P-02 · The fused schedule still does full-`nKeys` QKᵀ on sliding-window layers.**
  `decoder/fusedattn.go:85-97` breaks only on `k0 > hiMax`, with no `k1 <= loMin` skip; a cold
  prefill's assembled local window is the whole `[0, K)` (`decoder/kvcache.go:521`). For a local
  layer at K=8192, W=1024 the last query tile computes 16 key blocks and zeroes 13 of them
  (`decoder/fusedattn.go:101-107`): O(K²) where O(K·W) is available with a two-line block skip that keeps
  bit-identity (skipped blocks contribute exact zeros). Mellum2 has 21/28 sliding layers, Gemma-3
  5/6. Measure prefill wall at K=8192 on both with and without the skip; cosine must be 1.0.
- **P-03 · P18 allocates ~50 MB per 512-row chunk per layer.** `decoder/mlp.go:504`, `:507-508`,
  `:522`, `:532-535`, `decoder/forwardn.go:517`: `perRank` (n·k·hidden ≈ 37.7 MB at Mellum2 shapes),
  `gathered`/`gate`/`up`/`outBuf`, `logits`, `idxs`/`wtss` and `emOut` are fresh per chunk per layer —
  ~22 GB over one K=8192 prefill, the order of the 20.9 GB the per-row path was criticised for.
  Hoist to one per-prefill scratch sized `moeExpertMajorChunk`. The per-row attribution arm showed
  0.99–1.02× for allocation alone, so expect small but nonzero.
- **P-04 · The batched path's `Workspace` keeps aikit's default fan-out threshold**
  (`decoder/forwardn.go:317`, never `SetThreshold`; decode uses 300K at `decoder/scratch.go:84-85`),
  so small-K `forwardN` (spec verify, K≤8) runs its q/k/v/gate/up batches serial where decode's
  identical M=1 matmul fans out. Measure verify latency per round at K=4/8 with
  `DefaultDecodeParallelThreshold` vs current.
- **P-05 · Per-slot `vt` is allocated and unused whenever the fused schedule runs**
  (`decoder/scratch.go:311-312`; `gatherKVFused` writes `vBlk`), and `prefillAttnWorkers`
  (`decoder/scratch.go:230-240`) charges `2·nKeys·hd` but not `vBlk`/`sBlk`/`tmp`/`acc` — real
  per-slot use is ~25% above the 256 MiB budget at 8k. Allocate one of `vt`/`vBlk` per mode.
- **P-06 · RoPE cos/sin recomputed per position per layer in the batched loop**
  (`decoder/rope.go:31-34`, `decoder/forwardn.go:404-407`): ~2 s of a ~250 s 8k prefill on a 1.5B;
  a per-prefill `[K][half]` table removes it. Sub-1%; measure before bothering.
- **P-07 · `gatedDeltaNetStep` walks the `[hk,hv]` state column-wise (stride `hv`) in its inner
  loops** (`decoder/deltanet.go:226-243`): with `hk=hv=128` each `vd` iteration touches 128 floats
  512 B apart, twice, so the head's 64 KB state streams 128× per token as cache lines, and nothing
  vectorises across the strided access. Interchanging to `kd`-outer with `kv[hv]`/`delta[hv]`
  scratch keeps every per-output reduction in the same `kd`-ascending order (bit-identical) and
  makes the inner loop contiguous. `docs/task-zeno-compare.md` puts this step at ~19% of a decode
  token; the `GOINFER_DELTANET_TIMING` seam (`decoder/deltanet.go:21-60`) reports the number to
  compare. Measure on Qwen3.5-35B-A3B paired, then `TestGatedDeltaNet_parity` +
  `_chunkedMatchesSequential` for identity.
- **P-08 · Mamba-2 in/out projections stay f32 on the CPU path** (`decoder/mamba2.go:44`, `:51`,
  `:84`, `:158` — `[]float32` through `matvec`), the same 4× byte-stream the DeltaNet fix of
  2026-08-19 removed (`decoder/deltanet.go:77-84` records "22.1 GB per token across 48 DeltaNet
  layers, against ~9.5 GB for the whole int4 FFN"). Nemotron-H is the CPU family this hits hardest.
  `ssmQ8CPU`/`ssmQ8WeightsOnly` (`decoder/mamba2.go:76-83`, `:167-174`) already instrument the
  precision question. Measure granite/nemotron CPU decode f32 vs W8A8 mamba projections, paired,
  with the real-model oracle cosine as the accuracy arm.
- **P-09 · `gemma4Attend` re-gathers and transposes every KV head's full history per layer per
  token** (`decoder/forward_gemma4.go:301-310`): O(nKeys·hd) copies × nKV × layers on top of the
  attention itself — a 2–3× traffic multiplier at long context. Store V transposed at append time.
  Only worth it if Gemma-4 CPU decode is a target.

**Loaders and paging**

- **P-10 · Every `.giw` load CRCs the entire bundle before touching a layer**
  (`decoder/serialize.go:300-308`, `decoder/model.go:216-222`; `internal/prequant/prequant.go:193-201`
  does it again right after writing). For a >RAM `--stream-weights` bundle the whole file is read
  from disk at every start (NVMe ~10 s; the 5400 rpm archive minutes) and the pages it pulls are
  exactly the ones paging then evicts. Per-layer CRCs in the layer tail (or a Merkle of them in the
  header) keep the guarantee and make verification lazy. Measure cold-page-cache TTFT with the CRC vs
  header-only.
- **P-11 · `loadFusedExperts` materialises whole 3-D f32 expert tensors per layer, × GOMAXPROCS**
  (`decoder/weights.go:1071-1094`, callers `:870` and `:1823`; contrast `streamExperts` at
  `:1163-1187`, one expert at a time): Qwen3.6-35B-A3B ≈ 3 GB transient per in-flight layer → ~25 GB
  at 8 workers on top of the resident int4. Measure peak RSS of `Load(int4)` at GOMAXPROCS=1 vs 8,
  before/after per-expert `SubF32`. The gpt-oss safetensors loader is the opposite — single-threaded
  (`decoder/gptoss_safetensors.go:97`; every other loader uses `parallelLayers`).
- **P-12 · Kind-4 paged bundles fault the canonical copy outside the pager's budget on any M>1
  path** (`decoder/moepaging.go:61-79` registers row4 OR canonical, never both;
  `decoder/serialize.go:1239-1259` aliases both): P18 expert-major prefill (default ON) reads the
  canonical bytes, which are demand-faulted and never accounted or released by `SpanCache`. Correct
  output, wrong budget; `advisedBytes()` cannot see it. Measure RSS during a 4k-token prefill on a
  kind-4 vs kind-3 bundle at the same `WeightCacheBytes`. (`layerPager`'s window is also one layer
  over budget by construction — `decoder/layerpaging.go:107-114`, `:119-137`: resident set is
  `window+ahead`.)

**Sampling and speculation**

- **P-13 · `computeLogprobs` full-sorts the vocabulary per token whenever `top_logprobs > 0`**
  (`decoder/sampler.go:293-316`; also disables the on-device argmax path, `:125`, `:149`): O(V log V)

- **P-14 · Sampled n-gram speculation allocates two full-vocab float64 vectors per verify position**
  (`decoder/spec_sample.go:33`, `:38`; `:56` clones logits per position; called from

  scratch suffices. Measure GC count and tok/s at T=0.7 `--spec ngram` on CUDA vs T=0, with off.
- **P-15 · `forEachChunk` spawns GOMAXPROCS goroutines and a channel per call, twice per sampled

## §7 — Landscape, and an improvement program

The field as of 2026-09-02, from a sourced sweep (dates and links at the end of this section), read
against what the repo has already measured. Each item states the mechanism, why it fits goinfer's
constraints (single binary, no toolchain, bit-identity, measure-don't-assume), the lever it attacks
in the repo's own numbers, and a pre-registered decision rule in the queue's shape — including the
do-nothing arm. Items are marked **borrow** (the field has it), **verdict** (the field moved and the
repo's prior answer stands or changes), or **new** (a proposal specific to this codebase). Prior
art in-tree was read first: `docs/task-freetoken-techniques.md`, `docs/task-moe-streaming.md` §C′,
`docs/QUEUE.md` G31–G34, `docs/spec/README.md`, `docs/completed/task-turboquant-spike.md`,
`docs/roadmap.md`.

**Where the bar moved.** On an 8 GB laptop card, FreeToken (FlashML, arXiv 2608.16157, 17 Aug 2026)
decodes Qwen3.6-35B-A3B at **39.3 tok/s** on an RTX 4060 Laptop (i9-13900H; measured host BW
47.5 GB/s, PCIe 11.8 GB/s), and llama.cpp's `--n-cpu-moe` reaches **27–41 tok/s** on an RTX 3070 Ti
8 GB (May 2026 field reports). goinfer's measured figure for that class is 15.69 tok/s with CUDA
graphs and C′ expert streaming, with ~48% of the token in expert DMA at the PCIe ceiling (G31/G32).
Both peers get there the same way: **missing experts execute on the CPU from host RAM (~4× the
PCIe rate) instead of being streamed**, behind a global cross-layer LRU and a double-buffered
whole-layer prefill. On Macs, Ollama's MLX runner (default on ≥32 GB since v0.30, May 2026) and
mlx-lm's native MTP (Qwen3.5-27B 1.5×; **MoE only 1.11×** — one MTP layer predicts routing poorly)
set the Metal expectations; llama.cpp 0.2.0 (21 Aug 2026) ships `--fit on` by default and
in-GGUF MTP drafting (`--spec-type draft-mtp`, ~0.76–0.82 acceptance on Qwen3.8-27B, +33% on a 3090).
Models now ship as ~3B-active MoE + hybrid linear-attention layers + native MTP heads + NVFP4/QAT
checkpoints (Qwen3.8-27B/Flash-Next, Gemma 4, Nemotron 3.5 Lightning, DeepSeek V4). Go 1.27's
`simd`/`archsimd` (19 Aug 2026) adds arm64 NEON but no SDOT/i8mm/VNNI and is experiment-gated, so
hand-written assembly remains the CPU kernel substrate. goccy/go-llama is single-threaded with a
4 GiB linear-memory cap and no published benchmarks. Single binary + no toolchain is still unique
in this field (FreeToken is a Python/uv install; llama.cpp needs a compiler; Ollama bundles a
runner).

### A. Borrow — the field has it and it fits

**L-01 · Hybrid CPU/GPU expert execution for the 8 GB CUDA MoE path — promote Lead 5 from "track"
to first.** *(borrow: FreeToken q⋆ split; Fiddler, ICLR 2025; llama.cpp `-ncmoe`.)* Mechanism:
per layer, the m experts missing from the device cache are split — q⋆ ≈ m·(B_PCIe/B_host) fetched
into slots and run on the GPU, the rest computed on the CPU from the pinned host copy with the
existing W4A8/W8A8 NEON/AVX2 expert kernels, partial sums merged exactly. Why it fits: goinfer
already holds every expert pinned on the host for C′ (`cuda/resident.go:547-557`), already has
the CPU expert kernels (P18 made them expert-major), and already pays the host-visible routing
readback per layer that `task-moe-streaming.md` §C′ said the on-device router exists to avoid
(P-21: the D2H of `rIdx` is on the token path today) — so the architectural objection recorded in
`docs/task-freetoken-techniques.md` Lead 5 is smaller than it was when written. The lever is the
48% DMA term: with misses on the CPU the token time is `max(GPU hits, CPU misses)` instead of
`hits + DMA`, and G32's finding that the DMA is bandwidth-bound at line rate is exactly the case
where moving work off the bus beats overlapping it. **Decision rule:** Qwen3.6-35B-A3B int4 on the
8 GB card, paired and interleaved against the shipped C′ path and against `off`; fund at ≥1.3×
end-to-end, park below 1.15×, 1.15–1.3× ambiguous → second mechanism. The number to beat is 39.3.
Prerequisite: the G33 trace replay (`scripts/g33_replay.py`) already yields the per-layer miss
counts to size q⋆ from before any code.

**L-02 · A global cross-layer LRU for the CUDA expert cache (Lead 4).** *(borrow: FreeToken's
shared LRU; llama.cpp draft PR #27861's trace simulation — LRU-64 ~69% hit, LRU-128 ~81%, ~98.5% at
384 slots.)* The CPU pager already pools all layers into one frequency-aware `SpanCache`
(`decoder/moepaging.go`); only the CUDA path's `GOINFER_MOE_CACHE_SLOTS` is per-layer. G33 says
misses are capacity, not prediction — which is the regime where pooling raises effective capacity
wherever per-layer hot sets are uneven. **Decision rule:** replay the G33 trace under per-layer vs
global LRU at equal total slots first (no code beyond the replay); build only if the simulated miss
rate drops ≥15%; then the same paired A/B as L-01. Note llama.cpp's kernel-free formulation
(companion tensor with a permanently-zero slot + id remap, decode-only) is the shape to copy if
the slot-indexed kernels ever need to go.

**L-03 · Whole-layer double-buffered expert prefetch during prefill (Lead 2, §C′'s named next
lever).** *(borrow: FreeToken measured 19–26% from the second buffer; MoE prefill touches nearly
every expert, so the whole set is the right prefetch unit.)* Fits G32 ("overlap is the only
lever"). On the Mac paged path the per-layer expert set of the 35B is ~0.4 GB, so two buffers fit
beside the slot pool; combined with P18 (compute) this is the I/O half of paged prefill.
**Decision rule:** TTFT at 2k/8k prompts, paged 35B, single- vs double-buffered; fund at ≥1.2×.

**L-04 · `--fit`-style automatic placement as the default.** *(borrow: llama.cpp 0.2.0 `--fit on`:
shrink context first, then spill routed experts, dense tensors prioritised, 85–90% VRAM
utilisation; Ollama's runner does the equivalent.)* goinfer asks the operator for
`GOINFER_METAL_MOE_SLOTS`, `--moe-cache-slots`, `-ctx`, `--kv`; the M-01/M-02 fix produces the
computed budget this needs. Pick N slots and the context cap from RAM/VRAM with the same
priority order, print what was chosen, keep every knob as an override. Cost: a day; risk: none to
numerics. This is also the answer to "default to 64" having no code.

**L-05 · State checkpoints at semantic anchors (Lead 1), and disk restore points.** *(borrow:
FreeToken's anchor checkpoints for hybrid models; Ollama v0.33 "prefill restore points"; LM Studio's
KV checkpoints every 256 tokens; mlx-lm's SSM snapshot + KV trim under speculation.)* One mechanism
closes four open items: the Snapshot refusals for DeltaNet/Mamba/conv state (C-02(d)); P-18's
stop-string → cold prefill; the "resident models get no prefix reuse" trade for slow MoE in long
agent loops (the regime `task-freetoken-techniques.md` says to re-measure); and rollback of
recurrent state under speculation, which would lift `specRollbackSafe`'s blanket refusal of the
hybrid families. Snapshot the full recurrent state only at turn/tool-call boundaries (bytes are
bounded by turns, not tokens). **Decision rule:** TTFT of turn N in a 10-turn agent transcript on
Qwen3.6-35B-A3B, resident CUDA, with vs without anchors; fund at ≥2× turn-3+ TTFT.

**L-06 · Speculation on the GPU backends: three field results to fold into the P10/P15 gates.**
*(borrow.)* (a) EAGLE 3.1 (vLLM, 26 May 2026): FC-norm on target hidden states + post-norm feedback
fixes "attention drift" at depth, up to 2× acceptance length at long context, config-level — applies
if goinfer's EAGLE path loads 3.1 drafters. (b) DSpark (DeepSeek, arXiv 2607.05147): confidence-
scheduled verify length — a scheduler change that fits G34's finding that the slot budget, not
acceptance, caps width. (c) MTP→n-gram pipelining (llama.cpp #23184): extend an MTP draft with the
n-gram drafter for free; n-gram alone gives no gain in llama.cpp either, which matches spec/02.
Warnings the field supplies: mlx-lm's MoE MTP at 1.11× and llama.cpp's "diminished due to
expert-union" — for A3B-class MoE the draft quality, not the verify, limits gains; the repo's own
"MTP doesn't change the math on CPU" (`docs/roadmap.md:71`) stands. GPU-only.

**L-07 · Precomputed grammar masks for `constrain` (P-20).** *(borrow: XGrammar-2, arXiv
2601.04426 — accepted/rejected/context-dependent token classes per state, cross-grammar mask cache
keyed by sub-grammar hash, JIT of the K most expensive masks during prefill, ~45 µs/token;
llguidance's slicer, <50 µs/token on a 128k vocab.)* goinfer's O(V) walk per step is plausibly
6–30 ms on a 152k vocab against a 2–5 ms resident decode step, i.e. the headline feature ("a Go
struct the model cannot violate") is the slowest path on the fastest backend. Cheapest first: `[]bool`
EOS, first-byte bitmap, the two string-state bitsets, then a vocab byte-trie so one walk masks every
token sharing a prefix. **Decision rule:** measure `Process` at `fsStr` and `fsObjKeyOrClose` at
V=151,936 before and after each lever; the target is under 0.5 ms per step. Pure Go, no new
dependency, no numerics.

**L-08 · Formats the field now ships: NVFP4.** *(borrow: llama.cpp NVFP4 MMQ kernel merged 1 Apr
2026 and `llama-quantize` NVFP4 in Aug 2026; MLX `nvfp4`/`mxfp8` modes since Jan 2026; Qwen3.8,
Nemotron 3.5 Lightning and DeepSeek V4 publish NVFP4/QAT checkpoints.)* The MXFP4 reader
(`decoder/mxfp4.go`) and the fp8 e4m3 reader (`decoder/fp8.go`, Q3) are two-thirds of an NVFP4
reader (e2m1 elements, e4m3 per-16 block scale, f32 tensor scale) — dequant → int4/int8 requant the
way MXFP4 loads today. A loader item, no kernel work, and it unlocks the checkpoints the newest
models ship first. `scale_fmt: ue8m0` (G8's note) is the other missing scale encoding.

**L-09 · CPU kernels: keep assembly; the remaining gap is the interleaved-repack + SMMLA/VNNI
shape.** *(verdict.)* Go 1.27's `archsimd` has no dot-product intrinsics and an unstable API — not
a substrate for the W4A8 kernels yet; watch 1.28. The field's CPU int4×int8 path (KleidiAI:
4×4/8×8 interleaved weight repack + `SMMLA` outer products; Intel: int8 activations with VNNI beat
4-bit bandwidth savings once cores scale) is the shape of the "4-bit matmul to bandwidth class"
item already scoped (~40 vs ~67 GB/s aggregate). Nothing new to file; the scoping stands.

**L-10 · KV quantisation: the repo's NO-GO stands.** *(verdict.)* TurboQuant is still unmerged in
llama.cpp (PR #21089 closed; discussion #20969 only), shipped only in forks and QVAC; mlx-lm's
PolarQuant draft runs at 0.5× decode; llama.cpp and Ollama default to f16 KV. The in-repo spike
(`docs/completed/task-turboquant-spike.md`, NO-GO 2026-06-14) and the "KV-quant refuted as a speed
lever" result need no revisiting. Keep f16 default, q8_0 opt-in where it exists.

**L-11 · Grammar-constrained speculation: the repo's negative result is ahead of the field.**
*(verdict.)* The only shipped form anywhere is vLLM's validate-and-truncate (draft tokens checked
against the grammar bitmask, truncated at the first invalid position — accept length collapses
~7→~3); no engine ships grammar-aware *drafting*. goinfer measured the premise dead on 2026-08-26
(tokenization-boundedness: the mask forces a legal-but-different tokenization the drafter never
sees; the sign inverts where the target is fluent). Nothing to borrow. The result itself is
publishable and unclaimed — see L-18.

**L-12 · Positioning.** *(verdict.)* The README lane claim that "the pure-Go ports are archived
toys" is falsifiable now that goccy/go-llama exists; the true and durable statement is that the
transpiled ports are single-threaded with a 4 GiB linear-memory cap and no GPU, and goinfer's edge
is parallelism plus native GPU backends, not kernel quality — which inverts if goccy ships a
threaded build. The requirements the market now sets for "local": 26–35B-A3B on 8–16 GB at

rollback under speculation (L-05), NVFP4 (L-08). Single binary, no toolchain, remains the
differentiator no peer has.

### B. New — proposals specific to this codebase

**L-13 · P19-exact: a max-first two-pass fused attention that keeps A1's bit-identity.** *(new.)*
P19's fused kernel breaks `decode == prefill` and `spec-verify == sequential greedy` only because
the running-max rescale re-associates the sum; FlashAttention's block-wise `acc += P_blk·V_blk` is
otherwise an *ascending* fold over keys, identical to one long ascending loop. Compute the exact
per-row max in a first tiled pass over QKᵀ (no exp, no AV, nothing materialised beyond one
`[kt, kb]` block), then a second pass that recomputes QKᵀ blockwise, exponentiates against the
fixed max, and accumulates the denominator and P·V in the same ascending order and precision the
materialized kernel uses (f64 on the acc64 arm — `linalg.MatmulQKAcc64` already exists in that
form). No rescale ⇒ no re-association ⇒ bit-identical to the materialized acc64 path, with the fused
kernel's memory traffic. The cost is QKᵀ twice (≈ +50% of the attention term's FLOPs). The 1.69–1.73×
P19 win came from cache residency (the `[n, kb]` block vs the 1.4 MB score rows, invisible until
parallelised), not from FLOPs, so a second compute pass over a cache-resident K block is the cheap
side of that trade. If it clears, `--cpu-fast-attention` and the fused path can be default-ON
*without* an output change, the 512 floor goes, and the M-07 divergences (EAGLE, sessions) close by
construction. **Decision rule:** the P19 harness (`decoder/p19_fused_attn_test.go`, row-parallel,
causal, all tiles) at K=4096/8192, three arms — materialized acc64 (off), fused f32 (shipped),
fused-exact acc64 (new) — asserting `!=` on every logit between arms 1 and 3; fund at ≥1.3× over
arm 1, park below 1.1×, and if it lands between, keep the shipped f32 path and record the number.

**L-14 · Speculation pays on the paged CPU MoE path precisely because that path is not
compute-bound.** *(new.)* `docs/spec/README.md`'s CPU verdict — "an M=K verify pass costs ~K
sequential decodes" — is a statement about compute-bound dense decode. The paged 35B-A3B path
(1.5–2 tok/s on the Mac, ~70% of the token in expert page-ins, G33: capacity misses) is I/O-bound.
A batched verify of K draft rows pages in the *union* of their routed experts once per layer, where
K sequential decodes page in `K·topK` with repeats under a tight slot budget; and P18's expert-major
kernel runs the union at M>1 instead of K GEMVs. llama.cpp's note that MoE MTP gains are "diminished
due to expert-union" is the same effect with the sign flipped: on a resident model the union costs
compute, on a paged one the union *is* the saving. Turn G34 ("block verify pays at K=2–3; the slot
budget caps the width") into a controller: pick K per round so the predicted union fits the slots
(the n-gram drafter's proposals are known before the verify, so the union can be estimated from
the previous rounds' routing). **Decision rule:** paged 35B-A3B decode on the 16 GB Mac, `--spec
ngram` with union-bounded K vs `off`, paired on the same prompts; fund at ≥1.25× tok/s; the prior
CPU verdict stays intact for dense.

**L-15 · Longest-common-prefix session selection with ring-aware exactness.** *(new, half
borrowed from radix caches.)* The server's LRU reuses a session only when its whole token list is a
prefix of the new prompt (`internal/serveapp/sessions.go:155-164`), while the decoder's
`rewindForReuse` already implements the correct partial-prefix rewind with the ring exactness rule.
Let `acquire` pick the session with the longest common prefix above the system-preamble length, and
let the decoder truncate. A stop-string hit, a `max_tokens` cut mid-word, or a client that edits its
last message then reuses everything before the divergence instead of paying a cold prefill and an
eviction. Combined with L-05 anchors this is the single-user form of vLLM's prefix cache without a
radix tree. **Decision rule:** the P-18 measurement; fund if turn-3 TTFT with a stop string drops
to within 1.2× of turn-3 without one.

**L-16 · Lifecycle by construction — the engineering program that closes the LFM2 class.**
*(new.)* Derive `Architecture.ownForward()` and `KVCache.recurrentState()` once and make the seven
consumers in §0 theme 1 read them; extend `validateResolved` to dims and RoPE tables (M-06); replace
the census fixture list with a registry-driven check plus a reflection-built `LayerWeights`
round-trip (C-03); run `TestSession_reuseParity`/`snapshotRoundTrip` over every committed tiny
fixture in CI (they take `GOINFER_TEST_MODEL` already). Each is small; together they make "a new
family fell through a switch arm" a compile-time or CI-time event instead of an audit finding.

**L-17 · Gates for the two costs this audit found without a gate: per-token allocation and per-token
host round trips.** *(new.)* A `testing.AllocsPerRun`-style decode gate on one `forward` step per
family (would have caught M-03 the day it shipped), and a counted-syncs-per-token assertion on the
CUDA/Metal decode paths using the `profSyncCalls` seam (would make P-21's 4× undercount visible and
hold the line after L-01). Both run without assets on the tiny fixtures.

**L-18 · Argmax-only tails everywhere greedy, and no full-vocab readback on any backend.** *(new;
partly the existing `tailAllArgmax`.)* The block-spec prompt seed (C-12), the CUDA per-row verify
tail (P-21), WebGPU's every-token `vocab×4` readback and its prefill LM head (P-22) all move logits
the caller reduces to one integer. One device-side argmax per row (Metal has it; CUDA has
`argmax_reduce`; WebGPU needs a 64-lane kernel of the `moeRoute` shape) and a `tailLastArgmax` mode
remove them together. Bit-identity is preserved (argmax tie-break is pinned host-side and
kernel-side alike).

**L-19 · Publish the negatives.** *(new; positioning.)* Four results in this tree are ahead of the
field and unclaimed anywhere: grammar-aware drafting is dead for a tokenization reason (L-11);
TurboQuant is a NO-GO on accuracy at 3 bits on CPU (L-10); KV-quant is not a decode-speed lever;
MTP does not change the CPU arithmetic. They are exactly the shape of the inference primer's
chapter 11, and a written explainer series was already chosen as the visibility route over a bare
repo link. Cost: prose only.

## §9 — Method, limitations, and what was not confirmed

**Method.** Eleven reviewers, one per subsystem, each with a written brief carrying the repo's
conventions, the prior audit's §7 and dispositions, and the four queues; each was told to prefer
ten confirmed findings to forty speculative ones, to quote the lines, and to keep unconfirmed
suspicions in a separate list. Their reports were consolidated here; overlapping findings count
once and are marked. Every Critical and every gate item, plus the Metal guard, the release
workflow, the sidecar path and the session/ring mechanism, were then re-read from the source by
the consolidating pass before being written up. A twelfth pass surveyed the field with dated
sources and was read against the repo's own prior verdicts before anything was proposed.

**Not done.** No build, test run, race detector, fuzzing or device execution (go1.24.7 against a
`go 1.27.0` requirement, no module proxy, no GPU). The audit copy omitted `*.safetensors`,
`*_golden.json` and `docs/assets/`; the two conclusions that leaned on their absence were corrected
against the Mac. aikit was not readable; the M-invariance of its `MatmulW8A8` on the webgpu staged
backend (which P18's bit-identity and the dense batched path both assume), `Upload`'s implicit
synchronise, whether `Encoder.Dispatch` rebinds per dispatch (G-08's exact symptom), whether the
CUDA opt-in shared-memory attribute is ever set (M-16), and whether `NewBufferOf` copies or wraps
(M-02's doubling) are all stated as assumptions where they matter. Line numbers are as of
`cfec302`; the tree moves daily.

**Recommended follow-up not attempted here:** `go vet` + `staticcheck` under the tagged variants
across all five modules with the real toolchain; the race detector against two concurrent
`Generate` calls on a `StreamWeights` model and against `handleChatTools` with a prose-emitting
model and a 100 ms heartbeat (C-06); a fuzz target for `LoadSession` that mutates one header/payload
field and recomputes the CRC (M-04); `gguf-dump` of the local gpt-oss/Llama-4/Kimi GGUFs to confirm
their `tokenizer.ggml.pre` strings (C-10); and the P-01 measurement, which decides whether M-03 is a
perf item or a regression.

**Unconfirmed leads** — worth one look each, not reported as findings:

- `decoder/registry.go:1446-1451` asserts transformers 5.12's `DeepseekV3Attention` does NOT fold
  `mscale_all_dim²` into `scaling`, while `:1526-1528` says the real models do; every transformers
  the reviewers know folds it. If 5.12 still folds, V2-Lite's softmax temperature is off by
  ~1.59× and only the int8-vs-bf16 cosine bar (0.99) is hiding it. Check the pinned HF source.
- `cuda/resident.go:1235-1244`: CUDA `ForwardN` with `r.dnet != nil` and K>1 runs the sequential
  loop and does not decline — C-17's disposition chose "decline at the runner that owns the state"
  for webgpu so the fix would not depend on `specRollbackSafe` one package away; CUDA depends on it.
- `cuda/prefill.go:156-163`: `nonBatchableKind` returns `""` for an UNLOADED projection, which the
  caller reads as "batchable"; dense Qwen3.8 DeltaNet layers are declined only because
  `cuda/backend.go:983` zeroes their geometry — a coincidence, not a guard. `layerFusable`
  (`cuda/backend.go:53-55`, `:1214-1224`) likewise never looks at `qGate`/`kEqV`.
- `cuda/backend.go:225-244`, `:916-921`: no shape validation of the DeltaNet projections against
  `dnetParams` at build; a mis-sized loader tensor would be an OOB device write, not an error.
  `argmax_reduce` returns −1 for an all-NaN row (`cuda/argmax.cu:22-29`) and `ForwardArgmax` hands

- `cuda/foreign_context_test.go:52-79` uses `nvidia-smi --query-compute-apps`, which lists compute
  contexts; a Wayland compositor holds a graphics/EGL context and may not appear, so the floor gate
  could go red on a desktop again.
- `metal/kernels.go:515`, `:537`: RoPE angle is `float(pos)*invf` in f32 with fast-math `cos/sin`;
  at pos → 4096 the argument is ~4e3 rad and Metal's fast range reduction is not precise there,

- `gpu/decoderunner.go`: `Device.Poll(true)` has no timeout and `Run` never consults a context — a
  wedged adapter hangs the serve worker while holding `lm.mu`; the resident `Forward` runs on the

- `decoder/kvsnapshot.go:218-220`'s bound comment ("each of the pos positions stores ≥1 byte") is

- `decoder/forward_gemma4.go:216` treats a genuine `layer_scalar == 0` as absent; `HiddenLast`

- `docs/task-w4a8-neon-bandwidth.md:98` and `docs/task-oracle-refforward.md:15` cite concrete files
  under aikit's `docs/internal/`, which `CLAUDE.md:169-172` calls a forbidden destination "including
