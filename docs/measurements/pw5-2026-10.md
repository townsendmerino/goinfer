# PW5: Go's test cache for packages with no hidden input — 2026-10-27

The record for PW5 ([`docs/tasks/task-subsystems-2026-10.md`](../tasks/task-subsystems-2026-10.md) §12.2), graded against
PW5-G1–G5, registered there before the code. Measured on the MacBook (M1 Pro, arm64). Raw outputs are in
[`pw5-2026-10/`](pw5-2026-10/).

## 1. What changed

- **The data.** `internal/layout/test_cache.json` classifies all 82 packages of the seven modules. 16 are cacheable; each
  of the other 66 names its hidden inputs. The count of packages with each:

  | hidden input | packages |
  |---|---:|
  | files outside the module | 57 |
  | OS memory | 38 |
  | a subprocess | 37 |
  | timing | 23 |
  | a device | 22 |
  | the whole environment | 9 |
  | the network | 7 |

  A package counts what its own files read, and what the non-test files of every goinfer package it reaches read. So
  `decoder`'s importers carry OS memory: `Load`'s fit guard reads `internal/mem/probe`.
- **The cacheable 16:** `internal/adapter`, `batchio`, `cliutil`, `confidence`, `f16`, `fidelity`, `giw`, `inproc`,
  `kvmgr`, `layout`, `mem`, `movedpaths`, `towerid`, and `demo/agent/cmd/ken-stub`, `demo/agent/internal/embedmodel`,
  `site/cmd/build`.
- **The check.** `internal/layout`'s `TestTestCache_classified` re-scans the tree and fails when the data differs. A
  cacheable package that gains a hidden read fails with its name and the read; `-update` rewrites the data. A `declared`
  section takes hand-added reasons a scan cannot see; it is empty.
- **touched.py** drops `-count=1` for a package the data marks cacheable, and keeps it for every other package, for an
  unlisted one, and for all of them when the data is missing or malformed. Its step line now ends in `cached` when
  `go test` replayed the result.

## 3. The measurement (PW5-G5)

**Setup.**
- The diff `0158bdc0..3d01e4a3`: `decoder` 3 files, `internal/mem` 3, `metal` 1, and the scan tests they select.
- A scratch worktree at `3d01e4a3`, with one commit adding the tool files: the before `touched.py` (from `origin/main`),
  the after one, PW5's `touched_scans.py` for both arms, and the data. The arms differ only in `-count=1`.

**Result.**
- A re-run with nothing changed went from about 133 s (A1–A3) to 124.3 s (B3): about 9 s, 7%.
- A run after an edit that the cacheable tests read saves nothing (B2), as it should.
- The rest of each run is in packages with hidden inputs, which stay uncached:
  - `metal`'s whole suite takes 98–105 s every run: a device, and `touched.py` runs the whole package because `metal` is
    not in its slow list;
  - `decoder`'s selected tests take 13–18 s: OS memory, subprocesses, files outside the module, timing.

**What would move the number further** (not done here):
- `touched.py` runs `metal`'s whole device suite for a change to one `metal` test file. Adding `metal` to its slow
  list, which runs only the tests beside the change, would cut most of this diff's 100 s. That is a selection change,
  not a cache change.
- A `probe.Fake` as `decoder`'s default in tests would remove only one of `decoder`'s five reasons, so it would not make
  `decoder` cacheable.
