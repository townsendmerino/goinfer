## Why this is enough

- **The device code is the same.** The plain PTX of every attention module is byte for byte base's (step 1: all 15 modules rebuilt
  from the edited sources; step 2: `git diff` adds only the six `_cap` files), and G1-K holds 1,864 digests equal to base's. Both arms
  run the same kernels; what could differ is host code only.
- **The host difference is small and fixed.** For a model without a cap: `attnPTX` picks the plain module at load time (not in a
  token loop); `withCap` returns its argument list unchanged when `attnCap` is 0 (one comparison per covered launch); `faEligible` and
  `useAttnFused` gain one comparison each. The two cells that touch every launch path of a token (decode) and of a chunked prompt
  (time to first token) therefore bound it, and both read 1.000 to within their intervals.
- **Dense and sliding-window both ran.** The Gemma 3 4B cells take the windowed `attention`/`attn_batched`/split-KV launches with
  head dimension 256, the geometry Gemma 2 shares; the 1.5B takes the full-attention ones.

## What this does not cover, and how it differs from the registration

- The registration's cells were the 1.5B at depths 128 and 3900, Gemma 3 4B at 128, a 0.5B cell at 128, 4 blocks each. This run has
  no depth-3900 cell and no 0.5B cell: deep decode takes flash-decode or split-KV, whose PTX is identical, and a host difference that
  small does not depend on depth. That is an argument and not a measurement; a depth cell was not run.
- Noise: the 1.5B cell's interval half-width is 0.3%, tighter than the registry's same-binary sd (0.81%) would predict for 4 blocks,
  which is a property of this session and not a new floor.
- A real softcap model is not measured here (G2-P, B28): this is the guard that models without a cap did not get slower.
