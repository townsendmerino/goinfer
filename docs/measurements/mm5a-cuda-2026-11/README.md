# MM5a on CUDA: one list of buffers for the recurrent state (nobara-sb01, 2026-11-06)

The row (`docs/tasks/task-subsystems-2026-10.md`, MM5a) did Metal's recurrent state and batched step, and said "CUDA later". This is CUDA's recurrent state: the buffers of a Gated-DeltaNet or Mamba-2 layer's conv window and matrix/SSM state.

Before: `decoder.Model.StateSpecs` gave the plan's price, and the CUDA build sized the same buffers from its own kernel-geometry formulas (`dnetParams.winFloats` / `stateElems`, `mambaParams.winFloats` / `ssmFloats`) at five places: the live pair's upload, each further slot's pair, the checkpoint's sizing (`recurrentLiveBytes`), the charge (`recurrentStateCharged`) and the reset's zero buffers. Two descriptions of one buffer.

- **Red first** (`red.log`): `TestRecurrentState_everyBufferReadsTheList` moves both list entries (unequally, so a window sized as a state would show) through a `stateSpecsOf` variable and requires every copy to follow: the live pair, slot 1's pair, the checkpoint copy, `recurrentStateCharged`, `recurrentLiveBytes`, the ledger's state line, and a reset that zeroes the whole of each live buffer (filled with ones first). On `qwen35-tiny`, `olmo_hybrid-tiny` and `nemotron-tiny` every size check failed (buffers `[384 1024 ...]` against the moved `[392 1040 ...]`, charged 16,896 against 17,184).
- **Change:** each layer's window and state sizes are read from `stateSpecsOf` once, when the layer is uploaded (`cudaResident.recFloats`, `setRecurrentFloats`; a layer whose list is not a window and a state is a build error), and the five places read them. The kernels' geometry still comes from `dnetParams` / `mambaParams`.
- **Identity** (`green.log`): `TestRecurrentState_listEqualsKernelGeometry`: with the list unmoved, the list's sizes equal the kernels' geometry layer by layer on the same three fixtures, so no buffer changed size. `TestMemGate_cuda` (474 builds, against the plan, 113 s) and the recurrent-slot, checkpoint, Mamba, Olmo and plan tests pass; the `SKIP` lines in the log are heavy-gated tests (`GOINFER_HEAVY_TESTS` unset).
- **Plants** (not committed; `plant-*.log`): the reset zeroing the kernel-geometry size, the live upload one floats-block short, the charge one block short, and the further slots one block short each turn the test red. A first slots plant (`win - win%8`) was a no-op on these sizes (every moved size is a multiple of 8) and went green (`plant-slots-noop-first-try.log`); it was replaced by the `-8` plant, red.
- **`touched.py`** 17 checks and **`cmd/lint`** 7 of 7 pass.
- **Not in this PR:** the CUDA batched/step scratch list (MM5a's second half on Metal) and MM5 itself, which is blocked on OP4.
