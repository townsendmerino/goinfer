# The 413 prefill-share fix, end to end on the 7B at 4 clients, with live memory held in the band — pre-registration, 2026-09-28

The follow-up to [`spec-vs-batching-metal-2026-09-27.md`](spec-vs-batching-metal-2026-09-27.md) §5 and its
"Update 2026-09-27". The fix (5a92348a) was proven by `TestPrepare_prefillShare` only. The end-to-end attempt ran on
a Mac that was already swapping, and both arms' swap guards tripped. **Written before the run.**

## 1. Why a ballast

Admission (`decoder/prefill_budget.go`, `AdmitPrefillMemoryShare`) refuses a request whose prefill needs more than
`available × 0.70 ÷ share`.
- `available` is vm_stat's free + inactive + speculative + purgeable pages (`decoder/hostram_darwin.go`).
- `share` is 1 on the fixed build. On the unfixed build it is up to 4 under 4 clients.
- The need is the prefill scratch: 256 MiB plus 8 × 18,944 × prompt tokens. That is **~0.42 GB for the ~1000-token
  copy prompts**. No host KV is priced on the resident path.

So the builds disagree only when available memory is roughly **0.6–2.4 GB**:
- the fixed build refuses below ~0.6;
- the unfixed build, with 4 in flight, refuses below ~2.4.

Tonight's Mac will have far more than that, and both builds would pass: a run that cannot fail proves nothing.
[`ballast.py`](fix413-e2e-2026-09-28/ballast.py) holds available memory in **[1.0, 1.6] GB**. In that band the
fixed build's margin is 0.70–1.12 GB (admits), and the unfixed build's with 3–4 in flight is 0.18–0.37 GB (refuses).
It is the regime of §5's 09:39 cells, which 413'd without swapping.

The ballast's safety rails:
- it keeps its pages active, or the probe would count them as available;
- it releases everything if swap grows more than 256 MB, or the disk falls under 2.5 GB free;
- it never holds more than 12 GB, and expires after 15 minutes;
- it dies with its driver.

A daytime smoke on a harmless band settled in ~12 s and released cleanly, with no swap growth.

## 2. The run

- **The arms, both built from 33217487 so that they differ by exactly the fix:**
  - `serve-metal-fixed-33217487`, as committed;
  - `serve-metal-unfixed-33217487`, with 5a92348a's one condition reverted
    ([`unfixed.patch`](fix413-e2e-2026-09-28/unfixed.patch)).

  Building both from HEAD also avoids a Sep 27 binary rewriting the 7B's current-format Metal sidecar (~4.4 GB) on a
  disk with ~5 GB free.
- **Model:** Qwen2.5-7B-Instruct Q4_K_M from `~/models`, Metal, int4, the server's default concurrency (4).
- **The workload:** `bench_spec_copy.py`'s batch cell, as in §5: 4 clients × 2 requests of a ~1000-token copy prompt,
  256 max tokens, greedy. The 8 prompt sections are frozen in `sections.json` (sha256 prefix `bc7d4efaeac25f49`, from
  `decoder/model.go` @ cc5f8c2c).
- **Each round and arm:**
  1. load the server;
  2. one warm request;
  3. start the ballast and wait until it has held the band for 10 s (up to 240 s);
  4. run the cell, sampling available memory every second;
  5. stop the ballast, then the server.
- **Order:** 3 rounds (unfixed, fixed / fixed, unfixed / unfixed, fixed). Driver:
  [`fix413_e2e.py`](fix413-e2e-2026-09-28/fix413_e2e.py). Mac night queue, ~35 min.

## 3. The decision rule

- **A round is valid only if all hold:** the ballast settled; it did not abort or expire during the cell; available
  memory stayed within **[0.8, 2.0] GB** throughout the cell; and no request was refused 503 by the swap guard.
- **PASS:** at least 2 valid rounds per arm; the fixed build refused **no** request with 413 in its valid rounds; and
  the unfixed build refused **at least one** with 413 in its valid rounds. The last condition shows the band really
  reproduced §5.
- **FAIL:** the fixed build refused a request with 413 inside the band.
- **NOT DISCRIMINATING:** the unfixed build refused nothing either. The band did not reproduce §5, and the fix is
  neither confirmed nor refuted end to end.
- **INCONCLUSIVE:** fewer than 2 valid rounds for an arm. The usual cause would be the ballast being unable to hold
  the band without swap growth on this machine. That is itself recorded as the finding.
- **Reported, not graded:**
  - whether the fixed build's admitted requests completed (completion tokens);
  - the swap growth during each cell. §5 asked whether the refused requests "would have fit", and swap growth under
    the fixed build is the only evidence against that.
