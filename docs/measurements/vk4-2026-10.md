# VK4: a program fingerprint per family config — 2026-10-26

The record for VK4 ([`docs/tasks/task-subsystems-2026-10.md`](../tasks/task-subsystems-2026-10.md) §5.7), graded
against gates F1–F3, registered there before the code. Tier 0: no model beyond the tiny fixtures, no device, no timed
run. Measured on the MacBook (M1 Pro, arm64) at goinfer main `45346d08` plus this branch. Outputs are in
[`vk4-2026-10/`](vk4-2026-10/).

## 1. What it is

In `decoder/program_fingerprint.go`, which is new; nothing in `program*.go` changed:

- **`programFingerprint`** is a SHA-256 over a program's operations and parameters. A reflection walk writes each
  field's name and value (floats by their bits, slices with their lengths) and no type names.
- **`programForConfigDir`** builds the program from a `config.json` alone. Two inputs that the loader takes from the
  weights come from the config instead:
  - **Which layers carry experts:** layers `[FirstKDense, NumLayers)` of an MoE architecture, or Llama 4's per-layer
    flags.
  - **Whether the head is tied:** `tie_word_embeddings`, at the top level or under `text_config`; where it is absent,
    the adapter's default stands.
- **`testdata/program_fingerprints.json`** holds one fingerprint per committed fixture config that resolves (37), in
  one map per GOARCH. `TestProgramFingerprint_table` holds the map for the architecture it runs on, and `-update`
  rewrites that architecture's map. A gitignored local fixture is not in the table.
- **Why per GOARCH.** A program's float parameters, such as RoPE frequencies, come from math functions whose last bit
  differs between amd64's assembly and arm64's fused multiply-adds. 17 of the 37 programs differ between the two. CI
  found this: the first push, with an arm64-only table, failed on `root-windows` and `test-decoder-tail`, both amd64.
  The amd64 map was generated under Rosetta. Its 17 differing fixtures are exactly the 17 CI named.

## 2. The gates

| gate | result | evidence |
|---|---|---|
| F1 the table | **PASS**: 37 fixture programs; two computations agree | `f1-f2-real-2026-10-26.log` |
| F2 config equals weights | **PASS** on all 36 fixtures whose weights are present here (`mellum21-config` is a config with no weights) | `f1-f2-real-2026-10-26.log` |
| F3(a) refactor-blind | **PASS**: the table computed at `2c7e3c61` (before VK2) and at `f8e248b7` (between VK2's parts) equals this branch's. Both VK2 moves left every program unchanged | run in scratch worktrees; no file |
| F3(b) change-sensitive | **PASS**: `gate mutation` changing `Mscale` in `gemma4AttnParams` (1 → 1.0000001) turns F1 red, and the diff names exactly the two Gemma 4 fixtures (`gemma4-moe-kv-tiny`, `-tiny32`) | `f3-mutation.log`, `f3-mutation-diff.txt` |

**F2 caught one difference before it passed.** The first run found `smollm3-tiny`'s config program untied and its
loaded program tied. The loader ties the head when the checkpoint has no `lm_head` tensor, while the adapters leave it
false until load. Reading `tie_word_embeddings` from the config closed it, and all 36 then matched.

**F3(b) used a different parameter from the registration.** The registration named the v-norm epsilon in
`gemma4LayerOps`. The plant changed `Mscale` in the same parameter literal (`gemma4AttnParams`), one field over. It is
the same kind of test: one parameter, in one family's layer ops.

- **Six families have neither on this Mac:** gpt-oss, gpt2, granitemoehybrid, laguna, qwen2 and qwen2_moe.

## 4. What it does not do yet

The fingerprint is not in any key. VK5's shadow key replaces only `aikit_version`, and SD6's week of that shadow key
started at its first run on main (2026-10-26). Putting program fingerprints into the shadow key, in place of `core`'s
source files, changes what the shadow week measures. Francis (16:27) chose two weeks: this week grades the
`aikit_version` swap alone, and a second shadow week grades the key built from program plus kernel fingerprints, with
the forward source files out of it.
