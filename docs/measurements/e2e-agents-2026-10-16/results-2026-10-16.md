## Readings

- **All three agents start from `connect -write` and run end to end.** The caveat is closed: each configured, sent requests, used tools and finished tasks on a Mellum2.1 server on the 8 GB card.
- **A session's second and later starts restore a snapshot** (opencode and Codex): session-start TTFT falls from 84 s and 63 s to 5.6 s and 0.3 s. The 22,464 and 18,240 rows are three restores of 7,488 and 6,080 rows.
- **Claude Code gets no restore and is the slow agent.** Every session start and 3 of its 5 follow-ups re-prefill 18 to 20k tokens from nothing, about 198 s each (`reused=0`; `div` 16,312 to 18,262 of prompts of 18.2 to 20.3k). The prefix is shared to within a few thousand rows of the end, but the windowed-KV layers hold 1,536 positions and roll back 448, so none is reusable (the limit the 2026-10-15 side-requests record gives). Its `edit` run spent its 1,200 s on five such prefills.
- **Failures, none new in kind:**
  - Codex `edit`: 37 tool calls, 3 compactions, 900 s limit; the last message is prose about `apply_patch` (the pattern I3's Codex x Mellum record names).
  - Claude Code `search`: the reply is a literal `<tool_call>` text block naming an `Agent` tool, not an answer.
  - Claude Code `edit`: 8 turns, 4 tool calls, 2 compactions, timed out.
- **Fast alias:** opencode sent 3 requests to `mellum2.1-thinking-fast` (its titles); Codex and Claude Code sent none.
