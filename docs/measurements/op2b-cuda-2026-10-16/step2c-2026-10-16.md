## What changed

- `cuda/mamba_resident.go`: `recurrent()` (`r.dnet != nil || r.mamba != nil`), `batchedVerifyOK()`, `mambaStateBytes`.
- The sites that tested `r.dnet` now read `recurrent()` or say why not:

| site | after | why |
|---|---|---|
| `batchstep.go` `BatchStepRange` | `recurrent()` | state is not in a slot |
| `kvsnap.go` `snapshotDecline` | `recurrent()` | the same |
| `kvcopy.go` `CopyKV` | `recurrent()` | the same |
| `resident.go` `ForwardN` and `VerifyPath` | one helper, `batchedVerifyOK()` | the verify pass runs one token at a time; one answer for both |
| `resident.go` `Reset`, `resetState` | done in 2b | clear the Mamba state with the slot |
| `prefill.go` fast-lever switch | `recurrent()` | not reachable for Mamba (below); kept equal to DeltaNet's |
| `prefill.go` DeltaNet scratch (`dnPrefillBufs`) | unchanged | DeltaNet's own batched buffers; Mamba never batches |

- **The batched prefill declines a Mamba-2 mixer and a feed-forward-only block by name** (`nonBatchableKind`). Before this it declined them by accident: their q, k, v weights are absent, which reads as "absent/unquantized". (The registration said the batched prefill declines a recurrent family "as for DeltaNet"; DeltaNet in fact runs batched, `prefillDeltaNetRows`.)
- **The plan prices the Mamba state** (`resolveCtxCapFitSlack` is given `mambaStateBytes` beside the packed-allocation slack). The KV price itself needed no change: a Mamba or feed-forward-only block reports zero KV geometry, so both the build's `kvBytesForCap` and the decoder's `ResidentKVBytes` already skip it. DeltaNet's state is still not priced in the plan (not registered here; its models' plans are unchanged).
- `batchStepStaticDeclineOffForTest`: a test seam, so gate G can see `BatchStepRange`'s own recurrent check; the batched-prefill decline behind it also refuses a Mamba-2 model and would hide a guard left DeltaNet-only.
