# OP2b on CUDA, step 1: the Mamba-2 kernels and the squared-ReLU quantize (2026-10-16)

Registered in `docs/tasks/task-forward-architecture-2026-10.md` §4.7, "OP2b on CUDA". nobara-pc, RTX 2070 SUPER, driver 595.91.07, every GPU run under
the timing lock. Base is `cb9ed9f4` (main with the registration), the kernels are `367bf014` and `f5e74daf` on branch `op2b-cuda-step1-2026-10`.
**Nothing reaches the kernels yet and nothing is declared:** no pipeline binds them, Nemotron-H still runs on the CPU on CUDA.

## What was built

`cuda/mamba.cu` (`mamba_conv`, `mamba_ssm`, `mamba_gnorm`) and `cuda/nongated_act.cu` (`relu2_quant`), new files with new PTX
(`testdata/mamba.ptx`, `testdata/nongated_act.ptx`, ambient NVRTC 12.9.86). No ordinal was added to `glue.cu`, `prefill_batched.cu` or `actgroup.cu`, so no
existing PTX moves. Every float multiply and add is an explicit unfused intrinsic, as the CPU reference does on amd64 and as `TestKernelFMALint`
requires (both files joined its list); the gated norm accumulates its sum of squares in f64, like `decoder.gatedRMSNormGrouped`.

the log is `~/goinfer-bench/op1-cuda-2026-10/op2b-plants.log`). After the three, the sources and PTX equal git and K is green again.
