## What changed

- `cuda/mamba_resident.go`: the Mamba-2 geometry and its declines by name (Granite-4.0-H, an int8 load), the per-layer packing, `mambaMixer` (pre-norm, in_proj, `mamba_conv`, `mamba_ssm`, `mamba_gnorm`, quantize, out_proj accumulating into the residual), `nonGatedMLP` (up GEMV, `relu2_quant`, down GEMV), `resetMambaState`.
- `cuda/backend.go`, `cuda/resident.go`: the builder packs and uploads a Mamba block's own weights, an MLP-only block's `u` and `d`, and nothing a block does not have; a Mamba or MLP-only block reports zero attention geometry and holds no KV; `launchToken` dispatches those two kinds; `segB` stops after the o-projection for an attention block with no feed-forward; attention in Nemotron-H takes an all-zero rope table (identity rotation, as WebGPU's); `Reset` and `resetState` clear the Mamba state with the slot; graphs are off for it; one KV slot. Nemotron-3-Nano's MoE blocks decline (the decoder's admission says so first).
- `decoder/testhooks.go`: `SetResidentFeaturesForTest`, which adds features to a backend's declared set for a test's duration. The three Nemotron-H features (`ssm`, `non-gated-mlp`, `non-gated-relu2`) are NOT in `residentBackendFeatures`; the tests add them. Under `goinfer_testhooks` only.

## Not done here, on purpose

- **Step 2c** (registered): the recurrent guard sites still test `r.dnet`: the batched step, the prefix snapshot, the KV copy, both prefill sites, `ForwardN` and `VerifyPath`. A Mamba resident therefore passes them where it must decline; this is why nothing is declared and why the tests drive `Forward` token by token. 2c reads them as "recurrent" with gates G and P.
- **State pricing**: the Mamba state (about 88 MiB on the 4B) is allocated before `checkKVFits` reads free VRAM, so the KV plan sees it as used; the pre-build context plan does not price it. P is 2c's.
- **Gate F** and tier 1 follow the declaration path, after 2c and 2d.
