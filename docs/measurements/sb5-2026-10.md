# SB5: engine policies over a Forward interface — 2026-10-27

The record for SB5 ([`docs/tasks/task-subsystems-2026-10.md`](../tasks/task-subsystems-2026-10.md) §8 SB5), graded
against gates SB5-P1–P5, registered there before the code (commit `477533f1b`). Tier 0, CPU only, on mbp2 (Intel i5,
Linux amd64, 16 GB), from goinfer main `4c7cd4a0`, with origin/main merged before the PR.

## 1. What the code was

Every engine policy is a method on `*Model` over a concrete `*KVCache`:
- `GenerateSpeculative` (a draft model);
- `genNgramInto` (n-gram, fixed and adaptive, with resident and MC3 batch paths);
- `genGrammarInto` (grammar, CPU only);
- the session methods (resume, rewind, prefix copy) and prefix reuse.

The only model interface is the resident one (`ResidentForward`). Most "speculative equals plain greedy" parity tests load
a bench checkpoint (`GOINFER_PREQUANT_GGUF`) that CI's `ci.yml` does not download: only `release-assets.yml` does, so
per push they skip. Neither MTP nor a production tree verify exists.

## 3. The first move: grammar speculation over `Forward` (P3, P4, P5)

- **`Forward`** (`decoder/policy_forward.go`) is `Prefill`, `Verify` and `TruncateTo`. **`cpuForward`** implements it
  over `*Model` and `*KVCache`.
- **`genGrammarInto`** keeps its signature, builds its cache exactly as before, and runs **`grammarSpecLoop`**: the same
  loop as a function over `Forward` and a stop predicate. It is one path, not a second.
- **`scriptedForward`** (`decoder/policy_fake_test.go`) is a fake whose logits are a hash of the token history (all of
  it, the last token, or the last three). Every rollback is therefore a branch point: a wrong truncation changes every
  later row. It also refuses a truncation past what it holds.

|---|---|
| P3 | `TestGrammarSpecLoop_exactOnTheFake`, 216 cases in 6 s: 3 scripts × maxTokens 5 and 64 × K 1, 3, 8 × drafters (the grammar's own, an oracle that is always right, always wrong, wrong at each depth 0 to 7, drafting past the grammar's end), each equal to constrained greedy on the fake. Red once each: a rollback one short, the mask skipped on a draft, an acceptance at depth 1 regardless. The last one first survived, because no drafter was wrong at depth 1 (always-wrong is rejected at depth 0), so wrong-at-every-depth was added before grading |
| P4 | the census reproduces unchanged through the move, with the golden unedited |
| P5 | `TestPolicyTests_loadedRatchet` lists the 37 policy tests that load a model (38 before). `TestGrammarSpecParity` was removed: its claim now runs per push on the fake, and the census holds grammar speculation through a real model. ## 4. Second move: draft-model speculation over `Forward` (P3, P4, P5)

- **`Forward` gained `Step`,** a single token's forward. The draft model steps with `m.forward` on the CPU, which may
  round differently from a one-id `forwardN`, so the policy keeps using the call its plain path uses.
- **`residentForward`** implements `Forward` on a resident backend: positional, tracking its own position, and
  prefilling a fresh context only (the one way the policies prefill there).
- **`GenerateSpeculative`** builds a `Forward` for the target and one for the draft (CPU or resident each, as before)
  and runs **`draftSpecLoop`**, the same loop as a function over the two.

| gate | result |
|---|---|
| P3 | `TestDraftSpecLoop_exactOnTheFake`, 123 cases in 1 s. The targets are three scripts, one stopping at history 20. The drafts are the target itself, an unrelated model, and the target wrong at every 2nd, 3rd or 5th position. K is 1, 2, 4 or 8 and maxTokens 3 or 40, and every case equals greedy decoding. With a context cap, each stream is a prefix of the uncapped one and the target never holds more than the cap. Red once each: the target's rollback one short, an acceptance at depth 1 regardless, the bonus token from the wrong row, the draft not rolled back, the draft's catch-up step with the wrong token. The last two keep the stream exact: a draft out of step only drafts worse. So they first survived, and were caught by two checks added before grading: the target as its own draft must have every draft accepted, and the draft and target must end holding the same history |
| P4 | the census reproduces unchanged, the draft-attnfa and draft-self streams and their counters included |
| P5 | the ratchet's scope widened to `speculative*_test.go`, an explicit change of definition in this commit, which adds three entries (40 listed). ## 5. Third move: n-gram speculation over its target hooks (P3, P4, P5)

The n-gram loop carries more than the others: argmax-only verifies a resident backend computes on device, one-token
verifies through the MC3 batcher on a round that yields to other sessions, and the batcher's exclusive claim. A plain
`Forward` cannot say all of that, and a CPU-only copy of the loop would be a second path.

- **What moved.** The loop is lifted out of `genNgramInto` unchanged as **`ngramSpecLoop`**, over **`ngramTarget`**: a
  struct of the hooks the loop calls (verify, argmax-only verify, batch verify, truncate, resident commit, stop test,
  context cap, and the adaptive claim, release and exclusive section).
- **How the hooks are built.** `genNgramInto` sets each hook to the closure it already had. The fake builds them over a
  `scriptedForward`.
- **Who owns the position.** The loop owns `tpos`; the truncate hook only truncates.

| gate | result |
|---|---|
| P3 | `TestNgramSpecLoop_exactOnTheFake`, 792 cases in 0.1 s, each equal to greedy decoding. Targets: three scripts on a 32-token vocabulary, one stopping at history 25. Drafters: the real `NgramDrafter`, an oracle, always wrong, wrong at each depth 0 to 7. K 1, 3 and 8; maxTokens 4 and 48; full-logit and argmax-only verifies; with and without adaptive depth. The fake's verify hook checks that every position it is given is the one it holds. Red once each: an acceptance at depth 1 regardless, the rollback one short, the bonus token from the wrong row, and the argmax-only path's bonus from the wrong row |
| P4 | the census reproduces unchanged (n-gram K1/4/8, adaptive, sampled, and the n-gram session). The resident, MC3 and adaptive tests that run on mbp2 all pass through the move: `TestGenNgramInto_residentReusesWarmPrefix`, `_residentCommitMatchesPlain`, `TestSpecAdaptiveSwitch_*`, `TestMC3_*`, `TestSpecDecodeConflict_*`, `TestGenerateNgramSpeculativeAdaptive_costOnlyWhenGreedy` |
| P5 | the ratchet stays at 40. `TestNgramSpeculativeGreedyParity` and `TestNgramAdaptiveGreedyParity` were kept: on a real checkpoint they are also evidence that the batched verify equals sequential decoding (the SDE AVX-512 run in `docs/measurements/sde-2026-10-04/README.md` ran them), which the fake cannot give. The code comments now name the fake test as the policy's proof and these as the checkpoint's |

**Sampled n-gram speculation** goes through the same loop, and the census holds its seeded streams. Its claim is lossless
in distribution, which a stream equality cannot test; a distributional check on the fake is still to do.

## 6. Fourth move: the session policy (P3, P4, P5)

A session's own policy is two decisions over its KV: how much of a new prompt the live KV keeps (rewind for reuse), and
what the session records after a turn (reconcile). Both are now pure functions:
- **`sessionRewind(tokens, prompt, clean, adapterChanged, truncate)`** and
- **`sessionReconcile(pos, seq, recurrent, truncate)`**.

`Session.rewindForReuse` and `Session.reconcile` call them, so there is one path, and reconcile's guardrail comments
moved with the code. The decode a session runs is `generateInto`, which stays where it is (§7).

| gate | result |
|---|---|
| P3 | `TestSessionPolicy_exactOnTheFake`: seven turns on one fake KV (cold, resume, the same prompt again, a rewind to a shorter prefix, a divergence, a turn cut off mid-write, the turn after), each turn's stream equal to cold decoding of its prompt and the session's tokens always equal to the KV's contents. It runs on three KVs: plain, a ring cache that cannot truncate exactly below a 6-token window, and recurrent state. The paths it exists for are asserted to be taken: a resume reuses 19 of 22 tokens; the ring cache's short rewind falls back to cold; the cut turn's record rolls back to what the KV wrote (plain) or resets (recurrent). Red once each: the rewind one long, an inexact rewind trusted, a recurrent rollback trusted, the rolled-back tail kept |
| P4 | the census reproduces unchanged (session resume, rewind, copied prefix, n-gram session), as do the session tests that run on mbp2 |
| P5 | the ratchet stays at 40. `TestSession_reuseParity` and `TestSession_snapshotRoundTrip` run real sliding-window ring caches on a real checkpoint where one is present, which is KV evidence the fake cannot give |

## 7. What is next

- **The plain decode loop.** `generateInto` (685 lines) interleaves the CPU decode with about a dozen resident fast
  paths: greedy chains, device top-k and sampling, MC3 batch greedy, optimistic forward. Lifting it the way n-gram was
  lifted would put each behind a hook that mbp2 can check only through fakes. Its CPU path is covered by every census
  stream as the reference. Moving it is a step for a box that can run the resident paths (nobara or the Mac).
- **Prefix reuse.** The resident slot reuse (`resident_reuse.go`, `internal/kvmgr`) is bookkeeping already tested
  without a model. The CPU prefix checkpoint (`prefix_share.go`) is about hidden states, not token streams.
- **Sampled speculation** needs a distributional check on the fake.
- 40 tests are on the ratchet.
