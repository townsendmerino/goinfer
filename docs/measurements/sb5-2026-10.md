# SB5: engine policies over a Forward interface — 2026-10-27

The record for SB5 ([`docs/tasks/task-subsystems-2026-10.md`](../tasks/task-subsystems-2026-10.md) §8 SB5), graded
against gates SB5-P1–P5, registered there before the code (commit `477533f1b`). Tier 0, CPU only, on mbp2 (Intel i5,
Linux amd64, 16 GB), from goinfer main `4c7cd4a0`, with origin/main merged before the PR.

## 1. What the code was

Every engine policy is a method on `*Model` over a concrete `*KVCache`:
- `GenerateSpeculative` (a draft model);
- `genNgramInto` (n-gram, fixed and adaptive, with resident and MC3 batch paths);
- `genGrammarInto` (grammar, CPU only);
- the session methods (resume, rewind, prefix copy) and prefix reuse.

The only model interface is the resident one (`ResidentForward`). Most "speculative equals plain greedy" parity tests load
a bench checkpoint (`GOINFER_PREQUANT_GGUF`) that CI's `ci.yml` does not download: only `release-assets.yml` does, so
per push they skip. Neither MTP nor a production tree verify exists.

## 2. The census (P1, P2)

`TestPolicyStreams_census` records 38 token streams in `testdata/sb5/policy_streams.json` and holds each exact policy's
stream to its plain-decoding reference. The fixtures are llama-tiny, llama-attnfa-tiny as a draft model, and a
byte-level vocabulary (token *i* is byte *i*) so a real grammar mask runs without a tokenizer. It takes 0.4 s.

| cases | acceptance seen |
|---|---|
| plain greedy, 3 prompts | — |
| n-gram K1, K4, K8 and adaptive, 3 prompts | partial on p1 (e.g. 6 of 8 accepted), full on p0 and p2 |
| draft model llama-attnfa-tiny K4 | none: 92 drafted, 0 accepted (every rejection path) |
| the target as its own draft, K4 | all: 20 of 20 |
| grammar speculation K1 and K8 vs constrained greedy | the grammar's forced bytes |
| session: resume (79 reused), rewind (20), copied prefix (16), n-gram session resume | — |
| seeded sampling, plain and n-gram | recorded, not compared: sampled speculation is lossless in distribution, not in stream |

**P2 PASS:** each planted change turns the census red:
- n-gram accepting depth 0 regardless;
- a draft-model rollback one short;
- the grammar mask skipped on a draft;
- a session rewind one long.

## 3. The first move: grammar speculation over `Forward` (P3, P4, P5)

- **`Forward`** (`decoder/policy_forward.go`) is `Prefill`, `Verify` and `TruncateTo`. **`cpuForward`** implements it
  over `*Model` and `*KVCache`.
- **`genGrammarInto`** keeps its signature, builds its cache exactly as before, and runs **`grammarSpecLoop`**: the same
  loop as a function over `Forward` and a stop predicate. It is one path, not a second.
- **`scriptedForward`** (`decoder/policy_fake_test.go`) is a fake whose logits are a hash of the token history (all of
  it, the last token, or the last three). Every rollback is therefore a branch point: a wrong truncation changes every
  later row. It also refuses a truncation past what it holds.

| gate | result |
|---|---|
| P3 | `TestGrammarSpecLoop_exactOnTheFake`, 216 cases in 6 s: 3 scripts × maxTokens 5 and 64 × K 1, 3, 8 × drafters (the grammar's own, an oracle that is always right, always wrong, wrong at each depth 0 to 7, drafting past the grammar's end), each equal to constrained greedy on the fake. Red once each: a rollback one short, the mask skipped on a draft, an acceptance at depth 1 regardless. The last one first survived, because no drafter was wrong at depth 1 (always-wrong is rejected at depth 0), so wrong-at-every-depth was added before grading |
| P4 | the census reproduces unchanged through the move, with the golden unedited |
| P5 | `TestPolicyTests_loadedRatchet` lists the 37 policy tests that load a model (38 before). `TestGrammarSpecParity` was removed: its claim now runs per push on the fake, and the census holds grammar speculation through a real model. Red once each: a listed test that no longer loads, and a new loading test not listed |

## 4. What is next

The draft-model, n-gram, session and prefix-reuse moves come in batches, each onto `Forward`. n-gram and draft-model
speculation carry resident and MC3 batch paths beside the CPU one, so their move needs `Forward` to cover the resident
seam (`ResidentForward.ForwardN`, argmax-only verify) as well. 37 tests are on the ratchet.
