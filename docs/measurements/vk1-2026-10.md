# VK1: a numerics fingerprint of the aikit kernels goinfer calls — 2026-10-26

The record for VK1 ([`docs/tasks/task-subsystems-2026-10.md`](../tasks/task-subsystems-2026-10.md) §5.4), graded against
the gates registered there before the code (K1–K3). Tier 0 throughout: no model, no device, no timed run. Measured on
the MacBook (M1 Pro), arm64 natively and amd64 under Rosetta with `ROSETTA_ADVERTISE_AVX=1`, against aikit v1.75.0 on
goinfer main `4a91080e` plus this branch. Every build and test held the timing lock shared. The outputs are in
[`vk1-2026-10/`](vk1-2026-10/).

## 1. The instrument

`internal/kernelprint` (contract in its `doc.go`, design in `docs/code-notes/internal-kernelprint.md`). `Compute` runs
65 kernels on arm64 (64 on amd64, where the .giw row4 repack does not exist): the `linalg` and `embed` functions and
`WeightMat` kinds goinfer's production code calls, over a generated suite (M=1 and M>1 across the 2-, 4- and 32-row
tiles; K and N tails; the f32 kernel's 768 k-tile and 2048 packing threshold; aikit's default Workspace threshold, an
always-parallel one and goinfer's two decode thresholds; per-row and per-32 activations; K below one int4 group and
ragged last groups; every int4 layout goinfer loads; every GGUF type the reader dequantizes; safetensors F32, F16 and
BF16). It returns one SHA-256 of the output bits per kernel, under a configuration: GOARCH, the active tiers and the
forced fallbacks. `freshDepsHash` and the parity manifest are unchanged (VK5 is the shadow mode).

**K3 can go red** (`go run ./cmd/gate mutation`, `k3-gate-mutations-2026-10-26.log`): dropping K=16 from the per-32
shapes leaves `dotW4A8`'s `K >= 32` fallback unexecuted and turns K3 red; a production source naming
`linalg.HammingRows` (a function `uncalled` says goinfer never reaches) turns it red too. Both green after restore.

Building the suite against the gate turned up four things the first draft missed, now in it: goinfer passes `MatmulBT`
(not `MatmulBTInto`) as `AttendTileFused`'s matmul; `internal/whisper` calls `SoftmaxRowContractInto` in place; the .giw
reader's `WrapInt4Row4OnlyF16` declines shapes and cores that cannot run row4; and goinfer's int4 weights take any
`cols`, so K below one group and ragged last groups occur.

## 3. Findings

- **embed's AVX2 Q4_K and Q6_K dequantizers have a pure-Go fallback that no machine here and no CI cell runs.**
  `embed/gguf_dequant_q4k_amd64.go` declares its own `hasAVX2 = cpu.X86.HasAVX2`, and no `aikit_*` tag turns it off, so
  `aikit_noavx2` leaves it on. K3 reads embed's flag from the detected CPU so as not to demand what no tag can reach.
  The census (`docs/hardware-coverage.json`, `cpu-amd64-no-avx2`) lists only linalg's files for the fallback side.
  The fix is aikit's (a forcing hook for embed); until then, an amd64 CPU without AVX2 is the only place it runs.
- **A fingerprint is per configuration, and it has to be.** Of the 65 kernels, 48 give the same bits in all five
  configurations (every quantizer, conversion, f64-accumulated attention kernel and dequantizer). 16 differ by
  architecture or tier: the f32, 16-bit, Q4_K and int8 matmuls, `Dot` and `AttendTileFused` between arm64, amd64 AVX2
  and amd64 without AVX2; and the W4A8 int4 kernels between arm64 with and without DotProd too (the forced-fallback CI
  cells grade the goldens that pin one path by a closeness bound for the same reason). The 65th,
  `linalg.RepackW4A8Row4`, exists on arm64 only. `fingerprints-*-2026-10-26.json` hold all five.
- **The split-half int4 layout is fingerprinted though production never builds it** (`w4a8SplitHalfRepackEnabled` is
  set only by tests); the code notes say why it stays in.
- **Not covered:** aikit's `vision` and `audio` towers (Track AX moves them into goinfer), and the AVX-512 VNNI tier,
  which no machine here has. K3 reports any configuration it was not validated under instead of failing on it, so an
  AVX-512 runner in CI's pool does not turn the gate intermittent.

## 4. What it would have saved (VK0's window)

[`aikit_sweep.py`](vk1-2026-10/aikit_sweep.py) built the suite against each of the 37 aikit versions goinfer pinned in
VK0's window, on arm64 and on amd64, and [`sweep_report.py`](vk1-2026-10/sweep_report.py) joined the result with VK0's
per-commit records (`aikit-sweep-report-2026-10-26.txt`; 2 min 43 s for 74 builds):

- The suite builds against **v1.70.0 to v1.75.0** (9 versions); before v1.70.0 aikit has no bfloat16 API
  (`BF16ToF32`, `QuantizeBF16`), so the 28 older transitions are not comparable.
- **All 8 comparable bumps left every fingerprint unchanged on both architectures.** Five of them changed `linalg` or
  `embed` source (v1.70.1 the NEON bf16 widen, v1.70.2 `quant.go` and `weightmat.go`, v1.71.0 `safetensors.go`, v1.73.0
  the blocked Q8 span, the v1.74.1 pseudo-version `gguf_q4k.go`) and changed no output bit; three changed neither
  package.
- In those 8 transitions, **9 commits had the aikit pin as their only trigger, for 385 family re-stalings: a key with
  the kernel fingerprint in place of `aikit_version` would have re-staled none of them.** Across the whole window the
  pin was the only trigger of 38 commits and 1,553 re-stalings (VK0 §3); the 28 transitions before v1.70.0 cannot be
  graded with this suite.
- One bump in the window did change numerics on purpose: v1.50.0 (int4 group scales as binary16), which moved the int4
  goldens (`2669bf11`) and two families' recorded metrics (`e89ae216`). It is before the comparable range, so this
  sweep cannot show the fingerprint catching it; K2 is the evidence that it would.
- The caveat from §3 holds for the savings: several of the bumps carried tower changes (vision and audio), which the
  fingerprint does not see. Until Track AX moves the towers, a key that drops `aikit_version` needs the towers'
  fingerprint as well for the families that run them.

## 5. Amended 2026-10-26 (mac-ax01, Track AX step AX1)

AX1 copied the towers into goinfer (`internal/vision`, `internal/audio`; `docs/measurements/ax1-2026-10/README.md`), so
the `linalg` entry points only they call became entry points goinfer's production code calls, and K3 went red on
`uncalled`'s claim that goinfer never reaches `SiLUContractInto`, `GELUContractInto` and `GELUTanhContractInto`. `Compute`
now fingerprints the five entry points only the towers name: those three, `SoftmaxRowScaledContractInto` (the Whisper
encoder, in place) and `AttendTileFusedContractExp` (the ViT towers, `AttendTileFused`'s suite through the contract
exponential); the three `uncalled` entries are gone. That makes 70 kernels on arm64 and 69 on amd64. K1 and K3 PASS on
arm64 (14 sites: 8 reached, 6 excluded, 0 unreached, as before: the contract kernels' census sites are amd64's) and on
amd64 AVX2 under Rosetta (41 sites: 24 reached, 17 excluded, 0 unreached; 20 and 21 in the table above). The other four
configurations and K2 were not re-run. The towers' own numerics (their Go code, not the aikit kernels they call) are
goinfer source from AX1 on, so the "not covered" caveat in §3 now concerns only that the parity key must see them as
goinfer code, which VK2–VK5 do.

## 6. AVX-512 under SDE (2026-10-26, nobara)

K1 and K3 on the AVX-512 tiers, which neither box has, under Intel SDE 10.13.1 on nobara (Ryzen 7 3700X, linux/amd64),
Go 1.27.3, goinfer `origin/main` `eee90c011`, aikit v1.75.0. This is a correctness run, not a timed one: it held the timing
lock shared and started only once the lock was free of timed runs. The outputs, the run script and the harness patch are
in [`vk1-2026-10/sde-2026-10-26/`](vk1-2026-10/sde-2026-10-26/).

**What SDE's chips give.** aikit's dispatch has one AVX-512 tier, VNNI (`avx512vnni`, plus `avx512vnni+vl`). `-clx`, `-icx`,
`-spr` and `-gnr` all read `amd64[avx2,avx512vnni,avx512vnni+vl,f16c,popcnt]`. `-skx` (AVX-512 without VNNI) reads
`amd64[avx2,f16c,popcnt]`, the AVX2 tier. With the `aikit_noavx512` tag, a VNNI chip reads
`amd64[avx2,f16c,popcnt] forced=noavx512`. That tag's K3 was VOID in §2 because it forced nothing on a CPU without
AVX-512; here it forces the VNNI tier off.

**How K3 ran.** K3 skips a configuration missing from its `validated` list, and its coverage child runs `go test`, which
under SDE puts the whole Go toolchain under emulation. A first pass that did exactly that was unreliable. On `-icx` it
passed. On `-spr` it reported both VNNI-true sides unexecuted (`dotI8`'s `hasAVX512VNNI` branch and
`(*WeightMat).RepackInt4SplitHalf`'s VNNI+VL early return) in 7.8 s, against 36 s on `-icx`, which suggests the coverage
child ran natively. Its noavx512 pass hung for 18 minutes inside `go test` with pin logging
`ptrace_intercept_execve_and_check_result - waitpid failed`, and was stopped (`run-v1.log`, `v1-k3-spr.log`).

The pass recorded here keeps the toolchain out of SDE, through a local test-only patch that was not committed
(`sde-harness.patch`). It adds the two configurations to `validated`. When asked, `coverChild` runs a natively built
`-cover` test binary (the same `-covermode=set` and `-coverpkg` as the committed child) under its own `sde64 -<chip>`,
while the K3 parent runs under `sde64 -no-follow-child -<chip>`. The patch also logs **the configuration the coverage
child itself reports**, so a child that escaped the emulator cannot pass silently, and every site's status.

**The control.** By the committed path, natively: K1 PASS and K3 PASS, 41 sites, 24 reached, 17 excluded, 0 unreached, as
in §5. Through the harness under `-hsw`, the child reports `amd64[avx2,f16c,popcnt]` and the counts are the same:
24, 17, 0.

| configuration | chips (runs) | K1 | K3: sites / reached / excluded / unreached | coverage child's own config |
|---|---|---|---|---|
| `amd64[avx2,avx512vnni,avx512vnni+vl,f16c,popcnt]` | `-icx` ×2, `-spr` ×2, `-clx` ×1 | PASS, 69 kernels, every run; one Compute 10.8–13.9 s under SDE | **PASS** every run: 41 / 25 / 16 / 0 | the same VNNI config, every run |
| `amd64[avx2,f16c,popcnt] forced=noavx512` | `-icx` ×2, `-spr` ×2 | PASS, 69 kernels | **PASS** every run: 41 / 24 / 17 / 0 | the same, every run |
| `amd64[avx2,f16c,popcnt]` (AVX-512F, no VNNI) | `-skx` ×1 | PASS, 69 kernels | **PASS**: 41 / 24 / 17 / 0 | the same |

**Which dispatch paths ran under VNNI.** Against the AVX2 tier, the sites whose verdict changes are these (the full
per-site list is in `k3-icx-1.log` and `k3-hsw-control-1.log`, the `SDEHARNESS site` lines):

- Reached on their VNNI side: `dotI8`'s `hasAVX512VNNI` branch (the VNNI int8 dot); `w8a8TileRect`'s early return
  (`hasAVX512VNNI`: no AVX2 W8A8 tile); `w4a8TileRows`'s early return (`hasAVX512VNNIVL`: no AVX2 W4A8 tile);
  `(*WeightMat).RepackInt4SplitHalf`'s early return (VNNI+VL builds no split-half layout); and the decided sides of
  `dotW4A8F16Row` and `w4a8BatchOp`.
- Not reached, each covered by an exclusion already in `census_test.go`, keyed to the verdict it now has:
  `disableTopTier`'s AVX-512 branch (SelfCheck's repair, which runs only when a kernel disagrees with its reference);
  `w4a8SplitHalfTileRows`'s and `w4a8GroupedFastRowsQ`'s `true` sides (no split-half layout exists, because
  `RepackInt4SplitHalf` declines on VNNI+VL); and the four split-half wrappers (`uncalled`).

So the exclusions written for the other tiers already cover VNNI, and no new one was needed. **What K3 lacks for these
tiers is only the two `validated` entries**, which this run did not commit; adding them is a code change for whoever owns
VK1. Under `forced=noavx512`, every site has the same status as on the AVX2 tier.

**K1 and the fingerprints.** Every run of K1 passed: two Computes in one process agree on every kernel. Across runs and
chips the fingerprints group exactly by configuration:
- 7 files under the VNNI config (`-clx`; `-icx` and `-spr`, three each across both passes) agree on all 69 kernels.
- The 6 under `forced=noavx512` agree on all 69.
- `-skx`, native AVX2 (twice) and the 6 noavx512 files also give the same bits on every kernel.
- VNNI against AVX2: **5 kernels differ, all W4A8 int4**: `linalg.MatmulBTW4A8Batch`, `linalg.MatmulBTW4A8F16Into`,
  `linalg.MatmulBTW4A8F16Pre`, `linalg.WeightMat(int4).MatmulBTW4A8Into` and
  `linalg.WeightMat(int4).MatmulBTW4A8PreInto`. That is the same split goinfer's int4 decode golden already makes with
  its `amd64-vnni` key. The W8A8 int8 kernels give the same bits with VNNI as without.
- The two new fingerprint sets are `fingerprints-amd64-avx512vnni-sde-2026-10-26.json` and
  `fingerprints-amd64-noavx512-sde-2026-10-26.json`.

Wall time: about 10 minutes for the recorded pass (22:08 to 22:19 PDT); one Compute under SDE (9.8–14.6 s) takes about 4–6× its native
2.4 s on this box.
