- **Pure?:** yes when that function takes parsed data and does no exec, clock, environment or file I/O (it may print to

## 2. The goldens (SB12-C2)

`testdata/gate/goldens/<case>/` holds a recorded input and `want.txt`, the verdict today's grader gives on it.
`TestGraderGoldens` regrades each case from its recorded inputs alone. The cases are:
- the committed records, copied into the case where their directory grows, read in place where they are a dated
  campaign;
- streams recorded on mbp2 at `ce469e379`.

The graders read git through the case: `-update-goldens` captured every lookup (a tree, an object, a diff) with real git
into `case.json`, and a normal run answers from that recording and fails on a lookup it did not record. So the goldens
run on CI's shallow checkouts, and a grader that reads anything outside its record is caught.

## 3. Found on the way

- **`gate heavy -stream` has never counted a replayed stream.** In `-stream` mode `run` stores the events under an empty
  cell name and tallies the cell named by the stream's path, so every count is 0 and the verdict is RED "nothing
  actually ran". The live run of `heavy-narrowed` was GREEN (1 pass, 2 skip); its replay of the same stream was RED.
  `census -stream` is unaffected: `reportCensus` does not tally by cell.
  - No live verdict was ever wrong. The replay is, and it is the one replay `heavy` has.
  - The fix is the heavy family's step: the run record names its cells.
- **`TestProcSampler_findsTheTestBinaryUnderItsParent` fails on mbp2 alone, on `origin/main` as well.** It copies
  `sleep` to `fake.test` so the sampler sees a test binary. mbp2's `sleep` is uutils' multi-call coreutils (Rust, under
  `/usr/lib/cargo/bin/coreutils`), which picks its tool from the program name and refuses the renamed copy ("Requested
  utility `fake` does not match executable name"). The child exits at once and the sampler sees nothing. CI's Ubuntu
  24.04 has GNU coreutils, where the copy sleeps. This is a box finding, not SB12's: the test would need a binary that
  ignores its name (a tiny Go program built in the test) to run here.

## 5. Step 3: census and heavy grade run records (C2–C5)

- **The runner records.** A `census` or `heavy` run writes `gate_<name>_run.json` beside its streams in `-logdir`

  `report.go` and `skips.go` were renamed with no change.

  with a function of the same name. It allows `time`'s types and refuses its clock and timer functions. Red once:

`TestRunRecord_replayRefusesAnotherGatesRecord`: `census -replay` of a heavy record exits 2.

**DECISION NEEDED: what `gate heavy -stream` should do.** It still counts nothing (§3); `-replay` now does what it was
for.
- **A. Make it refuse (exit 2) and name `-replay` (recommended).** A bare stream lacks the exit codes and durations
  the tally reads, so it can never reproduce a run, and a refusal cannot mislead. Con: a replay verdict changes, from
  a wrong RED to "refused".
- **B. Tally the stream as one cell.** It would then agree with a one-cell run's counts. Con: it still cannot see a
  non-zero exit with no failing event (the hidden-failure rule), so it can disagree with the run it replays.
- **C. Leave it.** Con: it keeps reporting RED for green runs.

This step changes nothing about `-stream`, because no gate's verdict changes without Francis.

## 6. Step 4: the parity sweep grades its run record (C2–C5)
